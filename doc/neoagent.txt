1. INTRODUCTION                                           *neoagent-introduction*

Neoagent supplies a streamed Model API, cancellable Runs, and a plain tool
loop. Sessions, persistence, bundled tools, and the floating UI are optional
layers. Anthropic Messages, OpenAI-compatible Chat Completions, stateless
Responses, and the ChatGPT Codex subscription endpoint use curl.

Requirements: Neovim 0.10+, curl 7.76+, rg, and fd. ImageMagick's `magick` is
optional. Run >

  :checkhealth neoagent

===============================================================================
2. SETUP                                                         *neoagent-setup*

Example for llama.cpp: >lua

  require("neoagent").setup({
    providers = {
      local_llama = {
        api = "openai-completions",
        base_url = "http://127.0.0.1:8080/v1",
        models = {
          coder = { context_window = 131072, max_output_tokens = 8192 },
        },
      },
    },
    default_model = { provider = "local_llama", model = "coder" },
  })
<
For a Responses-compatible endpoint with request-time thinking levels: >lua

  providers = {
    local_llama = {
      api = "openai-responses",
      base_url = "http://127.0.0.1:8080/v1",
      models = {
        coder = {
          max_output_tokens = 8192,
          thinking = {
            off = {},
            low = { body = { reasoning = { effort = "low" } } },
            high = { body = { reasoning = { effort = "high" } } },
          },
        },
      },
    },
  }
<
BUILT-IN PROVIDERS                              *neoagent-built-in-providers*

The default registry contains these provider IDs:

  openai             OpenAI API; `:NeoagentLogin openai` or `OPENAI_API_KEY`.
  openai-codex       ChatGPT Codex plan; `:NeoagentLogin openai-codex`.
  anthropic          Anthropic API; `:NeoagentLogin anthropic` or
                     `ANTHROPIC_API_KEY`.
  anthropic-plan     Claude plan OAuth; `:NeoagentLogin anthropic-plan` or
                     `ANTHROPIC_OAUTH_TOKEN`.
  deepseek           DeepSeek API; `:NeoagentLogin deepseek` or
                     `DEEPSEEK_API_KEY`.
  zai                Z.AI API and Coding Plan; `:NeoagentLogin zai` or
                     `ZAI_API_KEY`.
  zai-coding-plan    Z.AI Coding Plan models using the same `zai` credential.

`:NeoagentModel` lists the models currently available from configured and
authenticated providers.

Credentials are stored at `stdpath("state") .. "/neoagent/auth.json"`. Stored
credentials take precedence over environment variables. `:NeoagentLogout`
removes a stored credential and restores any matching environment source.

Codex provider diagnostics default to
`stdpath("state") .. "/neoagent/codex.log"`. Configure or disable them with: >lua

  providers = {
    ["openai-codex"] = {
      diagnostics = { path = vim.fn.stdpath("state") .. "/my-codex.log" },
      -- diagnostics = false,
    },
  }
<
Diagnostic records exclude credentials, request and response bodies, and
conversation content.

The important options are: >lua

CONTROLLERS AND VIEWS                                *neoagent-controllers*

`setup(opts)` constructs the built-in `Neo` and `Chat` Controllers, installs
their shared default Window, and returns `Neo`. `Neo` uses the configured
system prompt, resources, and tools. `Chat` shares the model and provider
configuration while using an empty system prompt and tool list; AGENTS.md and
skill discovery are disabled for it. Commands and top-level convenience
functions target the active Controller in that Window. `new(opts)` constructs
an independent Controller:
>lua

  local neoagent = require("neoagent")
  local coding = neoagent.setup({ name = "Coding" })
  local reviewer = neoagent.new({
    name = "Review",
    tools = require("neoagent.tools").read_only(),
    persistence = { enabled = false },
    system_prompt = "Review without editing.",
  })
  local window = neoagent.new_window({
    controllers = { coding, reviewer },
    ui = { position = "left" },
  })
  neoagent.set_default_window(window)
<
Controller methods are: >lua

  controller:prepare()
  controller:send(text)
  controller:steer(text)
  controller:dequeue_steering()
  controller:compact([instructions])
  controller:stop()
  controller:new_session()
  controller:resume([path[, on_resumed]])
  controller:branch(entry_id[, summary])
  controller:select_branch([on_selected])
  controller:fork([entry_id[, position]])
  controller:select_fork([on_selected])
  controller:select_model([on_selected])
  controller:set_model(provider, model)
  controller:available_thinking_levels()
  controller:get_thinking_level()
  controller:set_thinking_level(level)
  controller:cycle_thinking_level()
  controller:login([method])
  controller:cancel_login()
  controller:logout([method])
  controller:set_ui_position(position)
  controller:subscribe(callback)
  controller:snapshot()
  controller:get_session()
  controller:get_model()
  controller:config()
  controller:is_running()
  controller:destroy()
<
`send` starts an interaction while idle and queues steering while working.
Controllers have independent Sessions, model selections, steering queues, and
Runs. Controllers using the same persistence directory share workspace data.

Window Controllers require unique, non-empty names. A Controller name is its
View label and workspace-settings scope. Renaming it selects a fresh scope;
matching names in separate Windows share one.

A Window owns one View and selects an attached Controller. Its operations are
`open`, `close`, `toggle`, `is_open`, `active`, `controllers`, `select`,
`cycle`, `set_position`, `set_input`, `input_history`, `add_input_history`,
`select_input_history`, and `destroy`. It retains input drafts per Controller
and shares workspace input history. Selection restores the active transcript
and draft while inactive Controller Runs continue. A Controller's initial
Session is created on its first send.

`set_default(controller)` points commands and top-level functions at an
existing Controller and returns the previous active Controller.
`set_default_window(window)` installs an assembled Window and returns the
previous Window. `default()` and `default_window()` return the active Controller
and command-facing Window. `set_position(position)` updates that Window and
`select_position()` opens its position selector. Another `setup()` destroys the
Controllers owned by an earlier `setup()` call. An active Run on either owned
Controller blocks the replacement.

`controller:subscribe(callback)` publishes `messages`, `context`, `event`, and
`finish` updates and returns an unsubscribe function. `controller:snapshot()`
returns the current messages, context, pending events, and result for a newly
attached consumer.

The `view` option is a factory receiving `config`, `window`, `on_submit`,
`on_stop`, `on_dequeue_steering`, `on_input_history`, `on_select_history`,
`on_cycle_thinking`, `on_cycle_agent`, `on_select_model`, and
`on_resume_session`, `on_dialog_action`, and `on_dialog_dismiss`. A View used
by a Window with a dialog source implements `set_dialog(snapshot)`. The
factory returns a passive View with `open`, `close`,
`is_open`, `destroy`, `get_input`, `set_input`, `set_messages`, `set_context`,
`apply`, and `finish`.

An executor can inject an optional `ctx.dialog` capability and attach its
source to a Window:
>lua

  local dialogs = require("neoagent.dialog").new()
  local opts = controller:config()
  opts.execute_tool = require("neoagent.dialog").wrap(
    dialogs, opts.execute_tool)
  controller = require("neoagent").new(opts)
  local window = neoagent.new_window({
    controllers = { controller },
    dialogs = dialogs,
  })

  local response = ctx.dialog:show({
    placement = "transcript",
    title = "Deploy release",
    body = "Deploy release 1.2.3 to production?",
    actions = {
      { id = "deploy", label = "deploy", key = "y" },
      { id = "cancel", label = "cancel", key = "n" },
    },
  }):await()
<
`show()` returns a cancellable Run whose successful result contains the
caller-defined `action`. Dialogs use FIFO order. Each action supplies its own
key and label. `placement = "transcript"` presents the body and actions in the
transcript surface. `placement = "float"` opens a focused floating surface;
an optional `input = { label, value, multiline }` adds editable text and the
result includes `input`. A request fails when no presenter is attached.
Presenter loss cancels pending dialogs and sets
`presenter_unavailable = true`. The injected capability expires with the tool
call. Headless compositions can omit it.

SANDBOXING                                                 *neoagent-sandbox*

The command-facing Neo Controller can compose native sandbox enforcement
around its tools: >lua

  require("neoagent").setup({
    sandbox = {
      enabled = true,
    },
  })
<
Sandboxing is experimental and defaults to disabled. Linux and Windows use
bundled standalone LuaJIT FFI runtimes to invoke native isolation APIs. Linux
applies namespaces and seccomp; Windows applies restricted tokens, ACLs, Job
Objects, and WFP; macOS delegates isolation to `/usr/bin/sandbox-exec`.

Successful activation wraps only the built-in Neo Controller. Chat remains
tool-free. `neoagent.new()` and direct Controller constructors do not interpret
the setup flag; custom compositions can use `require("neoagent.sandbox")`
directly.

Run >

  :NeoagentSandboxInfo
<
to inspect the active backend, isolation level, and available capabilities.
Activation failures include their setup stage and reason.

When activation requirements fail, Neo retains its configured host executor.
A warning is shown once when Neo is first displayed. Successful activation
reports full or degraded isolation through |:NeoagentSandboxInfo|. Failures
after successful activation fail closed as tool errors and never retry through
the host executor.

The default profile provides a read-only host filesystem, grants writes within
a bounded Workspace root and the shared host temporary roots, keeps
`<workspace>/.git` read-only, restricts networking, and clears the environment
to an explicit inherited set. POSIX systems grant the active host temporary
directory and canonical `/tmp`. Windows uses the managed `shared-tmp`
directory beneath its protected sandbox state. The profile points `TMPDIR`,
`TMP`, and `TEMP` at the selected directory. Files created there remain
visible to later sandbox invocations and host processes until they are
removed. Read-only access includes host files outside the Workspace; add deny
entries for sensitive paths. Override the profile with a table merged over
the default: >lua

  sandbox = {
    enabled = true,
    profile = {
      filesystem = {
        entries = {
          { path = vim.uv.cwd(), access = "write" },
          { path = vim.fs.joinpath(vim.uv.cwd(), ".git"), access = "read" },
          { path = "/absolute/secret", access = "deny" },
        },
      },
      network = "restricted",
    },
  }
<
Lists replace their defaults. Entry access is `read`, `write`, or `deny`;
paths are canonical absolute paths and writable roots must exist. The
filesystem default is `read`. `network` is `restricted` or `enabled`.

Windows paths may use drive roots or UNC shares. Profile and policy comparison
is case-insensitive, environment variable names share Windows casing
semantics, and device paths, alternate data streams, reserved device names,
and non-canonical paths are rejected. Windows sandboxing requires Neovim
0.12 or newer.

The default state directory is
`<stdpath("state")>/neoagent/windows-sandbox`. Set
`NEOAGENT_WINDOWS_SANDBOX_STATE` before starting Neovim to select another
directory. From an elevated PowerShell in the plugin checkout, provision the
directory once: >

  nvim --headless -u NONE -i NONE -n \
    -l scripts/sandbox_windows_runtime.lua -- --setup
<
Setup creates dedicated offline and online local accounts, stores random
passwords with current-user DPAPI in an owner-only state directory, and
installs persistent identity-scoped Windows Filtering Platform rules for the
offline account. Each state directory owns random filter identifiers, so
separate Neoagent installations do not replace one another's filters. Setup
creates `<state-directory>/shared-tmp` as the only default Windows temporary
write root. A state file is accepted only by the Windows identity that created
it.

Activation runs a live runtime probe. The probe verifies a fresh restricting
SID, filesystem write and deny rules, account-authenticated runner launch,
private-desktop process launch, Job Object supervision, shared
temporary-directory writes, and blocked offline loopback networking. Any
missing guarantee leaves the backend inactive.

Each Windows operation compiles the resolved profile into writable ACL roots
and read/write deny carveouts. Existing carveouts are opened without following
their final reparse point and checked by filesystem identity. A missing read or
deny child beneath a writable root is protected by a runtime-owned directory
placeholder when its parent exists. The placeholder identity is journaled and
only that exact object is removed after the call. A write entry below a deny
entry cannot be represented and fails before execution. A nested write below
a read entry becomes a separate writable ACL root. The runtime canonicalizes
the plan again, rejects overlap with its protected state
directory, creates an ephemeral restricting SID, and removes the account and
restricting-SID ACEs when the operation ends. Parent write grants omit
delete-child authority so a protected child cannot be removed through its
parent. A state-directory-scoped Windows mutex serializes ACL leases. The
owner-only state journals every transient ACL and placeholder before mutation,
and the next operation reconciles the journal after interruption.

`network = "restricted"` selects the WFP-blocked offline account.
`network = "enabled"` selects the online account. The owner runtime launches an
internal runner with `CreateProcessWithLogonW` over account-ACL-scoped named
pipes and verifies both pipe peer process IDs.
That runner creates a restricted primary token and starts the requested
process with `CreateProcessAsUserW` on a fresh private desktop. The runner and
target both start suspended and enter nested kill-on-close Job Objects before
their first instruction. Cancelling or timing out the runtime terminates both
stages and the complete process tree. Protocol handles are excluded from
target inheritance. Direct file operations impersonate the restricted token
and use the same framed, binary-safe protocol.

On Linux, missing read-only and denied paths beneath a writable entry remain
absent from the host filesystem. The namespace supervisor mediates creation
and removal while a sandboxed process runs, including open, directory, link,
rename, node, and Unix-socket operations. A path created concurrently by a
host process keeps the same creation and removal protection and is never
removed by sandbox cleanup.

Linux staging roots are created atomically beneath a host runtime directory
covered by the sandbox's private `/run` or `/dev`. Linux verifies each root's
identity before use and cleanup and fails closed when a filesystem profile
exposes every staging directory or a root pathname is missing, linked, or
substituted.

A callback can calculate the complete profile per tool call: >lua

  sandbox = {
    enabled = true,
    profile = function(default, ctx)
      default.filesystem.entries[#default.filesystem.entries + 1] = {
        path = "/absolute/read-only/path",
        access = "read",
      }
      return default
    end,
  }
<
Bundled file and subprocess operations use the selected backend and the
same resolved profile. Tool Lua runs in Neovim, so custom tools participate in
the sandbox only when they route effects through `ctx.fs` and `ctx.process`.
Subprocess exit codes retain each tool's normal success or error semantics.
Nonzero exits receive restricted-execution guidance when bounded output
contains recognized sandbox-denial text, or when Linux reports `SIGSYS`.
Explicit sandbox policy denials and backend failures receive sandbox-owned
errors.

Sandbox denials are ordinary `isError` tool results. They tell the agent to
retry the exact call only when necessary by adding: >json

  {
    "options": {
      "require_escalation": true,
      "escalation_justification": "why unrestricted execution is necessary"
    }
  }
<
The sandbox then presents an approval dialog. Approval grants host filesystem
and process capabilities for that one call. Denial returns an error without
running the unrestricted call. Escalation is denied when no dialog presenter
is available.

Shell approvals whose command starts with at least one literal argument token
also offer `yes and don't ask again for commands starting with`. Selecting it
opens a focused floating editor containing the current command. `<Enter>`
accepts the edited prefix and `<C-c>` returns to the approval dialog.
Accepted rules are argument-token prefixes bound to the active shell, scoped
to the active Session, and held only in memory. They apply only to later
shell calls that explicitly request escalation. Creating, resuming, or
forking a Session clears the remembered rules.

The option supports POSIX shells, `cmd.exe`, and PowerShell. Any literal
argument-token prefix of the current command can be remembered; the offered
tokens end at the first unquoted operator, redirection, comment,
substitution, expansion, newline, or control character. An edited prefix
containing such syntax is rejected and remains in the floating editor with an
explanation. A remembered rule only matches commands that form one literal
argument vector, so a prefix is never followed by shell syntax that chains
further commands: compound and dynamic commands always prompt. Token matching
preserves argument boundaries, so `git status` does not match
`git status-danger`; quoted literal operator text remains an ordinary
argument.

The low-level platform-neutral API has the process-runner result shape: >lua

  local result = require("neoagent.sandbox").sandbox_exec(argv, {
    profile = profile,
    cwd = cwd,
    env = env,
    stdin = input,
    capture = true,
    timeout_ms = 30000,
    kill_grace_ms = 1000,
    on_output = on_output,
  })
<
It returns `code`, `signal`, `stdout`, `stderr`, `output`, and `timed_out`.
Unsupported platforms and unavailable native requirements raise
`sandbox_unavailable`.

Controllers automatically replay assistant turns after transient transport and
provider failures. The default retry delays are 2, 4, and 8 seconds. Set
`retry.enabled = false`, or configure `retry.max_retries` and
`retry.base_delay_ms`, to change this policy. Backoff is cancellable with the
normal interrupt action. Failed partial assistant output is removed from the
active branch before replay, while the Session retains it as inactive history.
HTTP authentication, invalid-request, quota, billing, and context-window
failures fail immediately; context-window failures follow the compaction
recovery path.

The final model registry composes the defaults with `providers`. Provider and
model tables recursively override matching defaults. Use `false` to remove a
default provider or model: >lua

  require("neoagent").setup({
    providers = {
      openai = {
        api_key = function() return vim.env.MY_OPENAI_API_KEY end,
        models = {
          ["gpt-5.4"] = {
            thinking = {
              minimal = false,
              high = { body = { reasoning = { effort = "high" } } },
            },
          },
          ["gpt-4"] = false,
        },
      },
      ["openai-codex"] = false,
    },
  })
<
Set `default_registry = false` to use only the user `providers` table. A
provider with `auth` or `api_key` is available when its credential resolves;
providers without either are always available. The built-in catalog is
returned by `require("neoagent.registry").defaults()`.

The built-in prompt follows the active tools and includes the current working
directory. A string replaces it completely. Append instructions by composing
the exported default in a callback: >lua

  local default_prompt = require("neoagent.system_prompt").default

  require("neoagent").setup({
    system_prompt = function(context)
      return table.concat({
        default_prompt(context),
        "Run the project formatter after editing Lua files.",
      }, "\n\n")
    end,
  })
<
The callback context contains `session`, `model`, `workspace`, the submitted
`prompt`, the active `tools`, and discovered `agents` and `skills`. A custom
value replaces the base prompt, but contextual resources are appended unless
their configuration is disabled.

The default coding preset includes `read_agent_documentation`. The `tools`
option selects exactly the supplied tools. To keep the four coding tools
without the documentation tool: >lua

  require("neoagent").setup({
    tools = {
      require("neoagent.tools.read_file").new(),
      require("neoagent.tools.write_file").new(),
      require("neoagent.tools.edit_file").new(),
      require("neoagent.tools.shell").new(),
    },
  })
<

Use `tools = {}` for a tool-free chat composition.

Custom compositions can add the tool directly with: >lua

  require("neoagent.tools.read_agent_documentation").new()
<

Neoagent integrations are ordinary Lua modules loaded explicitly by Neovim
configuration. They can construct independent Controllers with `new()`, attach
them to a shared Window with `new_window()`, and install that Window with
`set_default_window()`.

AGENTS.MD AND SKILLS                                  *neoagent-context-files*

The default controller loads the global file
`stdpath("config") .. "/AGENTS.md"`, followed by every `AGENTS.md` from the Git
root through the active Workspace. Without a Git root it walks from the
filesystem root. Existing files enter the prompt in broad-to-specific order.

Agent Skills are `SKILL.md` files with YAML frontmatter containing `name` and
`description`. Neoagent recursively scans these defaults:

  ~/.agents/skills
  stdpath("config") .. "/neoagent/skills"
  <each project ancestor>/.agents/skills

Later global locations override earlier skills with the same name. Project
skills override global skills, and nearer project skills override broader
ones. Only skill metadata and the `SKILL.md` path enter the prompt. The model
loads full instructions on demand with `read_file`, so skills are included only
when that tool is active. Relative references inside a skill resolve from the
directory containing its `SKILL.md`.

Replace the configured lists to customize discovery. An empty list disables
that class of locations. Set `agents = false` or `skills = false` to disable a
resource type completely. The independent `neoagent.agents` and
`neoagent.skills` modules expose `discover(opts)` and `format(resources)` for
custom workflows; discovery results include non-fatal `diagnostics`.

Provider, model, and Model:stream() options may each define `request_opts` as
a table or callback. Layers merge in that order. Only `url`, `headers`, and
`body` are accepted. Headers and body merge recursively, lists replace lists,
and header keys are case-insensitive.

Models expose optional request-time thinking controls through a `thinking`
table. Keys use the order `off`, `minimal`, `low`, `medium`, `high`, `xhigh`,
and `max`; values are `request_opts` tables or callbacks. Missing keys are
unsupported and `false` removes an inherited level. The selected level supplies
request options for Controller Model calls.

WORKSPACE SETTINGS                                  *neoagent-workspace-settings*

With persistence and `workspace_settings` enabled, model and thinking
preferences are scoped by Controller name and UI position is shared by the
workspace. An unnamed standalone Controller uses the `default` scope. A
resumed Session's recorded model and thinking values take precedence for that
Session.

The bundled Window keeps the 100 most recent accepted inputs for each
workspace and shares them across its Controllers. Set
`persistence.workspace_settings = false` to keep configured model, thinking,
and position defaults authoritative while retaining Sessions and input
history.

The workspace settings layer is also usable independently: >lua

  local settings = require("neoagent.workspace_settings").new({
    directory = vim.fn.stdpath("state") .. "/my-plugin/workspaces",
    root = vim.fn.getcwd(),
  })
  local effective, overrides = assert(settings:merge(defaults))
  assert(settings:update({ my_option = { enabled = true } }))
  assert(settings:write(overrides))
<
The returned object exposes `metadata()`, `load()`, `merge(defaults)`,
`write(settings)`, and `update(patch)`.

3. COMMANDS                                                   *neoagent-commands*

  :Neoagent                       Toggle the floating UI.
  :NeoagentCycle                  Select the next Controller.
  :NeoagentNew                    Use a new empty UI Session.
  :NeoagentResume [path]          Resume a stored Session or select one.
  :NeoagentStop                   Cancel the active UI Run.
  :NeoagentSandboxInfo            Show recorded sandbox capabilities.
  :NeoagentModel [provider/model] Select a configured Model or choose one.
  :NeoagentThinking [level]       Set a thinking level or cycle to the next.
  :NeoagentPosition [position]    Set the UI position or select one.
  :NeoagentLogin [method]         Store an API key or authenticate an account.
  :NeoagentLogin!                 Cancel an active login.
  :NeoagentLogout [method]        Remove a stored credential or select one.
  :NeoagentCompact [instructions] Compact the active branch context.
  :NeoagentBranch [entry-id]      Move the leaf or select a branch point.
  :NeoagentFork [entry-id]        Fork before a user message or select one.

No global mappings are installed. Argument-free selectors and the input-history
selector use `vim.ui.select`, so configured `vim.ui` providers can render them.
Fork selection restores the selected user message to the input buffer.

===============================================================================
4. UI                                                               *neoagent-ui*

The input and transcript are focusable Neovim buffers. Input opens in Insert
mode, and the transcript supports normal search, motions, Visual selection,
and yank. Set `ui.scroll_on_submit`, `ui.scroll_on_transcript_leave`, or
`ui.scroll_on_reopen` to control automatic scrolling.

Assistant text renders Markdown, and thinking uses a muted italic style. The
footer displays context usage when the selected Model declares a
`context_window`. Tool output and compaction summaries can be expanded with
the configured `expand_tools` mapping.

Enter queues steering while the active Controller is working. The queue appears
in the transcript and drains one message after the current assistant response
and tool calls. Alt-Up restores all pending steering messages to the
input. Ctrl-C restores the queue and cancels the active Run; while idle it
clears the draft.

Insert-mode Tab opens Neovim's popup menu with filename matches relative to the
current working directory and advances through them. Enter accepts the selected
match without submitting the prompt. Up, Down, Ctrl-K, and Ctrl-J navigate an
open completion menu. Set `ui.completion` to false, use an empty
`ui.completion.sources` list, or change `ui.mappings.complete` to configure the
behavior. `files` is the supported completion source.

Accepted input is shared by every Controller in the workspace. Insert-mode Up
and Down or Ctrl-K and Ctrl-J browse the most recent 100 entries. Multiline
cursor movement takes precedence until the cursor reaches the first or last
line, and returning past the newest entry restores the previous draft. Ctrl-R
opens a searchable history selector and places the selected entry in the
active draft.

Default mappings:

  <CR>        Accept popup completion, or send from input in Normal or Insert
              mode.
  <Tab>       Open filename completion or select the next popup item in Insert
              mode.
  <C-c>       Interrupt the active Run and restore queued steering; clear the
              draft while idle.
  <C-w>w or <C-w><C-w>
              Alternate between input and transcript in Normal, Insert, or
              Visual mode.
  <Esc><Esc>   Hide the UI from input Normal mode.
  <C-d>       Hide the UI when the input is empty.
  <C-o>       Expand or collapse tool output and compaction summaries.
  <S-Tab>     Cycle through supported thinking levels.
  <A-n>       Cycle Controllers (input Normal/Insert; transcript Normal).
  <A-m>       Select a model (input Normal/Insert; transcript Normal).
  <A-r>       Resume a session (input Normal/Insert; transcript Normal).
  <Up>/<Down> or <C-k>/<C-j>
              Browse workspace input history from Insert mode.
  <C-r>       Select workspace input history (input Normal/Insert; transcript
              Normal).
  <A-Up>      Restore queued steering messages to the input.
  q           Hide the UI from the transcript.

Set a value in `ui.mappings` to an lhs string or list of strings, or to `false`
to disable it.
Use `:NeoagentPosition [auto|left|right|top|bottom|center]` to place the UI.
With no argument, the command opens a position selector. Position changes are
saved when workspace settings are enabled. `ui.width` and `ui.height` accept a
fraction in `(0, 1]`, an integer greater than one, or `nil` for the layout
default.
Card colors are customizable through `NeoagentUserBackground`,
`NeoagentToolPendingBackground`, `NeoagentToolSuccessBackground`, and
`NeoagentToolErrorBackground`. Markdown highlight groups begin with
`NeoagentMarkdown`. All Neoagent highlights use Neovim's `default` behavior.

5. CORE APIS                                                   *neoagent-core-api*

The direct Model constructor requires no setup: >lua

  local model = require("neoagent.api.openai_completions").new({
    provider = "local",
    model = "coder",
    base_url = "http://127.0.0.1:8080/v1",
    api_key = nil,                 -- string or callback
    context_window = nil,          -- enables bundled context usage display
    max_output_tokens = nil,
    request_opts = nil,
    request_opts_layers = nil,
  })

  local run = model:stream({
    messages = messages,
    system_prompt = nil,
    tools = {},
    request_opts = nil,
    on_event = function(event) end,
    on_done = function(result) end,
  })
<
Use `require("neoagent.api.anthropic_messages").new` for an Anthropic Messages
endpoint with the same Model interface. Its default `max_output_tokens` is
4096.

Use `require("neoagent.api.openai_responses").new` for a Responses endpoint.
Its additional constructor options are `reasoning`, `reasoning_effort`,
`reasoning_summary`, and `reasoning_context`. Set
`reasoning_summary = "none"` to omit summaries.

`require("neoagent.api.openai_codex_responses").new` adds
`responses_lite`, `request_max_retries` (default 4), and
`on_diagnostic(event)` options. Direct construction requires explicit
authentication and diagnostic handling.

Authentication is separately composable: >lua

  local manager = require("neoagent.auth").new({
    methods = { my_plan = my_login_method },
    store = my_credential_store,
  })
  local authenticated_model = manager:wrap(model, "my_plan")
<
Credentials have one of these tagged forms: >lua

  { type = "api_key", key = "...", env = { OPTIONAL = "value" } }
  { type = "oauth", access = "...", refresh = "...", expires = 0 }
<
Untagged OAuth values are accepted as OAuth credentials. A method has an
optional `type`, `name`, `login(interaction)`, and `request_opts(credential)`.
OAuth methods also have `refresh(credential)`. Login and refresh return Runs.
The interaction prompt types are `text`, `secret`, `select`, and `manual_code`;
the bundled Controller uses a masked command-line prompt for `secret`.

`require("neoagent.auth.api_key").new({ name = "Example API key" })` creates a
Bearer-key method. Its optional `request_opts(credential)` callback can derive
another header profile.

A store implements `read(id)`, `write(id, credential)`, `modify(id, fn)`,
`list()`, and `delete(id)`. `manager:list_credentials()` returns secret-free
metadata, and `manager:logout(id)` returns a cancellable Run.

`manager:wrap(model, id, { optional = true })` runs the underlying Model when
no stored credential exists, allowing its ambient API-key callback to supply
authentication. Stored credentials take precedence over ambient credentials.

Model events are `text_delta`, `thinking_delta`, `tool_call_delta`, and
`usage`. A Model may emit `{ type = "provider_status", text = "..." }`; the
Controller retains it as transient provider status. A successful result has
`{ ok = true, message, text }`; a failure has
`{ ok = false, error, message? }`. Non-empty partial output is retained in the
optional failure message.

A Run supports: >lua

  run:cancel()
  run:is_done()
  run:is_cancelled()
  run:result()
  run:await()       -- only inside neoagent.async.run()
<
Callbacks run on Neovim's main loop and completion occurs exactly once.

The tool loop is: >lua

  require("neoagent.agent").run({
    model = model,
    messages = messages,
    system_prompt = nil,
    tools = {},
    execute_tool = nil,
    context = nil,
    model_options = nil,
    on_event = nil,
    on_done = nil,
  })
<
It copies input messages, performs no global model lookup, and uses exactly the
tools passed by the caller. The loop continues while the model requests tools
or steering supplies another turn. A final assistant response or cancellation
ends the Run. Executor context includes `model`, `run`, `execute_tool`,
`context`, `on_update`, and a copy of the current tool call in `call`.

To bridge a callback API inside a tool or executor: >lua

  local value = require("neoagent.async").await(function(done)
    start_operation(function(err, result)
      if err then done.reject(err) else done.resolve(result) end
    end)
    return function() cancel_operation() end
  end)
<

6. TOOLS AND SESSIONS                                    *neoagent-composition*

A tool is `{ name, description, input_schema, execute }`. `execute(arguments,
ctx)` returns `{ content = { ... }, isError?, details? }`; content blocks are
text or base64 images. Replace or decorate `execute_tool(tool, arguments, ctx)`
to add approval, logging, a native sandbox, or subagent behavior.

Bundled tools use `ctx.fs` for model-directed disk access and
`ctx.process(argv, opts)` for subprocesses when an executor supplies them.
Direct calls use `neoagent.fs` and `require("neoagent.process").run`.
Decorators can copy `ctx`, replace either capability for one invocation, and
then invoke the next executor. The filesystem capability implements
`create_temp`, `read`, `mkdirp`, and `write_all`.

Process options support `cwd`, `env`, `clear_env`, `stdin`, `capture`,
`timeout_ms`, `kill_grace_ms`, and `on_output`. The host runner executes argv
with `vim.system`, captures ordered output unless `capture` is false, escalates
timed-out or cancelled processes from TERM to KILL, and returns `code`,
`signal`, `stdout`, `stderr`, `output`, and `timed_out`.

Bundled presets: >lua

  require("neoagent.tools").coding()    -- read/write/edit/shell/Neoagent docs
  require("neoagent.tools").read_only() -- read/grep/find
  require("neoagent.tools").all()
<
File tools operate on disk, never loaded buffers.
ImageMagick transformations stream image bytes through stdin and stdout and
create no temporary files.
The shell tool retains a bounded output tail and streams overflow to a
temporary log through `ctx.fs`. The returned path remains available to later
sandboxed file reads.

`require("neoagent.session").new()` is an in-memory, tool-free message owner.
It may receive `{ store = store }` or `{ messages = messages }`, but not both.
The default JSONL Store is created with: >lua

  local store = require("neoagent.storage").new({
    directory = directory,
    cwd = cwd,
  })
<
`directory` is the workspaces root. The Store uses the Pi v3 append-only JSONL
format and creates no file until the first accepted message. Use
`require("neoagent.storage").open(path)` to open an existing Store.

Tree-aware Session methods are: >lua

  session:messages()                 -- active branch for consumers
  session:context_messages()         -- compacted LLM projection
  session:entries()
  session:entry(id)
  session:leaf_id()
  session:path([id])
  session:state()
  session:move_to(id[, summary])
  session:append_entry(type, values)
  session:label(id)
  session:name()
<
`move_to()` changes the active leaf; the next append creates a branch child.
The optional summary creates a Pi `branch_summary` entry. Fork a linked child
session with: >lua

  local child = require("neoagent.storage").fork(store_or_path, {
    directory = directory,
    entry_id = user_entry_id,
    position = "before", -- or "at"
  })
<
Omitting `entry_id` copies the complete append-only file. The default
Controller exposes `branch`, `select_branch`, `fork`, and `select_fork`.

`store:info()` returns the path, ID, cwd, optional name and parent, creation
timestamp, latest message activity, message count, and first user message.
`storage.list_sessions(directory, cwd)` returns these values in recent-activity
order.

CONTEXT COMPACTION                                  *neoagent-compaction*

Automatic compaction runs at the configured context threshold and after a
provider context-overflow error. Subsequent Model requests use the summary and
retained recent messages; the complete Session tree remains available for
navigation. The bundled View expands compaction summaries with the configured
`expand_tools` mapping.

The threshold is `context_window - reserve_tokens`, and recent retention uses
`keep_recent_tokens`. Set `compaction = false` to disable Controller compaction
or `compaction.auto = false` to retain manual and overflow compaction. A custom
`compaction.run(opts)` returns a cancellable Run with `summary`,
`first_kept_entry_id`, `tokens_before`, and optional `usage` and `details`.
The `neoagent.compaction` module exposes `settings`, `estimate_context`,
`should_compact`, `prepare`, `serialize`, and `run` for direct composition.

Session adapters: >lua

  require("neoagent.chat").send(session, prompt, opts)
  require("neoagent.chat").run(session, prompt, opts)
  require("neoagent.chat").continue(session, opts)
<
`continue()` uses the projected context without appending another user
message. `run()` and `continue()` forward an optional `get_steering_messages`
callback to the agent loop. It returns user-message tables to inject after the
current assistant response and tool calls. Accepted messages are persisted.
Session adapters allow one active mutation per Session.
The top-level `require("neoagent")` module constructs Controllers with `new`,
constructs shared Windows with `new_window`, owns the replaceable default
Window, and forwards commands and convenience operations to its active
Controller.
