1. INTRODUCTION                                           *neoagent-introduction*

Neoagent provides streamed Models, cancellable Runs, and a plain Agent Loop.
The plugin adds optional tools, persistence, provider management, and a
floating UI.

Requires Neovim 0.10+, curl 7.76+, `rg`, and `fd`. ImageMagick's `magick` is
optional for image conversion. Check the installation with: >

  :checkhealth neoagent

===============================================================================
2. SETUP                                                         *neoagent-setup*

A minimal setup selects a model. Neoagent installs no global mappings: >lua

  require("neoagent").setup({
    default_model = {
      provider = "openai",
      model = "gpt-5.4",
    },
  })

  vim.keymap.set("n", "<leader>a", "<Plug>(NeoagentToggle)")
<
For a local OpenAI-compatible endpoint: >lua

  require("neoagent").setup({
    providers = {
      local_llama = {
        api = "openai-completions",
        base_url = "http://127.0.0.1:8080/v1",
        models = {
          coder = {
            input = { "text" },
            context_window = 131072,
            max_output_tokens = 8192,
          },
        },
      },
    },
    default_model = { provider = "local_llama", model = "coder" },
  })
<
The main options and defaults are: >lua

  {
    name = nil,
    default_registry = true,
    providers = {},
    default_model = nil,
    default_thinking_level = "medium",
    system_prompt = nil,
    tools = nil,
    shell_timeout = 300,
    execute_tool = nil,

    retry = { enabled = true, max_retries = 3, base_delay_ms = 2000 },
    compaction = {
      auto = true,
      reserve_tokens = 16384,
      keep_recent_tokens = 20000,
    },
    sandbox = { enabled = false, profile = nil },
    workspace_trust = {
      path = vim.fn.stdpath("state") .. "/neoagent/trust.json",
    },
    agent_instructions = {
      global_files = { vim.fn.stdpath("config") .. "/AGENTS.md" },
      project_filenames = { "AGENTS.md" },
    },
    skills = {
      global_dirs = {
        vim.fn.expand("~/.agents/skills"),
        vim.fn.stdpath("config") .. "/neoagent/skills",
      },
      project_dirs = { ".agents/skills" },
    },
    persistence = {
      enabled = true,
      workspace_settings = true,
      directory = vim.fn.stdpath("state") .. "/neoagent/workspaces",
    },
    recording = {
      enabled = false,
      format = "auto", -- "auto", "yaml", or "json"
      retention = "rolling", -- "rolling" or "all"
      directory = vim.fn.stdpath("state") .. "/neoagent",
    },
    ui = {
      style = "codex",
      renderer = nil,
      position = "center",
      width = nil,
      height = nil,
      margin = 1,
      input_height = 7,
      scroll_on_submit = true,
      scroll_on_transcript_leave = true,
      scroll_on_reopen = true,
      wrap_cards = false,
      show_thinking = true,
      images = {
        backend = "kitty",
        display = "always", -- or "expanded"
      },
      provider_shell = {
        position = "center",
        width = 0.75,
        height = 0.75,
      },
      completion = true,
      border = "rounded",
    },
  }
<
See |neoagent-ui| for mappings and |neoagent-built-in-providers| for credentials.

Provider tables recursively override the built-in registry. Assign `false` to
remove a provider, or set `default_registry = false` to use only configured
providers. For a source-free provider, a table under `models[id]` adds or
overrides that model. For a discovery-backed provider, it overrides the ID
while the current catalog contains it. Put a permanent model and its base
configuration under `catalog.additions[id]`. `false` under `models[id]`
removes the ID. A model may set `api` to override its provider's adapter.
Built-in adapter names are
`openai-completions`, `openai-responses`,
`openai-codex-responses`, and `anthropic-messages`: >lua

  providers = {
    deepseek = {
      catalog = {
        transform_model = function(model)
          if model.id:match("^deepseek%-v4.*vision") then
            model.input = { "text", "image" }
          end
          return model
        end,
      },
      models = {
        ["deepseek-v4-flash-vision-exp"] = {
          input = { "text", "image" },
          context_window = 1000000,
        },
      },
    },
  }
<

`transform_model(model, ctx)` receives a Model configuration copy and
secret-free context. Return the modified table, a replacement, or `false` to
exclude the ID. Exact-ID configuration takes final precedence.

`neoagent.model_rules.compile(rules)` builds a transform from ordered Lua
patterns or predicate functions. `defaults` fills absent fields, `set`
recursively overlays fields, and `apply(model, ctx)` handles derived values or
returns `false`: >lua

  local rules = require("neoagent.model_rules")
  local efforts = require("neoagent.model_efforts")

  providers = {
    openai = {
      catalog = {
        transform_model = rules.compile({
          {
            match = "^gpt%-5",
            set = { input = { "text", "image" } },
            apply = function(model)
              model.thinking = efforts.openai_responses({
                "low", "medium", "high",
              })
              return model
            end,
          },
          {
            match = "^gpt%-5%.6",
            apply = function(model)
              model.thinking.xhigh = efforts.openai_response("xhigh")
              model.thinking.max = efforts.openai_response("max")
              return model
            end,
          },
        }),
      },
    },
  }
<
Rules run in list order. `neoagent.model_efforts` also supplies constructors for
OpenAI Chat Completions, generic thinking-enabled completions, and Anthropic
adaptive thinking request layers.

Providers, models, and individual Model calls may set `request_opts` to a
table or callback. The layers merge in that order across `url`, `headers`,
and `body`. Header names are case-insensitive, maps merge recursively, and
lists replace inherited lists.

A model's `thinking` table maps levels to request options. Levels are ordered
`off`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, and `ultra`.
Missing levels are unavailable; `false` removes an inherited level. Selecting
a model starts at `default_thinking_level`, clamped to a supported value.

`input` lists accepted message modalities: `"text"`, `"image"`, or both.
Built-in adapters replace unsupported images in the request copy with a text
placeholder. Sessions keep the original image block.

The built-in system prompt follows the active tools and includes the working
directory. Set `system_prompt` to a string or callback to replace it. The
callback receives the Session, Model, Workspace, submitted prompt, tools, and
discovered resources. Configured AGENTS.md and skill context is appended to
the result.

BUILT-IN PROVIDERS                              *neoagent-built-in-providers*

The default provider IDs are:

  openai             OpenAI API; login `openai` or `OPENAI_API_KEY`.
  openai-codex       ChatGPT subscription; login `openai-codex`.
  anthropic          Anthropic API; login `anthropic` or
                     `ANTHROPIC_API_KEY`.
  deepseek           DeepSeek API; login `deepseek` or `DEEPSEEK_API_KEY`.
  alibaba-token-plan Alibaba Cloud Token Plan Personal; login
                     `alibaba-token-plan` or use
                     `BAILIAN_TOKEN_PLAN_API_KEY` for inference; optional
                     dashboard login provides quota reporting.
  zai                Z.AI API; login `zai` or `ZAI_API_KEY`.
  zai-coding-plan    Z.AI Plan; login `zai-coding-plan`, `zai`, or
                     `ZAI_API_KEY`. Both login names use the `zai` credential.
  opencode-go        OpenCode Go; login `opencode-go` or
                     `OPENCODE_API_KEY`.
  llama.cpp          Local llama.cpp router; login `llama`.

Open the Provider Shell with `:NeoagentProvider`, select a provider, and choose
an authentication action. Stored inference credentials take precedence over a
configured `api_key`, then an `api_key` callback such as an environment lookup.
Each logout action removes its corresponding stored credential. Dismissing
OAuth or device-code instructions leaves authorization running; use
`:NeoagentProvider!` to cancel it.

Credentials default to `stdpath("state") .. "/neoagent/auth.json"`; override
with `auth.path`. Listing credentials returns IDs and types only.

Alibaba Cloud Token Plan Personal requires its dedicated `sk-sp-...` key from
Token Plan My Subscriptions and uses the Singapore plan endpoint. Supply the
key through login or `BAILIAN_TOKEN_PLAN_API_KEY`. The optional dashboard login
enables quota reporting and stores a separate credential.

Codex diagnostics default to
`stdpath("state") .. "/neoagent/codex.log"`. They contain bounded transport
metadata and exclude credentials, HTTP bodies, and conversation content.
Configure or disable the sink under the provider: >lua

  providers = {
    ["openai-codex"] = {
      diagnostics = false,
      -- diagnostics = { path = "/private/path/codex.log" },
    },
  }
<
AGENTS AND APPLETS                                   *neoagent-agents*

`setup(opts)` creates the command-facing Neoagent Applet and registers the Neo
and Chat Profiles. Neo is configured for coding; Chat has an empty system
prompt and no tools. Agents and Sessions are created when work begins.

`:Neoagent` opens the Neo draft for the current Workspace. Drafts retain model,
thinking, sandbox, and input choices per Profile and Workspace until the first
accepted message creates an Agent. `:NeoagentCycle` lists drafts and live
Agents. Closing the UI leaves the Agent running.

A draft selects its model from the Workspace/Profile preference, configured
`default_model`, or first available provider/model. See
|neoagent-workspace-settings| for saved preferences.

The top-level Applet supports: >lua

  applet:toggle()
  applet:open()
  applet:close()
  applet:show_agents()
  applet:new(profile_id)
  applet:draft(profile_id[, workspace])
  applet:retained_draft(profile_id[, workspace])
  applet:resume([path])
  applet:fork([entry_id[, position]])
  applet:select_fork()
  applet:copy_session()
  applet:agents()
  applet:active_agent()
  applet:default_agent()
  applet:select(agent_or_id)
  applet:destroy_agent(agent_or_id)
  applet:foreground_applet()
  applet:toggle_provider_shell()
  applet:set_provider_shell(open)
  applet:provider_shell_open()
  applet:provider_shell()
  applet:destroy()
<

`require("neoagent").default()` returns the active or last foreground Agent and
may return nil before work begins. `require("neoagent").applet()` returns the
command-facing Applet. Calling `setup()` again replaces an idle composition;
active Agent or authentication work blocks replacement.

`new(opts[, runtime])` constructs an independent Agent immediately.
`runtime.session` and `runtime.workspace` bind caller-supplied values;
`runtime.runtimes` can supply shared provider runtimes: >lua

  local neoagent = require("neoagent")
  local session = require("neoagent.session").new()
  local review = neoagent.new({
    name = "Review",
    tools = require("neoagent.tools").read_only(),
    persistence = { enabled = false },
    system_prompt = "Review this project.",
  }, {
    session = session,
    workspace = vim.fn.getcwd(),
  })
<

Agent methods include: >lua

  agent:id()
  agent:profile_id()
  agent:label()
  agent:applet()
  agent:activity()
  agent:summary()
  agent:subscribe_activity(callback)
  agent:presenter()
  agent:dialogs()
  agent:prepare()
  agent:send(text)
  agent:steer(text)
  agent:dequeue_steering()
  agent:compact([instructions])
  agent:stop()
  agent:branch(entry_id)
  agent:select_branch([callback])
  agent:select_model([callback])
  agent:set_model(provider, model)
  agent:available_thinking_levels()
  agent:get_thinking_level()
  agent:set_thinking_level(level)
  agent:cycle_thinking_level()
  agent:set_ui_position(position)
  agent:subscribe(callback)
  agent:snapshot()
  agent:get_session()
  agent:get_model()
  agent:get_model_selection()
  agent:get_workspace()
  agent:get_toolset()
  agent:set_toolset(toolset)
  agent:config()
  agent:is_running()
  agent:destroy()
<

Each Agent has fixed Profile, Session, and Workspace identity. `send()` starts
a turn while idle and queues steering while busy. `set_toolset()` replaces the
`{ tools, execute_tool }` pair between Runs and returns its previous value.

`destroy()` cancels work and releases owned resources. A destroyed Agent
rejects new work; caller-owned provider runtimes remain available.

`agent:subscribe(callback)` publishes `messages`, `context`, `event`,
`submission_accepted`, and `finish` updates with increasing revisions.
`snapshot()` supplies current state for a newly attached consumer.
`submission_accepted` identifies the prompt that became durable.

`agent:presenter()` serializes semantic selection, input, confirmation, and
notice requests. `agent:dialogs()` exposes the Agent's dialog source for
executor interactions. The bundled Agent Applet presents both; a headless Agent
uses the fallback host presentation.

`branch()` and `select_branch()` move inside the Agent's Session. New, resume,
fork, and copy operations belong to the top-level Applet, which keeps one live
claim for each Session ID.

WORKSPACE TRUST                                  *neoagent-workspace-trust*

The built-in Neo Profile asks for trust before loading project resources or
starting a tool-capable Run. Chat and direct Lua compositions use only policies
their caller supplies.

The target is the canonical Git worktree root, or the canonical working
directory outside Git. The prompt offers persistent trust, trust until Neovim
exits, and cancel (`t`, `s`, and `q`). Cancelling restores the submitted text
to the retained Profile draft.

Persistent decisions default to
`stdpath("state") .. "/neoagent/trust.json"`. Remove a path from that file to
revoke trust. Configure another path or disable the built-in policy with: >lua

  workspace_trust = { path = "/private/path/trust.json" }
  -- workspace_trust = false
<

Trust allows repository content to influence Neo. Executor and sandbox policy
control tool effects.

Custom compositions can construct `neoagent.workspace_trust.new(opts)` and
inject it through `neoagent.new(opts, { workspace_trust = policy })`.
`policy:request(workspace)` reports trusted, scheduled, or active state, and
`policy:attach(callbacks)` connects an interaction surface.

SANDBOXING                                                 *neoagent-sandbox*

Native sandboxing is experimental and disabled by default. Enable its initial
state for the built-in Neo Profile with: >lua

  require("neoagent").setup({
    sandbox = { enabled = true },
  })
<

`:NeoagentToggleSandbox` changes the selected Agent or retained Neo draft.
`:NeoagentSandboxInfo` reports the selected backend and capabilities. A tool
call keeps the mode it started with.

The default profile grants read-only host access, writes within the Workspace
and shared temporary directory, read-only access to `.git`, restricted
networking, and a small inherited environment. Override it with a table or
callback: >lua

  sandbox = {
    enabled = true,
    profile = {
      filesystem = {
        entries = {
          { path = vim.uv.cwd(), access = "write" },
          { path = vim.fs.joinpath(vim.uv.cwd(), ".git"), access = "read" },
          { path = "/absolute/secret", access = "deny" },
        },
      },
      network = "restricted",
    },
  }
<

Filesystem access is `read`, `write`, or `deny`; paths are canonical and
absolute. `network` is `restricted` or `enabled`. Lists replace their defaults.
A profile callback receives a copy of the default profile and tool context and
returns the complete profile.

Linux uses namespaces and seccomp. macOS uses `/usr/bin/sandbox-exec`. Windows
uses restricted accounts, ACLs, Job Objects, and WFP, requires Neovim 0.12+,
and needs one elevated setup from the plugin checkout: >

  nvim --headless -u NONE -i NONE -n -l scripts/sandbox_windows_runtime.lua -- --setup
<

Set `NEOAGENT_WINDOWS_SANDBOX_STATE` before Neovim starts to select another
Windows state directory. Custom tools participate when they route file and
process effects through `ctx.fs` and `ctx.process`; their Lua code itself runs
inside Neovim.

A denied call can request one host execution with: >json

  {
    "options": {
      "require_escalation": true,
      "escalation_justification": "why host execution is required"
    }
  }
<

Approval grants host capabilities for that call. Shell approvals may remember
a literal argument-token prefix for the current Session. Compound or dynamic
shell syntax always prompts.

Custom compositions can use
`require("neoagent.sandbox.composition").compose(toolset, config, runtime)`.
Use `.switchable()` when the caller needs runtime changes.

AGENTS.MD AND SKILLS                                  *neoagent-context-files*

Neo loads the global `stdpath("config") .. "/AGENTS.md"` and each project
`AGENTS.md` from the Git root to the Workspace. Outside Git, discovery starts
at the filesystem root. Files enter the prompt from broadest to most specific.

Skills are directories containing a `SKILL.md` with YAML `name` and
`description`. The defaults are:

  ~/.agents/skills
  stdpath("config") .. "/neoagent/skills"
  <project ancestor>/.agents/skills

Nearer project skills override broader or global skills with the same name.
Only metadata and the path enter the initial prompt; the model reads full
instructions on demand. Skill discovery requires an active file-reading tool.

Replace the configured lists to customize discovery. Empty lists disable those
locations. `agent_instructions = false` or `skills = false` disables that
resource type. The `neoagent.agent_instructions` and `neoagent.skills` modules
also expose `discover(opts)` and `format(resources)`.

PROVIDER RUNTIMES AND SERVICES                     *neoagent-provider-services*

The interactive composition shares a runtime for each provider: definition,
Authentication, ModelCatalog, optional Provider Service, and transport. Direct
Agents create runtimes unless `runtime.runtimes` supplies shared values.

A ModelCatalog owns the provider's selectable inventory. Its API is: >lua

  catalog:start()
  catalog:snapshot()
  catalog:discoveries()
  catalog:subscribe(function(snapshot) ... end)
  catalog:refresh({ force = true })
  catalog:publish_discoveries(models[, opts])
  catalog:destroy()
<

`snapshot()` returns a copy of the model map with revision, source, freshness,
refresh, and persistence status. Subscribers receive the current snapshot
immediately. Catalog updates leave already resolved Models unchanged.

`catalog.discover(ctx)` returns a cancellable Run. A successful result contains
`models` and may contain ETag or Last-Modified validator data; an unchanged
result preserves the current discoveries. A failed or empty effective
inventory preserves the published snapshot.

A discovery source declares stable cache identity: >lua

  catalog = {
    source_id = "example-models",
    source_revision = 1,
    account_scoped = true,
    ttl_ms = 14 * 24 * 60 * 60 * 1000,
    source_options = function(provider)
      return {
        management_url = provider.service_opts.management_url,
      }
    end,
    discover = discover_models,
  }
<

Increase `source_revision` when changed discovery semantics make an existing
cache unsafe. `source_options` returns JSON-safe provider options that affect
discovery. Account-scoped sources use a hashed Authentication identity and
perform live discovery when no safe identity is available.

Catalogs are cached under `stdpath("state") .. "/neoagent/provider/state"`,
independently of Session persistence. `catalog.ttl_ms` sets freshness; expired
catalogs refresh automatically and retain their snapshot on transient failure.

A Provider Service supplies management status and provider-scoped operations:
>lua

  {
    id = "example",
    name = "Example",
    state = function(ctx) ... end,
    operations = {
      refresh = {
        label = "Refresh",
        run = function(ctx) ... end,
      },
    },
  }
<

Optional members are `wrap_model(model)`, `subscribe(listener)`,
`on_event(event)`, and `destroy()`. A wrapped Model must satisfy the normal
Model contract. Operations receive provider configuration, raw arguments,
authentication resolution, and interaction helpers for selection, input,
confirmation, progress, and notification. They return cancellable Runs and may
return a document artifact for Neoagent to open.

Non-mutating operations may run with model, compaction, and catalog work.
Mutating operations require exclusive use of their Service. Login and logout
coordinate all Services sharing the Authentication method.

`neoagent.provider_state.new(snapshot)` creates a semantic dashboard channel.
Snapshots may contain `status`, `field`, `progress`, `limit`, `list`, and
`activity` blocks. A `field.level` may be `info`, `success`, `warn`, `error`,
or `muted`.

The Provider Shell presents runtimes independently of Agents. Dynamic catalogs
offer `Refresh model catalog`. Login and logout actions follow each method's
credential state; see |neoagent-built-in-providers| and |neoagent-core-api|.

The Shell invokes the Service's non-mutating `refresh` operation on focus,
with no background polling. Changing provider cancels a pending automatic
refresh; explicit operations continue when the Shell loses focus.

The Provider Shell API is: >lua

  local shell = applet:provider_shell()
  shell:providers()
  shell:select(provider_id)
  shell:cycle(step) -- step is -1 or 1
  shell:operations()
  shell:info()
  shell:run(operation[, args])
  shell:cancel()
  shell:login([provider_id])
  shell:logout([provider_id])
  shell:cancel_login()
  shell:open([origin])
  shell:close()
  shell:toggle([origin])
  shell:is_open()
  shell:is_active()
<

Restricted management endpoints may reject an otherwise valid model
credential. The provider remains usable and the Shell shows a warning. Z.AI
management origins derive from `base_url` and can be overridden with
`service_opts.management_url`.

llama.cpp model definitions can include a Hugging Face source, load parameters,
and explicit thinking request layers: >lua

  providers = {
    ["llama.cpp"] = {
      catalog = {
        additions = {
          qwen = {
            hf_repo = "ggml-org/Qwen3.5-0.8B-GGUF",
            quantization = "Q4_0",
            load = { ctx_size = 32768, gpu_layers = 99 },
            context_window = 32768,
            max_output_tokens = 80000,
            thinking = {
              off = {
                body = { chat_template_kwargs = { enable_thinking = false } },
              },
              high = {
                body = { chat_template_kwargs = {
                  enable_thinking = true,
                  reasoning_effort = "high",
                } },
              },
            },
          },
        },
      },
    },
  }
<

Catalog additions remain selectable independently of the router inventory.
Their IDs define loadable models and alias their Hugging Face router IDs.
`models[id]` may override a router-reported model without keeping it in the
catalog. `service_opts` may set `wait_timeout_ms`,
`download_timeout_ms`, and `poll_interval_ms`.

HTTP RECORDING                                            *neoagent-recording*

Provider HTTP recording is disabled by default. Enable it with: >lua

  require("neoagent").setup({
    recording = {
      enabled = true,
    },
  })
<

Recording captures requests, responses, timing, and outcomes for model streams,
catalog discovery, Provider Shell operations, and built-in authentication.
Model exchanges include Workspace, Agent, Session, provider, and model IDs.

`recording.directory` defaults to `stdpath("state") .. "/neoagent"`.
Recordings are stored under that root at: >text

  workspaces/<basename>-<sha256>/recordings/<date>-<session-id>/
  provider/recordings/<provider>/<date>/
<
Session-less Workspace exchanges use `unscoped` in place of the Session ID.

`recording.retention` controls completed files in each Session or shared
provider directory:

  `rolling`   Keep the newest successfully published exchange. This is the
              default.
  `all`       Keep every completed exchange.

Failed finalization preserves the previous recording and the partial file.

`recording.format` accepts:

  `auto`   Publish YAML when compatible Mike Farah `yq` v4 is on `PATH`;
           otherwise publish JSON Lines.
  `yaml`   Require compatible `yq` v4 and publish `.yaml`.
  `json`   Publish `.jsonl` without a `yq` dependency.

YAML recordings represent JSON bodies as native values; machine replay requires
`yq`. JSON recordings are newline-delimited JSON. Invalid UTF-8 bodies use
base64 with an encoding marker.

Credential headers, credential-bearing URL values, known credential fields in
non-model requests, and authentication response bodies classified as sensitive
are replaced by `*`.

Model request bodies and ordinary provider response bodies are not sanitized.
Recordings can therefore contain prompts, tool schemas and results, images,
generated text, and other private interaction content. Treat them as sensitive
when storing or sharing them.

Recorder directories and files use private permissions. Failures produce
content-free diagnostics and do not change provider results. A
`.partial.ndjson` file marks an exchange interrupted by process exit or
finalization failure.

WORKSPACE SETTINGS                                  *neoagent-workspace-settings*

With persistence and workspace settings enabled, the first accepted message in
a new Session saves its model and thinking level as the Workspace preference
for that Profile. Starting a new Session with a Model without thinking clears
the Profile's thinking preference. Resuming a Session restores the last model
and thinking level used on its active branch, independently of the preference.

Model and thinking preferences for bundled Agents are scoped by stable Profile
ID. Direct Agents use their configured name as the preference key. UI position
and the latest 100 accepted inputs are shared by the Workspace.

Unreadable, invalid, or unsupported Workspace settings leave configured
defaults active. The warning identifies the settings file to update or delete.
Workspace settings, Sessions, and input history share
`<persistence.directory>/<workspace-basename>-<workspace-sha256>/`.

Set `persistence.workspace_settings = false` to keep configured model,
thinking, and position values authoritative while retaining Sessions and input
history.

The reusable settings object is created with
`require("neoagent.workspace_settings").new({ directory = path, root = cwd })`.
It exposes
`metadata()`, `load()`, `merge(defaults)`, `write(settings)`, and
`update(patch)`. Update recursively merges keyed tables and replaces lists,
scalars, and other values. A `vim.NIL` value deletes its key.

3. COMMANDS                                                   *neoagent-commands*

  :Neoagent                       Toggle the UI.
  :NeoagentCycle                  Open the Agent and Profile draft switcher.
  :NeoagentResume [path]          Resume through the Session's Profile.
  :NeoagentCopySession            Copy under a selected Profile.
  :NeoagentStop                   Cancel the active Agent Run.
  :NeoagentModel [provider/model] Select a Model or open the selector.
  :NeoagentThinking [level]       Set or cycle the thinking level.
  :NeoagentPosition [position]    Set or select the UI position.
  :NeoagentTranscriptStyle style  Select the `pi` or `codex` Renderer.
  :NeoagentProvider [op [args]]   Toggle the Provider Shell or run an action.
  :NeoagentProvider!              Cancel the active provider operation or login.
  :NeoagentCompact [instructions] Compact the active branch.
  :NeoagentBranch [entry-id]      Move to an entry or select a branch point.
  :NeoagentFork [entry-id]        Fork before a user message or select one.
  :NeoagentToggleSandbox          Toggle sandbox execution for Neo.
  :NeoagentSandboxInfo            Show sandbox status and capabilities.

Use the `<Plug>` targets to assign global mappings: >lua

  vim.keymap.set("n", "<leader>a", "<Plug>(NeoagentToggle)")
  vim.keymap.set("n", "<leader>A", "<Plug>(NeoagentCycle)")
<

Selectors filter labels and details with case-insensitive fuzzy matching. Use
`<C-j>`/`<C-k>`, `<C-n>`/`<C-p>`, or arrow keys to move through results, and
Enter to select. Normal-mode `q`,
`<Esc>`, or `<C-c>`, Insert-mode `<C-c>`, and `:q` close the picker. Fork
selection restores the chosen user message to the input.

The resume picker reads Profile identity from each Session header. A live
Session selects its existing Agent. A dormant Session constructs an Agent from
its recorded Profile and Workspace. Profile-free and unavailable-Profile
Sessions are rejected. `:NeoagentCopySession` copies the visible Session's
complete tree after Profile selection. Fork and copy retain the source Agent
and foreground the derived Agent. If activation fails after creating the new
Session, the error includes its path so it can be resumed.

4. UI                                                               *neoagent-ui*

The bundled Agent UI is available as `require("neoagent.ui").new(opts)`.

The transcript supports native search, motions, Visual selection, and yank.
Streamed redraws pause during interactions that require stable text. `<A-f>`
toggles following in an expanded streaming card.

Input submitted while an Agent is busy becomes steering and is consumed after
the current assistant response and tool calls. The interrupt mapping cancels
the Run and restores queued steering to the composer.

Filename completion is available in Insert mode when `ui.completion` is true.
Each Agent Applet has an input-history cursor; the Workspace stores the latest
100 accepted entries.

`<C-g>?` opens the current mapping reference. Configure `ui.mappings` with a
lhs string, list of lhs strings, or `false` for each key:

  Key                    Default             Action
  help                   <C-g>?              Show mappings.
  submit                 <CR>                Submit or accept completion.
  complete               <Tab>               Complete filenames.
  interrupt              <C-c>               Clear input; if empty, stop.
  close_input            <Esc><Esc>          Hide from input Normal mode.
  close_empty            <C-d>               Hide when input is empty.
  card_details           <CR>                Expand card details.
  card_raw               r                   Toggle raw Markdown details.
  card_follow            <A-f>               Toggle following in details.
  card_center            zz                  Center the expanded card.
  card_previous          <A-k>, <C-Up>        Previous card.
  card_next              <A-j>, <C-Down>      Next card or input.
  focus_input            <C-w>j              Focus input.
  focus_transcript       <C-w>k              Focus transcript.
  provider_previous      <C-k>               Previous provider.
  provider_next          <C-j>               Next provider.
  menu_previous          K                   Previous action.
  menu_next              J                   Next action.
  cycle_thinking         <S-Tab>             Cycle thinking levels.
  agents                 <A-n>               Switch Agent or draft.
  select_model           <A-m>               Select Model.
  resume_session         <A-r>               Resume Session.
  history_previous       <Up>, <C-k>         Older input.
  history_next           <Down>              Newer input.
  select_history         <C-r>               Select from history.
  dequeue_steering       <A-Up>               Restore queued steering.
  toggle_provider_shell  <A-p>               Toggle Provider Shell.
  provider_close         q                   Hide Provider Shell.
  close                  q                   Hide Agent UI.

`<C-c>` closes details and the Provider Shell, or cancels an active prompt.
Dialog actions use `<CR>` or displayed shortcuts. Sandbox escalation requests
default to denial.

`ui.position` accepts `auto`, `left`, `right`, `top`, `bottom`, or `center`.
Width and height accept a fraction in `(0, 1]`, an integer greater than one, or
nil for the layout default. Provider Shell position accepts every value except
`auto` and uses the same dimension rules.

Set `ui.show_thinking = false` to hide reasoning from the transcript while
retaining it in the Session. Set `ui.wrap_cards = true` to soft-wrap complete
card lines.

The bundled Renderers display PNG attachments with the Kitty graphics protocol.
Tmux 3.3 or newer must enable pass-through for every pane that can host
Neoagent: >tmux

  set -g allow-passthrough all
<

Set `ui.images = false` to disable images, or set
`ui.images.display = "expanded"` to show images only in card details. The
default `"always"` shows them in the transcript and details. Unsupported images
or unavailable transport use compact text fallbacks. `:checkhealth neoagent`
reports transport requirements.

Tools can publish changing PNG previews through `ctx.on_update` by retaining an
image `id` and changing its `revision`. The final tool result determines what
the Session retains; transient previews are neither journaled nor sent in later
model requests.

RENDERERS                                                *neoagent-renderers*

A Renderer turns copied semantic values into Pane content Tree nodes. Codex is
the default; Pi is also bundled: >lua

  local renderers = require("neoagent.ui.renderers")
  renderers.codex
  renderers.pi
  renderers.get("codex")
  renderers.names()
<
Select one with `ui.style` or provide `ui.renderer`. The explicit Renderer
takes precedence. `applet:set_renderer(renderer)` replaces one
Agent Applet's live Renderer and redraws its transcript.

A native Renderer has a non-empty `name`, an Applet `theme`, and these required
methods:

  render_block(block, env, continuation)
  render_details(block, env, continuation)

Each method receives a copied semantic block and layout, focus, Theme, and image
context. It returns a content Tree node and optional continuation, reused for
the same block and surface until the Renderer changes. See |applet-trees| for
the node vocabulary.
Tool `render(opts)` hooks return semantic values for the active Renderer to
convert into nodes.

5. CORE APIS                                                   *neoagent-core-api*

Models can be constructed without `setup()`: >lua

  local model = require("neoagent.api.openai_completions").new({
    provider = "local",
    model = "coder",
    base_url = "http://127.0.0.1:8080/v1",
    input = { "text", "image" },
  })

  local run = model:stream({
    messages = { { role = "user", content = "Hello" } },
    on_event = function(event) end,
    on_done = function(result) end,
  })
<

Other constructors are `neoagent.api.anthropic_messages`,
`neoagent.api.openai_responses`, and
`neoagent.api.openai_codex_responses`. Optional settings include `api_key`,
`context_window`, `max_output_tokens`, and `request_opts`; `stream()` also
accepts `system_prompt`, `tools`, and `request_opts`. The Codex constructor adds
`responses_lite`, `request_max_retries`, and `on_diagnostic`.

A Model has `api`, `provider`, and `id` fields, a `stream` function, and a
unique `input` list containing `text` and optionally `image`. Optional context,
timeout, and thinking values are validated when the Model is constructed or
wrapped.

Adapters preserve native assistant signatures for matching API, provider, and
model identities; omitted fields default to the destination. For other
identities, requests convert visible thinking to text and omit redacted
thinking, signatures, and phase metadata. Session messages remain unchanged.

Model events are `text_delta`, `thinking_delta`, `tool_call_delta`, `usage`,
and optional `provider_status` and `inference_stats`. A successful result
contains `{ ok = true, message, text }`; a failure contains
`{ ok = false, error, message? }`. Failures may retain meaningful partial
output. A successful `toolUse` response contains at least one `toolCall` block;
an inconsistent provider response fails. Cancellation uses
`stopReason = "aborted"`.

A Run supports: >lua

  run:cancel()
  run:is_done()
  run:is_cancelled()
  run:result()
  run:diagnostics()
  run:await()       -- inside neoagent.async.run()
<

Callbacks run on Neovim's main loop and completion occurs once. Callback and
cancellation-handler failures leave the primary result unchanged and appear as
bounded diagnostics. `neoagent.async.run()` accepts an optional diagnostic
reporter.

`neoagent.async.await(start)` gives `start` a completion value and expects an
optional cancellation function. A producer that transfers a resource may call
`done.resolve(value, disposer)`; cancellation either cancels pending work or
disposes a settled value before delivery.

The reusable Agent Loop is: >lua

  require("neoagent.agent_loop").run({
    model = model,
    messages = messages,
    tools = {},
    commit_message = function(message)
      local ok, err = message_owner:append(message)
      return ok, err
    end,
  })
<

The loop copies messages and uses the supplied dependencies. Optional fields
are `system_prompt`, `execute_tool`, `context`, `model_options`,
`get_steering_messages`, `on_event`, `on_done`, and `report`.
`commit_message(message)` returns `true` after the message becomes
authoritative or `nil, err` on failure. Its optional third result is a copied
observation message with presentation metadata. Assistant, tool-result, and
steering messages commit before dependent work or final observation.

Tool schemas and model-produced arguments are validated before execution.
Malformed calls become error tool results.

`get_steering_messages()` may return one message and an acknowledgement
function. The Agent Loop calls `acknowledge(true, observation)` after commit or
`acknowledge(false)` when commit fails.

Authentication is independently composable: >lua

  local manager = require("neoagent.auth").new({
    methods = { example = login_method },
    store = credential_store,
  })
  local authenticated = manager:wrap(model, "example")
<

Credentials are tagged `api_key` or `oauth` values. A login method may provide
`login`, `refresh`, `request_opts(credential[, scope])`, `public_metadata`, and
`cache_identity(credential)`. `validate_credential(credential)` may enforce a
method-specific credential shape. Set `login_with_ambient = true` when stored
login remains available alongside an active environment or configured
credential. Stores implement `read`, `write`, `modify`, `list`, and `delete`.
Metadata and cache-identity APIs return values that do not contain credentials.

Providers may bind independent Authentication methods to named scopes: >lua

  providers = {
    example = {
      auth = "example-inference",
      auth_scopes = { dashboard = "example-dashboard" },
    },
  }
<
Model wrapping uses `auth`. A Provider Service operation declares
`auth_scope = "dashboard"` and requests that credential with
`ctx.resolve_auth("dashboard")`. The Provider Shell gates the operation and
offers login and logout for each method independently. Authentication methods
may set `login_label` and `logout_label` for those actions.

Use `manager:wrap(model, id, { optional = true })` when the Model can run with
an ambient credential.

6. TOOLS AND SESSIONS                                    *neoagent-composition*

A Tool is `{ name, description, input_schema, execute }`.
`execute(arguments, ctx)` returns
`{ content = { ... }, isError?, details? }`. Content blocks contain UTF-8 text
or base64 `image/*` data. Transient image updates sent through `ctx.on_update`
use stable `id` and changing `revision` values.

`execute_tool(tool, arguments, ctx)` is the policy boundary for approval,
logging, sandboxing, and other decorators. Model-produced arguments satisfy the
supported `input_schema` vocabulary before this function runs.

Optional Tool fields are:

  capabilities.read_files   Enable skill discovery for this toolset.
  on_messages(messages, ctx)
                            Derive state from the active conversation.
  render(opts)              Return semantic presentation data.

Bundled presets are: >lua

  require("neoagent.tools").coding()
  require("neoagent.tools").read_only()
  require("neoagent.tools").update_plan()
  require("neoagent.tools").all()
<

The coding preset provides file read, write, edit, shell, and Neoagent
documentation tools. The optional plan tool derives its state from successful
calls on the active Session path.

Bundled tools use `ctx.fs` and `ctx.process(argv, opts)` when supplied. Process
options cover working directory, environment, input, output capture, timeout,
and streaming callbacks. The shell timeout defaults to 300 seconds;
`shell_timeout = false` disables that default.

`write_file` and `edit_file` replace regular files through same-directory
temporaries, preserve existing modes, reject symbolic links, and request mode
`0644` for new files. `details.changed_paths` tells the interactive Neo Agent
which unmodified buffers may be refreshed after success.

`edit_file` requires unique, non-overlapping matches in the original content.
Exact matches take precedence over a punctuation- and whitespace-tolerant
fallback. Edits preserve surrounding text, the BOM, and line-ending convention.

`require("neoagent.session").new()` creates an in-memory Session. It accepts an
optional store, initial messages, or validated tree snapshot. User, assistant,
and tool-result messages use the same semantic message format as Models and the
Agent Loop.

The bundled append-only store is: >lua

  local store = require("neoagent.storage").new({
    directory = directory,
    cwd = cwd,
  })

  local session = require("neoagent.session").new({ store = store })
<

No Session file is created until the first message is accepted. Open an
existing store with `require("neoagent.storage").open(path)`.

Tree-aware Session methods are: >lua

  session:append(message[, state])
  session:id()
  session:identity()
  session:messages()
  session:context_messages()
  session:entries()
  session:entry(id)
  session:leaf_id()
  session:path([id])
  session:state()
  session:append_compaction(values)
  session:move_to(id)
  session:snapshot()
  session:metadata()
  session:store()
<

`state` may include `model = { provider, model }` and `thinking_level`. Omitted
thinking state preserves the active branch value; a string selects a level;
`vim.NIL` clears it. `move_to()` selects another tree entry, and the next
append creates a branch.

Create a linked child with: >lua

  local child = require("neoagent.storage").fork(store_or_path, {
    directory = directory,
    entry_id = user_entry_id,
    position = "before", -- or "at"
  })
<

`storage.derive(snapshot, opts)` creates an independent copy while preserving
the source tree. `storage.list_sessions(directory, cwd[, opts])` returns recent
picker records.

`require("neoagent.profile_sessions")` associates Session headers with stable
Profile IDs. It provides `new`, `open`, `derive`, and `list` operations for
new, resumed, forked, and copied Profile Sessions. Generic Session and storage
constructors remain Profile-free.

Session documents are authoritative. Workspace indexes are rebuilt when
missing or invalid. Cross-process mutation uses `neoagent.file_lock`: >lua

  local lock = require("neoagent.file_lock").new({
    path = persistence_path .. ".lock",
    timeout_ms = 15000,
    poll_ms = 50,
  })
  local result = assert(lock:with(function() return update() end))
<

`acquire()` returns a lease with `release()`, and `acquire_async()` is
cancellable. Locks use OS advisory ownership and stable private lock files.

CONTEXT COMPACTION                                  *neoagent-compaction*

Automatic compaction runs near the Model's context limit and after a provider
context-overflow error. It stores a summary in the Session tree and uses that
summary before retained recent messages in later requests. The full tree
remains available for branch navigation.

The threshold is `context_window - reserve_tokens`; recent retention uses
`keep_recent_tokens`. Set `compaction = false` to disable all Agent
compaction or `compaction.auto = false` to keep manual and overflow
compaction.

`neoagent.compaction.run(opts)` returns a cancellable Run whose result contains
`summary`, `first_kept_entry_id`, `tokens_before`, and optional `usage`. The
module also exposes `settings`, `estimate_context`, `should_compact`, `prepare`,
and `serialize`.

Session adapters are: >lua

  require("neoagent.chat").send(session, prompt, opts)
  require("neoagent.chat").run(session, prompt, opts)
  require("neoagent.chat").continue(session, opts)
<
`continue()` uses projected context without adding a user message. The
optional `get_steering_messages` callback supplies user-message tables between
assistant/tool turns and supports the acknowledgement return documented under
|neoagent-core-api|. Session adapters allow one active mutation per Session.
`on_accept` observes a committed user message; callback failures reach
`report(message, level)` without stopping the turn.
