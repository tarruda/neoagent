1. INTRODUCTION                                           *neoagent-introduction*

Neoagent provides streamed Models, cancellable Runs, and a plain Agent Loop.
The plugin adds optional tools, persistence, provider management, and a
floating UI.

Requirements:

  Neovim 0.10+
  curl 7.76+
  rg
  fd

ImageMagick's `magick` is optional. Run this after installation: >

  :checkhealth neoagent

===============================================================================
2. SETUP                                                         *neoagent-setup*

A minimal setup selects a model. Neoagent installs no global mappings: >lua

  require("neoagent").setup({
    default_model = {
      provider = "openai",
      model = "gpt-5.4",
    },
  })

  vim.keymap.set("n", "<leader>a", "<cmd>Neoagent<cr>")
<
For a local OpenAI-compatible endpoint: >lua

  require("neoagent").setup({
    providers = {
      local_llama = {
        api = "openai-completions",
        base_url = "http://127.0.0.1:8080/v1",
        models = {
          coder = {
            input = { "text" },
            context_window = 131072,
            max_output_tokens = 8192,
          },
        },
      },
    },
    default_model = { provider = "local_llama", model = "coder" },
  })
<
The main options and defaults are: >lua

  {
    name = nil,
    default_registry = true,
    providers = {},
    auth = { path = ..., methods = {} },
    default_model = nil,
    default_thinking_level = "medium",
    system_prompt = nil,
    tools = nil,
    shell_timeout = 300,
    execute_tool = nil,

    retry = {
      enabled = true,
      max_retries = 3,
      base_delay_ms = 2000,
    },
    compaction = {
      auto = true,
      reserve_tokens = 16384,
      keep_recent_tokens = 20000,
    },
    sandbox = {
      enabled = false,
      profile = nil,
    },
    workspace_trust = {
      path = stdpath("state") .. "/neoagent/trust.json",
    },
    agent_instructions = {
      global_files = { stdpath("config") .. "/AGENTS.md" },
      project_filenames = { "AGENTS.md" },
    },
    skills = {
      global_dirs = {
        expand("~/.agents/skills"),
        stdpath("config") .. "/neoagent/skills",
      },
      project_dirs = { ".agents/skills" },
    },
    persistence = {
      enabled = true,
      workspace_settings = true,
      directory = stdpath("state") .. "/neoagent/workspaces",
    },
    recording = {
      enabled = false,
      format = "auto", -- "auto", "yaml", or "json"
      directory = stdpath("state") .. "/neoagent",
    },
    ui = {
      style = "codex",
      renderer = nil,
      position = "center",
      width = nil,
      height = nil,
      margin = 1,
      input_height = 7,
      scroll_on_submit = true,
      scroll_on_transcript_leave = true,
      scroll_on_reopen = true,
      wrap_cards = false,
      show_thinking = true,
      images = {
        backend = "kitty",
        display = "always", -- or "expanded"
      },
      provider_shell = {
        position = "center",
        width = 0.75,
        height = 0.75,
      },
      completion = true,
      border = "rounded",
      mappings = {},
    },
  }
<
Provider tables recursively override the built-in registry. Assign `false` to
remove a provider, or set `default_registry = false` to use only configured
providers. Every configured provider has one ModelCatalog, and that catalog is
the inventory used for both model selection and resolution.

A catalog starts with restored or packaged discoveries, applies the bundled
provider transform and then the configured `transform_model`, applies exact-ID
`models` entries last, validates the complete candidate, and publishes it
atomically. Rich provider catalogs are authoritative for capability fields.
Documented family transforms supply fields for inventory APIs that return only
model IDs. Exact-ID configuration takes final precedence. A table under
`models[id]` upserts and overlays that ID; `false` removes it. A model may set
`api` to override its provider's adapter. Built-in adapter names are
`openai-completions`, `openai-responses`,
`openai-codex-responses`, and `anthropic-messages`: >lua

  providers = {
    deepseek = {
      catalog = {
        ttl_ms = 14 * 24 * 60 * 60 * 1000,
        transform_model = function(model, ctx)
          if model.id:match("^deepseek%-v4.*vision") then
            model.input = { "text", "image" }
          end
          return model
        end,
      },
      models = {
        ["deepseek-v4-flash-vision-exp"] = {
          input = { "text", "image" },
          context_window = 1000000,
        },
      },
    },
  }
<

The transform receives an owned Model configuration and a secret-free context
containing `provider_id` and an owned `source_model`. It returns that table, a
replacement table, or `false` to exclude the ID. It is synchronous. A callback
error or invalid result rejects the complete candidate and preserves the
published snapshot. Exact-ID configuration has final precedence over the
transform.

`neoagent.model_rules.compile(rules)` builds a transform from ordered Lua
patterns or predicate functions. `defaults` fills absent fields, `set`
recursively overlays fields, and `apply(model, ctx)` handles derived values or
returns `false`: >lua

  local rules = require("neoagent.model_rules")
  local efforts = require("neoagent.model_efforts")

  providers = {
    openai = {
      catalog = {
        transform_model = rules.compile({
          {
            match = "^gpt%-5",
            set = { input = { "text", "image" } },
            apply = function(model)
              model.thinking = efforts.openai_responses({
                "low", "medium", "high",
              })
              return model
            end,
          },
          {
            match = "^gpt%-5%.6",
            apply = function(model)
              model.thinking.xhigh = efforts.openai_response("xhigh")
              model.thinking.max = efforts.openai_response("max")
              return model
            end,
          },
        }),
      },
    },
  }
<
Matching rules run in list order, so broad family defaults can be followed by
specific exceptions. `neoagent.model_efforts` also supplies constructors for
OpenAI Chat Completions, generic thinking-enabled completions, and Anthropic
adaptive thinking request layers.

Providers, models, and individual Model calls may set `request_opts` to a
table or callback. The layers merge in that order across `url`, `headers`,
and `body`. Header names are case-insensitive, maps merge recursively, and
lists replace inherited lists.

A model's `thinking` table maps levels to request options. Levels are ordered
`off`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, and `ultra`.
Missing levels are unavailable; `false` removes an inherited level. Selecting
a model starts at `default_thinking_level`, clamped to a supported value.

`input` lists accepted message modalities: `"text"`, `"image"`, or both.
Built-in adapters replace unsupported images in the request copy with a text
placeholder. Sessions keep the original image block.

The built-in system prompt follows the active tools and includes the working
directory. Set `system_prompt` to a string or callback to replace it. The
callback receives the Session, Model, Workspace, submitted prompt, tools, and
discovered resources. Configured AGENTS.md and skill context is appended to
the result.

BUILT-IN PROVIDERS                              *neoagent-built-in-providers*

The default provider IDs are:

  openai             OpenAI API; login `openai` or `OPENAI_API_KEY`.
  openai-codex       ChatGPT subscription; login `openai-codex`.
  anthropic          Anthropic API; login `anthropic` or
                     `ANTHROPIC_API_KEY`.
  deepseek           DeepSeek API; login `deepseek` or `DEEPSEEK_API_KEY`.
  zai                Z.AI API; login `zai` or `ZAI_API_KEY`.
  zai-coding-plan    Z.AI Plan; login `zai-coding-plan`, `zai`, or
                     `ZAI_API_KEY`. Both login names use the `zai` credential.
  opencode-go        OpenCode Go; login `opencode-go` or
                     `OPENCODE_API_KEY`.
  llama.cpp          Local llama.cpp router; login `llama`.

Open the Provider Shell with `:NeoagentProvider`, select a provider, and choose
Log in to store a key or start OAuth. A provider ID resolves its configured
auth method. Credential source precedence is a stored credential, a configured
`api_key` string, then an `api_key` callback such as an environment lookup.
The shell shows Log out when the selected provider uses a stored credential.
Configured and environment credentials are managed at their source.
Log in changes the Provider Shell action menu into the authentication method
menu. Selection and confirmation requests remain in that menu. Text, secret,
manual-code, and notice requests use modal Layers above the provider Panes.

The `openai-codex` device-code flow presents its verification URL and code in
a persistent Provider Shell modal titled
`OpenAI device login · <C-c> close`. `q` or `<C-c>` closes the modal while
authorization continues. Browser navigation remains under the user's control.
The browser-callback flow opens its authorization URL through the configured
Presenter and keeps its waiting instructions in a persistent Provider Shell
modal until authorization completes.

Credentials live at `stdpath("state") .. "/neoagent/auth.json"`. The store
uses atomic writes, private permissions, and a cross-process lock. Listing
credentials returns IDs and types only.

Codex diagnostics default to
`stdpath("state") .. "/neoagent/codex.log"`. They contain bounded transport
metadata and exclude credentials, request and response bodies, and conversation
content. A sink failure produces one warning through the owning provider
runtime. Configure or disable the sink under the provider: >lua

  providers = {
    ["openai-codex"] = {
      diagnostics = false,
      -- diagnostics = { path = "/private/path/codex.log" },
    },
  }
<
AGENTS AND APPLETS                                   *neoagent-agents*

`setup(opts)` creates the command-facing Neoagent Applet and returns it. Neo
is the coding Profile; Chat has an empty system prompt and no tools. Setup
creates zero Agents and Sessions.

`:Neoagent` opens the retained Neo draft for the current Workspace. Its first
submitted message creates a provisional Agent. A trust decision may pause that
message; granting trust retries it once. Durable acceptance binds the Agent.
Trust, model, preparation, interaction, and pre-acceptance Run failures remove
the provisional Agent and preserve the draft for retry. `:NeoagentCycle` lists
new Neo and Chat Sessions and every live Agent.

A draft chooses its model from the Workspace/Profile preference, the
configured `default_model`, or the first available provider/model, in that
order. `no model` means that none of those choices exists. Model, thinking,
and composer state are retained per Profile and canonical Workspace; position
and input history are shared by the Workspace. Toggle restores the last live
Agent; its New switcher item reopens the retained draft.
Workspace model preferences require safe non-empty provider and model IDs.
Invalid values produce the Workspace-settings warning and use the configured
or first-available fallback.

Programmatic and interactive draft model changes resolve the concrete Model
through that Profile's configuration, Authentication, and provider runtimes
before changing draft state. Every factory, Authentication wrapper, and
Provider Service wrapper returns a table with `stream(opts)`. Resolution or
binding failures return `nil, err` and preserve the complete prior request
selection. Thinking queries and changes expose only the levels declared by
that resolved Model. Switching models updates the displayed draft thinking
level to the nearest supported configured preference.

Closing an Agent UI keeps its Agent running. Selecting another Agent restores
that Agent's transcript, draft, focus, scroll state, and dialogs.

The Provider Shell is available with zero Agents and retains its selected
provider across Agent construction and selection.

The top-level Applet supports: >lua

  applet:toggle()
  applet:open()
  applet:close()
  applet:show_agents()
  applet:new(profile_id)
  applet:draft(profile_id[, workspace])
  applet:retained_draft(profile_id[, workspace])
  applet:resume([path])
  applet:fork([entry_id[, position]])
  applet:select_fork()
  applet:copy_session()
  applet:agents()
  applet:active_agent()
  applet:default_agent()
  applet:select(agent_or_id)
  applet:destroy_agent(agent_or_id)
  applet:foreground_applet()
  applet:toggle_provider_shell()
  applet:set_provider_shell(open)
  applet:provider_shell_open()
  applet:provider_shell()
  applet:destroy()
<
`default()` returns the active or last foreground Agent and may return nil
before the first message. `applet()` returns the command-facing
Neoagent Applet. Reconfiguring with `setup()` destroys an idle prior
composition; working Agents or an active authentication operation block
reconfiguration.

`new(opts[, runtime])` constructs an independent headless Agent immediately and
composes its provider runtimes unless `runtime.runtimes` is supplied.
`runtime.session` and `runtime.workspace` bind a caller-supplied Session and
Workspace for the Agent's complete lifetime: >lua

  local neoagent = require("neoagent")
  local session = require("neoagent.session").new()
  local review = neoagent.new({
    name = "Review",
    tools = require("neoagent.tools").read_only(),
    persistence = { enabled = false },
    system_prompt = "Review this project.",
  }, {
    session = session,
    workspace = vim.fn.getcwd(),
  })
<
Agent methods include: >lua

  agent:id()
  agent:profile_id()
  agent:label()
  agent:applet()
  agent:activity()
  agent:summary()
  agent:subscribe_activity(callback)
  agent:presenter()
  agent:dialogs()
  agent:prepare()
  agent:send(text)
  agent:steer(text)
  agent:dequeue_steering()
  agent:compact([instructions])
  agent:stop()
  agent:branch(entry_id)
  agent:select_branch([callback])
  agent:select_model([callback])
  agent:set_model(provider, model)
  agent:available_thinking_levels()
  agent:get_thinking_level()
  agent:set_thinking_level(level)
  agent:cycle_thinking_level()
  agent:set_ui_position(position)
  agent:subscribe(callback)
  agent:snapshot()
  agent:get_session()
  agent:get_model()
  agent:get_model_selection()
  agent:get_workspace()
  agent:get_toolset()
  agent:set_toolset(toolset)
  agent:config()
  agent:is_running()
  agent:destroy()
<
`send()` starts a turn while idle and queues steering while a Run is active.
Each Agent has an independent Session, model and thinking selection, toolset,
steering queue, presentation state, dialogs, and activity. The returned outer
Run owns preflight compaction, interaction, retries, continuations,
cancellation, and provider-use release. Returning a Run signals active work;
the `submission_accepted` update signals that the user message is durable.
Every submitted turn and steering value has an opaque Agent-local identity.
Queued steering is a validated semantic user message. It remains owned by the
Agent until the Agent Loop acknowledges its durable Session commit. Every
claim commits once or returns to its queue position. Initial turns and steering
publish one acceptance record after commit, and the Agent Applet clears
composer text only for the matching accepted identity.
`set_toolset()` replaces the `{ tools, execute_tool }` pair between Runs and
returns the previous value. A Run keeps the toolset it started with.
`get_model_selection()` returns a copy of the live `{ provider, model }`
choice, or nil before selection.
`agent:config()` and `require("neoagent.config").get()` return resolved
inspection snapshots. Pass an ordinary options table to `neoagent.new()` and
`neoagent.setup()`.

Agent Profile identity, Session identity, and Workspace are fixed at
construction. `branch()` and `select_branch()` move within that Session tree.
The top-level Applet creates Agents for new, resume, fork, and copy
operations and holds one live claim for each Session ID.

`agent:presenter()` serializes semantic `select`, `input`, `confirm`, and
`notice` requests. `notice({ prompt, body })` returns a
cancellable Run and publishes a read-only modal until it is resolved or
cancelled. The bundled View maps `q`, `<Esc>`, and `<C-c>` to cancellation.
Without an attached Applet, one fallback host surface owns the active request.
Attachment cancels that fallback once before publishing the same semantic
request, and every settlement or destruction path finalizes the current owner.
`agent:dialogs()` returns the Agent-owned dialog source.

`agent:subscribe(callback)` publishes `messages`, `context`, `event`,
`submission_accepted`, and `finish` updates and returns an unsubscribe
function. Every update has a monotonically increasing `revision`, and every
listener receives an independent semantic copy. `submission_accepted` carries
the opaque `submission_id`, copied prompt, and persisted entry ID. A retained
`finish` result contains only `ok`, normalized status, bounded scalar error
metadata, message count, stop reason, and scalar usage. Direct Run results may
retain their Session;
Agent snapshots and publications never retain Session, Store, Model, Run,
Presenter, Agent, Applet, or response-body owner graphs. `snapshot()` provides
the current revision and state to a newly attached consumer. Agent Applets
retain the newest revision for hydration and ignore stale updates.

Executors may publish dialogs through an injected `ctx.dialog` capability.
`dialog:show(request)` returns a cancellable Run. Requests choose
`placement = "transcript"` or `"float"`, define actions, and may include an
editable input. Optional `default_action` names the action selected when the
dialog opens. Each Agent owns its dialog FIFO.

WORKSPACE TRUST                                  *neoagent-workspace-trust*

The built-in Neo Agent asks for trust before it loads project resources
or starts a tool-capable Run. Chat and direct Lua compositions use only
policies supplied by their caller.

The trust target is the canonical Git worktree root, or the canonical working
directory outside Git. The prompt offers persistent trust, trust until Neovim
exits, and cancel (`t`, `s`, and `q`). The Agent Applet retains the
first submitted message only while a concrete trust request is scheduled or
active. Accepting trust retries that exact message once. Cancellation, dialog
failure, trust-store failure, or a later pre-acceptance failure removes the
provisional Agent and restores the exact ProfileDraft. Closing the Applet
leaves the decision unresolved.

Persistent decisions default to
`stdpath("state") .. "/neoagent/trust.json"`. The file contains canonical
trusted paths and is updated atomically with private permissions. Remove a path
from that file to revoke trust. Configure another path or disable the built-in
policy with: >lua

  workspace_trust = { path = "/private/path/trust.json" }
  -- workspace_trust = false
<
Trust allows repository content to influence Neo. Executor policy and sandbox
configuration control tool effects.

Custom compositions can construct `neoagent.workspace_trust.new(opts)` and
inject it as `neoagent.new(opts, { workspace_trust = policy })`. Supply its
Dialog source and attach callbacks explicitly when the composition presents
trust decisions. `policy:request(workspace)` returns `true` for trusted state
or `false, nil, "scheduled"|"active"` while a concrete request is owned.
`policy:attach({ on_result = function(result) ... end })` receives success,
cancellation, dialog, activation, and trust-storage terminal results.

SANDBOXING                                                 *neoagent-sandbox*

Native sandboxing is experimental and disabled by default. Enable its initial
state for the built-in Neo Agent with: >lua

  require("neoagent").setup({
    sandbox = { enabled = true },
  })
<
Use `:NeoagentToggleSandbox` to change the selected Agent's runtime state.
For an unbound Neo Applet, the choice belongs to that draft and is passed
to its eventual Agent; later Neo drafts begin with the configured Profile
default. `:NeoagentSandboxInfo` inspects the selected state without allocating
an Agent or draft. Each tool call keeps the mode it started with. Runtime
changes preserve the tool list and schemas.

The default profile grants read-only host access, writes within the Workspace
and shared temporary directory, read-only access to `.git`, restricted
networking, and a small inherited environment. Override it with a table or a
callback: >lua

  sandbox = {
    enabled = true,
    profile = {
      filesystem = {
        entries = {
          { path = vim.uv.cwd(), access = "write" },
          { path = vim.fs.joinpath(vim.uv.cwd(), ".git"), access = "read" },
          { path = "/absolute/secret", access = "deny" },
        },
      },
      network = "restricted",
    },
  }
<
Filesystem access is `read`, `write`, or `deny`; paths are canonical and
absolute. `network` is `restricted` or `enabled`. Lists replace their
defaults. A profile callback receives a copy of the default profile and the
tool context, then returns the complete profile.

Linux uses namespaces and seccomp. macOS uses
`/usr/bin/sandbox-exec`. Windows uses restricted accounts, ACLs, Job Objects,
and WFP and requires Neovim 0.12+. Provision Windows once from an elevated
PowerShell in the plugin checkout: >

  nvim --headless -u NONE -i NONE -n -l scripts/sandbox_windows_runtime.lua -- --setup
<
Set `NEOAGENT_WINDOWS_SANDBOX_STATE` before Neovim starts to choose another
state directory.

Custom tools participate when they route file and process effects through
`ctx.fs` and `ctx.process`. Tool Lua itself runs in Neovim.

A denied call can request one host execution by adding these tool arguments:
>json

  {
    "options": {
      "require_escalation": true,
      "escalation_justification": "why host execution is required"
    }
  }
<
Approval grants host capabilities for that call. Shell approvals may remember
a literal argument-token prefix for the current Session. Remembered rules are
held in memory and apply only to later calls that explicitly request
escalation. Compound or dynamic shell syntax always prompts.

Activation failures report the failed stage. An initial failure uses the host
executor and is shown in the workspace trust prompt or a UI warning. Failures
after successful activation return tool errors and do not fall back to host
execution.

Custom compositions can use
`require("neoagent.sandbox.composition").compose(toolset, config, runtime)`.
Use `.switchable()` when the caller needs runtime changes. Both return the
effective toolset and sandbox status; switchable composition also returns its
dialog source and runtime control.

Retries are configured separately under `retry`. Transient failures use
cancellable exponential backoff. Authentication, invalid-request, quota, and
billing failures return immediately. Context-window errors use compaction
recovery.

AGENTS.MD AND SKILLS                                  *neoagent-context-files*

Neo loads the global `stdpath("config") .. "/AGENTS.md"` and each project
`AGENTS.md` from the Git root to the Workspace. Outside Git, discovery starts
at the filesystem root. Files enter the prompt from broadest to most specific.

Skills are directories containing a `SKILL.md` with YAML `name` and
`description`. The defaults are:

  ~/.agents/skills
  stdpath("config") .. "/neoagent/skills"
  <project ancestor>/.agents/skills

Nearer project skills override broader or global skills with the same name.
Only metadata and the path enter the initial prompt; the model reads full
instructions on demand. Skill discovery requires an active file-reading tool.

Replace the configured lists to customize discovery. Empty lists disable those
locations. `agent_instructions = false` or `skills = false` disables that
resource type. The `neoagent.agent_instructions` and `neoagent.skills` modules
also expose `discover(opts)` and `format(resources)`.

PROVIDER RUNTIMES AND SERVICES                     *neoagent-provider-services*

Every configured provider is composed into one runtime: >lua

  {
    id = "example",
    definition = provider_definition,
    catalog = model_catalog,
    service = provider_service,
    credentials = provider_credentials,
    transport = provider_model_transport,
    auth_method = authentication_method_id,
    auth_services = shared_method_services,
  }
<
The runtime's ProviderCredentials value applies stored, configured,
environment, optional, and absent credential precedence for Models, catalogs,
Services, Authentication, and the Provider Shell. Its state is secret-free.

The ModelCatalog owns inventory, transformation, exact overrides, cache
freshness, and refresh work. Its direct API is: >lua

  catalog:start()
  catalog:snapshot()
  catalog:discoveries()
  catalog:subscribe(function(snapshot) ... end)
  catalog:refresh({ force = true })
  catalog:publish_discoveries(models[, opts])
  catalog:destroy()
<
`snapshot()` returns an owned value with `revision`, an ID-keyed `models`
map, `validated_at`, `stale`, `source`, bounded `refresh` state, and:
>lua

  persistence = {
    configured = true,
    enabled = true,
    error = nil,
  }
<
`configured` means a store and declared source ID and revision are present.
`enabled` means the current source fingerprint is safe for reads and writes.
`error` is the bounded reason an otherwise configured cache is unavailable.
Subscribers receive the current complete snapshot immediately and every later
revision.
`refresh()` returns a cancellable Run. One active generation owns discovery;
a newer refresh supersedes it. Current model Runs retain their already resolved
Model values across catalog publication.

`catalog.discover(ctx)` returns a cancellable Run whose successful value is
either `{ ok = true, models = {...}, validator = {...} }` or
`{ ok = true, unchanged = true, validator = {...} }`. The context contains the
bounded provider connection fields, transport, authentication and ambient-key
resolvers, the previous validator, `force`, and a clock. Source adapters return
sparse Model configurations with safe unique IDs. Successful discovery
produces an effective inventory containing at least one Model after
transformations, overlays, and removals. An empty effective inventory fails the
refresh and preserves the current snapshot, validator, and persisted cache.
An empty persisted discovery cache is ignored during restoration, which makes
the packaged or configured fallback active and eligible for immediate
discovery.
`publish_discoveries({})` supports provider operations that intentionally
clear an inventory. A packaged source uses the same contract as a remote or
local source.

Every discovery definition supplies stable source identity: >lua

  catalog = {
    source_id = "example-models",
    source_revision = 1,
    account_scoped = true,
    source_options = function(provider)
      local service_opts = provider.service_opts or {}
      return {
        management_url = service_opts.management_url,
      }
    end,
    discover = discover_models,
  }
<
Increment `source_revision` when discovery semantics make an existing cache
unsafe. `account_scoped` requires an Authentication method that can derive a
safe opaque cache identity. The manager hashes that value before catalog
composition; credentials and raw account metadata never enter catalog state.
An account-scoped source without a safe identity performs live discovery
without restoring or writing remote cache data.

`source_options(provider)` returns every additional provider option that can
change discovery results. The callback receives an owned projection containing
`api`, `base_url`, `auth`, `auth_optional`, and `service_opts`. Its
result contains JSON-safe nil, booleans, finite numbers, safe UTF-8 strings,
lists, and keyed tables without cycles or metatables. The canonical encoded
value is limited to 16 KiB and participates in the source fingerprint.
Discovery with non-empty `service_opts` requires this callback.

The normal Neoagent composition persists every catalog under
`stdpath("state") .. "/neoagent/model-catalog"`. Cache records use one strict
version-2 schema containing a source fingerprint, sparse discoveries,
`validated_at`, and optional ETag or Last-Modified validators. The fingerprint
covers API identity, normalized base URL, source ID and revision,
Authentication method, and hashed account identity when applicable. A mismatch
rejects the complete record. Provider policy and effective transformed Models
remain in the composed definition. Catalog persistence is independent from
Session `persistence.enabled`.

Stored credentials have first precedence. A configured API-key string follows,
then an environment API-key callback. Built-in API-key methods derive the
account identity from either stored or ambient key material and hash it with
the Authentication method ID. Matching stored, configured, and environment
keys therefore restore the same account-scoped cache without writing the key
to catalog state.

Remote provider catalogs use a fourteen-day TTL; the local router catalog uses
five minutes. Set one provider's `catalog.ttl_ms` to a positive integer number
of milliseconds to change its freshness window. Expired catalogs refresh
automatically; transient failures retain the snapshot and retry with bounded
exponential backoff. Authentication failures wait for login or an explicit
refresh.

A Provider Service supplies management status and provider-scoped operations:
>lua

  {
    id = "example",
    name = "Example",
    state = function(ctx) ... end,
    operations = {
      refresh = {
        label = "Refresh",
        run = function(ctx) ... end,
      },
    },
  }
<
Optional members are `wrap_model(model)`, `subscribe(listener)`,
`on_event(event)`, and `destroy()`. `wrap_model(model)` returns a complete
Model with `stream(opts)`; Neoagent validates the replacement before exposing
it to request selection.

Operations receive `ctx.provider`, raw `ctx.args`, `ctx.resolve_auth`, and
`ctx.interact` helpers for selection, input, confirmation, progress, and
notifications. They return cancellable Runs. A successful operation may return
a bounded document artifact, which opens with exact content in an unlisted
`nofile` buffer named under `neoagent://provider/`. Artifact names are safe
display text without path separators. Provider actions are provider-scoped and
receive no selected Model or Agent state.

Operations use concrete idempotent coordination values: >lua

  local use = provider_service.acquire_use(service)
  use:release()

  local action = provider_service.begin_operation(service, {
    mutating = true,
  })
  action:finish()
<
Non-mutating operations share access with Model, compaction, and catalog work.
Mutating operations require exclusive access to the Service. An operation
token is available to a manual owner or may be claimed by one Provider Run.
The claiming Run holds and releases that token through terminal settlement.

`neoagent.provider_state.new(snapshot)` creates a reusable dashboard channel.
Snapshots contain semantic `status`, `field`, `progress`, `limit`,
`list`, and `activity` blocks. The Provider Pane validates and copies updates,
composes content Tree nodes, and delivers them on Neovim's main
loop. A `field` may set `level` to `info`, `success`, `warn`, `error`, or
`muted` to place a health marker at the right edge.

The Provider Shell shows a selector when several services are configured. `✅`
means the provider is usable, `⭕` means required credentials are disconnected,
`📤` marks environment credentials, and `⚠️` marks an authentication error.
`<C-k>` and `<C-j>` select the previous and next provider while ordinary
motions retain their native behavior. The detail Pane shows provider
information, actions, model count, catalog source and freshness, and bounded
refresh errors.
Every usable provider has a `Refresh model catalog` action with ID
`neoagent.catalog.refresh`; it forces discovery even while the cache is fresh.

Authentication actions follow the selected provider's credential state. A
required logged-out provider shows Log in as its only action. An optional login
shows Log in alongside provider operations. A stored credential adds Log out.
Configured and environment credentials enable provider operations and remain
managed at their source. An active login shows Cancel login.
An active selection replaces the action menu with its choices and a cancel
action. Input and notice presentations occupy a modal Layer inside the
Provider Shell bounds and above its selector and detail Panes. Secret input
uses a concealed sensitive transient buffer with swap and undo persistence
disabled. Every following prompt uses a distinct transient buffer generation;
the secret buffer is overwritten and deleted before its native ownership is
released. Authentication, catalog, and Provider Service notifications appear
as bounded status feedback in the detail Pane. Provider runtime diagnostics use
the same feedback path while the bundled Provider Shell owns the runtimes.
Successful login forces a refresh for every catalog using that
Authentication method. Logout invalidates the same catalogs and forces
discovery for providers that remain usable through configured or environment
credentials.
Providers without a usable source remain offline. Provider Shell login and
logout release their exclusive Authentication-method coordination before
catalog refresh acquires shared Service use.
One Shell action owns login, logout, catalog refresh, or Service work through
settlement. Login and logout acquire exclusive access across every Service
sharing the Authentication method. Both release credential exclusivity before
the forced catalog refreshes acquire shared-use leases.

The built-in services are:

  openai        Reports 30-day organization completion usage and costs when
                permitted.
  openai-codex  Shows account limits and usage. Actions refresh usage, load
                activity and workspaces, inspect reset credits, and redeem a
                credit after confirmation.
  deepseek      Shows account balances in every returned currency.
  anthropic     Reports 30-day organization token usage and costs when
                permitted.
  zai           Shows the general API endpoint and current available and total
                API balance.
  zai-coding-plan
                Shows the plan endpoint and current token, credit, and MCP
                quotas.
  opencode-go   Shows shared subscription windows.
  llama.cpp     Shows endpoint health, available and loaded Models, and load,
                download, and request state. Service actions are `reload`,
                `catalog`, `load`, `unload`, `download`, and `preset`.

Claude Pro/Max access is provided through Anthropic's Claude Code product.
Anthropic publishes no third-party subscription API or OAuth client contract;
the built-in `anthropic` provider uses the supported metered Messages API.

The Provider Shell runs a service's non-mutating `refresh` operation whenever
the selected service gains shell focus. This includes opening, reopening,
focusing an already visible shell, and selecting another provider. Concurrent
focus requests coalesce with an active refresh; a request blocked by a
different operation waits at the Shell boundary. Switching providers cancels
a pending automatic refresh, while explicit provider actions retain their
operation boundary. The Shell performs no background polling. Use
`:NeoagentProvider operation [args]` to run an operation for the selected
provider and `:NeoagentProvider!` to cancel the active provider operation or
login. Opening from an Agent or Profile draft selects the provider of its live
model choice when that provider belongs to the shell. Opening the shell leaves
Profile drafts and Agent lifecycles unchanged.

Provider Service coordination is keyed by the concrete service value. Model
and compaction Runs hold shared-use leases. Catalog refresh and non-mutating
operations share access. Mutating shell operations require exclusive access,
and login or logout acquires exclusivity across the Authentication method's
complete Service group. Retiring Services wait for every lease and operation
token before destruction. Operation/runtime changes refresh the shell.

The Provider Shell API is: >lua

  local shell = applet:provider_shell()
  shell:providers()
  shell:select(provider_id)
  shell:cycle(step) -- step is -1 or 1
  shell:operations()
  shell:info()
  shell:run(operation[, args])
  shell:cancel()
  shell:login([provider_id])
  shell:logout([provider_id])
  shell:cancel_login()
  shell:open([origin])
  shell:close()
  shell:toggle([origin])
  shell:is_open()
  shell:is_active()
<

OpenAI and Anthropic organization queries use the same credential as model
requests. A key without access to a restricted reporting endpoint leaves model
data visible and adds a warning to the shell.

The Z.AI API service reads the available and total balance from the general API
balance endpoint with the normal Bearer API key. An unavailable balance
endpoint leaves the shell usable and adds a warning. Z.AI Plan quota
access uses the same key with its management Authorization form and recognizes
token-based and credit-based plan windows. Both services derive the management
origin from `base_url` and accept `service_opts.management_url` for a custom
endpoint.

llama.cpp model definitions can name a Hugging Face source and router load
parameters: >lua

  providers = {
    ["llama.cpp"] = {
      models = {
        qwen = {
          hf_repo = "ggml-org/Qwen3.5-0.8B-GGUF",
          quantization = "Q4_0",
          load = { ctx_size = 32768, gpu_layers = 99 },
          context_window = 32768,
          max_output_tokens = 80000,
          thinking = {
            off = {
              body = { chat_template_kwargs = { enable_thinking = false } },
            },
            high = {
              body = { chat_template_kwargs = {
                enable_thinking = true,
                reasoning_effort = "high",
              } },
            },
          },
        },
      },
    },
  }
<
The router supplies per-slot context size and input modalities when it reports
them. For unloaded models, Neoagent derives per-slot context from the router's
context-pool and parallel-slot arguments. Configured definitions override
router fields. Thinking levels are explicit
definition values because router metadata does not describe chat-template
controls. The definition ID is selectable and aliases its Hugging Face router
ID. `service_opts` may set `wait_timeout_ms`, `download_timeout_ms`, and
`poll_interval_ms`.

The built-in llama.cpp provider requests prompt progress and per-token timings.
The transcript footer shows prompt processing as `pp` once it has remained
active for two seconds, then token generation as `tg`, measured over a rolling
three-second server-time window. It displays one current phase and retains the
final generation rate until another inference starts.

HTTP RECORDING                                            *neoagent-recording*

Neoagent can record its provider HTTP exchanges for diagnosis: >lua

  require("neoagent").setup({
    recording = {
      enabled = true,
    },
  })
<
Recording is disabled by default. When enabled, it includes model streams,
model-catalog requests, Provider Shell operations, and HTTP performed by
built-in authentication methods. Each exchange records its prepared request,
response status and headers, response body, curl callback boundaries,
microsecond offsets, and terminal result. Model exchanges also record their
Workspace, Agent ID, Session ID, provider, and model so a Session can be linked
to its provider traffic.

Recordings default to: >lua

  vim.fn.stdpath("state") .. "/neoagent"
<
`recording.directory` is the state root used to organize both kinds of
recording. An exchange with an explicit Workspace is stored beneath the same
basename-and-hash Workspace directory used by settings and Sessions: >text

  <recording.directory>/workspaces/<basename>-<workspace-sha256>/recordings/<UTC-date>-<session-id>/
<
The Workspace directory also gains `workspace.json`, which identifies its
canonical root. A Workspace exchange without a Session ID uses `unscoped` as
the final directory component. Catalog, Provider Shell, and Authentication
exchanges have no Workspace owner and use: >text

  <recording.directory>/provider-recordings/<provider>/<UTC-date>/
<
An Authentication exchange without a provider identifier uses its
authentication method as the provider directory; a fully unscoped transport
uses `http`. Set `recording.directory` to an absolute or normalized state root
when a different owner, such as a test runner, supplies the storage location.
Each filename begins with a sortable UTC timestamp, process ID, and sequence,
then names its provider and origin. Normal filename sorting preserves
request-start order within one Neoagent process.

Each request/response pair owns one private staging file ending in
`.partial.ndjson`. Neoagent appends timing records while the request runs,
appends the complete response body and completion, and closes the file.
It then publishes one final file:

  `format = "auto"`   Use YAML when compatible Mike Farah `yq` v4 is on
                      `PATH`; otherwise publish JSON Lines.
  `format = "yaml"`   Require compatible `yq` v4 and publish `.yaml`.
  `format = "json"`   Publish `.jsonl` without invoking `yq`.

YAML conversion invokes `yq` once with the closed NDJSON staging file as its
input. Valid JSON request and response bodies become native YAML values and
carry `body_format = "json"`; other text bodies remain strings. A YAML
recording consists of ordered YAML documents and requires compatible `yq` for
machine replay. A JSON recording remains newline-delimited JSON and has no
`yq` dependency. A conversion failure retains the staging file for inspection.
Directories created by the recorder use mode `0700`; files use mode `0600`.

Authentication values, API keys, access and refresh tokens, OAuth client
identifiers and codes, passwords, cookies, private keys, credential-bearing
URL values, and known credential fields in non-model request bodies are
replaced by `*` before persistence or YAML conversion. Authentication adapters
classify responses known to contain credentials; those non-empty bodies are
`*`, while empty bodies remain empty. Request and response header names and
non-sensitive values are retained in stable name order; values carried by
credential-bearing headers are `*`.

Model request bodies bypass content sanitation. Ordinary response bodies also
bypass content sanitation, including credential-shaped text returned as model
output. NDJSON staging and JSON recordings store valid UTF-8 bodies
byte-for-byte. YAML recordings represent valid JSON bodies structurally and
retain other valid UTF-8 bodies as strings. Other bodies use lossless base64
with `body_encoding = "base64"`. Recordings therefore retain prompts, tool
schemas and results, images, generated text, provider payloads, and other
private interaction content. Treat the directory as sensitive and remove
captures when they are no longer needed.

Recording failures are reported without request or response content and do
not change the provider request result. A `.partial.ndjson` file identifies an
exchange interrupted by process exit or persistence/conversion failure.

WORKSPACE SETTINGS                                  *neoagent-workspace-settings*

With persistence and workspace settings enabled, the first accepted message in
a new Session commits its selected model and thinking level as the Workspace
preference for that Profile. Selecting another model changes live Agent or
draft state. Each accepted user message records its model and thinking state
with the message in one Session append, so resuming a Session restores the last
model used on its active branch. A resumed Session keeps its recorded model
independently from the Workspace preference.
When that first accepted Model has no thinking level, it writes the Session
clear marker and removes the Profile's Workspace thinking override. A later
thinking-capable draft then uses its configured Profile default.

Model and thinking preferences for bundled Agents are scoped by stable Profile
ID. Direct Agents use their configured name as the preference key. UI position
and the latest 100 accepted inputs are shared by the Workspace.

Unreadable, invalid, or unsupported Workspace settings leave configured
defaults active. The warning identifies the settings file to update or delete.
Workspace settings, Sessions, and input history share
`<persistence.directory>/<workspace-basename>-<workspace-sha256>/`.

Set `persistence.workspace_settings = false` to keep configured model,
thinking, and position values authoritative while retaining Sessions and input
history.

The reusable settings object is created with
`require("neoagent.workspace_settings").new({ directory, root })`. It exposes
`metadata()`, `load()`, `merge(defaults)`, `write(settings)`, and
`update(patch)`. Update recursively merges keyed tables and replaces lists,
scalars, and other values. A `vim.NIL` value deletes its key, and deletion
prunes empty Agent scopes. The encoded settings document contains no
tombstones.

Neoagent defines `<Plug>(NeoagentToggle)` and
`<Plug>(NeoagentCycle)` as stable targets for user mappings. It assigns
no concrete global lhs: >lua

  vim.keymap.set("n", "<leader>a", "<Plug>(NeoagentToggle)")
  vim.keymap.set("n", "<leader>A", "<Plug>(NeoagentCycle)")
<

built-in View. An editable prompt filters labels and details with
case-insensitive fuzzy matching. The first enabled result is selected
immediately. Use `<C-j>`/`<C-k>`, `<C-n>`/`<C-p>`, or the arrow keys to move

`<Esc>`, or `<C-c>`, Insert-mode `<C-c>`, and `:q` close the picker. Fork

Session selects its existing Agent. A dormant Session constructs an Agent from
its recorded Profile and Workspace. Profile-free and unavailable-Profile
Sessions are rejected. `:NeoagentCopySession` copies the visible Session's
complete tree after Profile selection. Fork and copy retain the source Agent
and foreground the derived Agent. A persisted derived Session becomes
authoritative when its document and index entry are published. If immediate
Agent construction or activation fails, the error reports the created path in
its message, sets `session_created = true`, and supplies `session_path` so
`applet:resume(path)` can open it. An activation failure after registration also
supplies `agent_id`; resume activates that live Agent and its existing Session
claim.

4. UI                                                               *neoagent-ui*

The built-in Agent UI is available to integrations as
`require("neoagent.ui").new(opts)`. It contains transcript, composer, details,
and dialog Panes. The Provider Shell uses a separate Applet.

An Agent Applet publishes a View only after composer text, draft context,
dialog and presentation state, and its explicit Agent snapshot hydrate
successfully. Binding queues Agent publications until snapshot hydration and
attachment commit. A thrown or returned View failure destroys the mutated
candidate, detaches provisional ownership, preserves semantic composer text,
and leaves binding retryable. Direct headless Agent construction defers the
top-level Applet, Pane, layout, image, and bundled Renderer modules until UI
composition is requested.

The transcript and Provider Shell use managed document Panes; the composer uses
an editable Pane. Dialogs, provider prompts, notices, and expanded details use
Applet Layers.
The transcript supports normal search, motions, Visual selection, and yank.
Streamed redraws pause during operations that require stable text.
Expanded details preserve their viewport until `<A-f>` enables following.
Expanded details retain complete logical rows. Text and thinking details use
native window wrapping, and tool details expose long rows through horizontal
scrolling. Transcript cards own width-based reflow and truncation. Raw Markdown
preserves the source line boundaries received from the model.
While following, a 150 ms timer moves the details window to the buffer end,
and the expanded-card border displays the active mode and toggle mapping. The
mapping and border hint are present only while a text or thinking card is
streaming; completion stops following and removes both.
Input accepted while an Agent is busy becomes steering. Steering is sent
after the current assistant response and tool calls. The interrupt mapping
cancels the Run and restores queued steering to the draft.

Filename completion is available in Insert mode when `ui.completion` is true.
Each Agent Applet
owns its history cursor; persistent Workspace history keeps the latest 100
accepted entries.

The input footer displays `<C-g>? help`. This mapping opens a persistent,
read-only mapping reference grouped into Input window and Transcript window
sections. `q` or `<C-c>` closes the reference and restores input focus.

Default mappings:

  <C-g>?      Open the Input and Transcript window mapping reference.
  <CR>        Submit input, accept completion, open details, or choose a menu
              item.
  <Tab>       Open filename completion or select its next item.
  <C-c>       Clear a draft; with an empty draft, stop the active Run.
  <Esc><Esc>  Hide the UI from input Normal mode.
  <C-d>       Hide the UI when input is empty.
  <A-k>       Move to the previous card. `<C-Up>` is an alias.
  <A-j>       Move to the next card or input. `<C-Down>` is an alias.
  <A-f>       Toggle periodic following in expanded card details.
  zz          Center the expanded card in the transcript while details retain
              focus.
  <C-w>j      Focus input.
  <C-w>k      Focus transcript.
  r           Toggle rendered and raw Markdown in text or thinking details.
  <S-Tab>     Cycle thinking levels.
  <A-n>       Open the Agent and Profile draft switcher.
  <A-m>       Select a Model.
  <A-r>       Resume a Session.
  <Up>/<Down> Browse input history.
  <C-k>       Browse toward older input.
  <C-r>       Select from input history.
  <A-Up>      Restore queued steering to input.
  <A-p>       Toggle the Provider Shell.
  <C-k>/<C-j> Select the previous/next provider in the Provider Shell.
  K/J         Jump to the active dialog or Provider Shell action menu, then
              move to its previous/next action.
  q           Hide the current Agent UI or Provider Shell.
  <C-c>       Close card details or the Provider Shell from those panes.

An active Provider Shell prompt uses `<C-c>` to cancel the prompt. Otherwise,
`<C-c>` closes card details or the Provider Shell from their read-only panes.
Transcript dialog actions use `<CR>` or their displayed shortcut keys. A newly
shown dialog focuses its declared default action, or its first enabled action,
while retaining any composer draft. Sandbox escalation requests default to
denial. Provider selector and action menus begin on their first enabled item
and use `K`/`J` plus `<CR>` consistently.

Every `ui.mappings` value accepts a lhs string, a list of lhs strings, or
`false`. Mapping keys are `help`, `submit`, `complete`, `interrupt`,
`close_input`, `close_empty`, `card_details`, `card_raw`, `card_follow`,
`card_center`, `card_previous`, `card_next`, `focus_input`,
`focus_transcript`,
`provider_previous`, `provider_next`, `menu_previous`, `menu_next`,
`cycle_thinking`, `agents`, `select_model`,
`resume_session`, `history_previous`, `history_next`, `select_history`,
`dequeue_steering`, `toggle_provider_shell`, `provider_close`, and `close`.

`ui.position` accepts `auto`, `left`, `right`, `top`, `bottom`, or
`center`. Width and height accept a fraction in `(0, 1]`, an integer greater
than one, or nil for the layout default.

`ui.provider_shell.position` accepts `left`, `right`, `top`, `bottom`, or
`center`. `ui.provider_shell.width` and `ui.provider_shell.height` use the
same dimension rules as the Agent UI.

Set `ui.show_thinking = false` to hide reasoning from the transcript while
retaining it in the Session. Set `ui.wrap_cards = true` to soft-wrap complete
card lines. The default clipped view recomputes when its Applet bounds
change.

The bundled Renderers display PNG attachment blocks through
`ui.images.backend = "kitty"`. Kitty supports direct terminals and tmux where
the protocol is available. A custom Neovim UI may construct
`Applet.ImageSystem` with another backend table; see |applet-images|.

Tmux 3.3 or newer must pass terminal graphics through every pane that can host
Neoagent: >tmux

  set -g allow-passthrough all
<

Image availability does not depend on terminal identity variables or Neovim
highlight color depth. ImageSystem sends bounded direct chunks and orders terminal
graphics after Neovim text through its serialized TUI transport.

Set `ui.images = false` to disable terminal images. Set
`ui.images.display = "expanded"` to keep a compact metadata tag in the
transcript and create the image only in the card-details window. The default
`"always"` displays it in the transcript and details. Unavailable transports and
unsupported attachment formats use one ellipsized metadata row without
reserving the configured image height. `:checkhealth neoagent` reports the
Kitty transport requirements.

Transcript images are left-aligned thumbnails whose automatic height is
bounded to 12 rows. Card-details images approach their native pixel size
within the available width. Both remain scrollable, and the card-details
mapping works from any transcript image row.

Tools can publish changing PNG previews through `ctx.on_update` by keeping one
image `id` and changing its `revision` with each complete byte snapshot. The
current preview remains visible while its replacement prepares. The final tool
result determines the image retained in the transcript; a text-only result
removes it. Transient previews are not journaled or sent in later model
requests, and cancellation rejects later producer updates.

RENDERERS                                                *neoagent-renderers*

A Renderer turns copied semantic values into native Pane content Tree nodes. Codex
is the default; Pi is also bundled: >lua

  local renderers = require("neoagent.ui.renderers")
  renderers.codex
  renderers.pi
  renderers.get("codex")
  renderers.names()
<
Select one with `ui.style` or provide `ui.renderer`. The explicit Renderer
takes precedence. `applet:set_renderer(renderer)` replaces one
Agent Applet's live Renderer and redraws its transcript.

A native Renderer has a non-empty `name`, an Applet `theme`, and these required
methods:

  render_block(block, env, continuation)
  render_details(block, env, continuation)

Each method returns a Pane content Tree node and an optional opaque
continuation. The next render of the same block on the same surface receives
that continuation. Components discard it when the block identity or Renderer
changes. Components can compose the node with `Applet.Pane.nodes.region`,
`text`, `panel`, `source`, `image`, `target`, `scope`, `column`, `row`,
`responsive`, and `virtual`. The compiler validates keys, UTF-8 text,
display-cell geometry, actions, ranges, and mappings before a managed buffer
commit. `render_block` and `render_details` receive a copied semantic block
plus bounded context containing extent, width, height, focus, theme generation,
and image capability. Values contain no buffers, windows, namespaces, extmarks,
mutable View state, or response callbacks. Tool `render(opts)` hooks return
bounded semantic values for the active Renderer to convert into Tree nodes.

5. CORE APIS                                                   *neoagent-core-api*

Models can be constructed without `setup()`: >lua

  local model = require("neoagent.api.openai_completions").new({
    provider = "local",
    model = "coder",
    base_url = "http://127.0.0.1:8080/v1",
    api_key = nil,
    input = { "text", "image" },
    context_window = nil,
    max_output_tokens = nil,
    request_opts = nil,
  })

  local run = model:stream({
    messages = messages,
    system_prompt = nil,
    tools = {},
    request_opts = nil,
    on_event = function(event) end,
    on_done = function(result) end,
  })
<
Other constructors are `neoagent.api.anthropic_messages`,
`neoagent.api.openai_responses`, and
`neoagent.api.openai_codex_responses`. The Codex constructor also accepts
`responses_lite`, `request_max_retries`, and `on_diagnostic`.

Every runtime Model has safe non-empty `api`, `provider`, and `id` fields, a
`stream` function, and a unique non-empty `input` list containing `text` and
optionally `image`. Optional `context_window` and `timeout_ms` values are
positive finite numbers. Optional `thinking` entries are named request-option
layers. API factories, Authentication wrappers, Provider Service wrappers,
and RequestSelection binding validate this complete shape.

Model events are `text_delta`, `thinking_delta`, `tool_call_delta`, `usage`,
and optional `provider_status` and `inference_stats`. Inference statistics use
exactly one of `prompt_tokens_per_second` and `generation_tokens_per_second`
for the current phase when the provider reports that measurement. Prompt
statistics include the phase's `elapsed_ms`. A successful result has
`{ ok = true, message, text }`; failure has
`{ ok = false, error, message? }`. Partial output may appear in a failure
message. Adapters retain meaningful text and thinking blocks plus protocol-
complete Tool calls. They omit open Tool-call and Responses item slots.
Cancellation uses `stopReason = "aborted"`; other failures use `"error"`.

A Run supports: >lua

  run:cancel()
  run:is_done()
  run:is_cancelled()
  run:result()
  run:diagnostics()
  run:await()       -- inside neoagent.async.run()
<
Callbacks run on Neovim's main loop and completion occurs once. Callback and
cancellation-handler failures leave the Run result unchanged and append
bounded `{ kind = "callback", phase, message }` diagnostics. Messages escape
invalid and control bytes and contain at most 1024 characters. `diagnostics()`
returns a copy of the newest 32 entries. An optional `report(diagnostic)`
callback passed to `neoagent.async.run()` receives a copied neutral record for
each failure. An awaited child without its own reporter forwards diagnostics
to its parent Run.
Thrown values are normalized through a total bounded renderer. A failing
`__tostring` metamethod produces a safe fallback message. A structured
`{ kind, message, ... }` error becomes an owned metatable-free copy with
sanitized kind and message fields.

`neoagent.async.await(start)` gives `start` a `done` value. A producer may call
`done.resolve(value, disposer)` when `value` transfers resource ownership. The
await owns a settled value until coroutine delivery. Cancellation before that
delivery invokes the disposer exactly once; cancellation while pending invokes
the producer cancellation function exactly once. Disposer and cancellation
failures become callback diagnostics. Callback queues preserve order with
incremental compaction during large streams.

The reusable Agent Loop is: >lua

  require("neoagent.agent_loop").run({
    model = model,
    messages = messages,
    system_prompt = nil,
    tools = {},
    commit_message = function(message)
      local ok, err = message_owner:append(message)
      return ok, err
    end,
    execute_tool = nil,
    context = nil,
    model_options = nil,
    get_steering_messages = nil,
    on_event = nil,
    on_done = nil,
    report = nil,
  })
<
It copies messages and uses exactly the supplied Model, tools, executor, and
context. The required `commit_message(message)` command returns `true` after
the message is authoritative or `nil, err` on failure. Its optional third
return is a matching copied message carrying `_neoagent_entry_id` presentation
metadata. Every assistant, Tool-result, and steering message commits before
its final observation and before dependent Tool or Model work. Preparation
validates and copies the complete semantic message list, request options,
Toolset, schemas, and callbacks before constructing a Run. Chat performs the
same preparation before accepting a user message. Malformed provider tool
arguments and declared schema mismatches become error tool results without
entering the executor. Schema diagnostics
begin with a general mismatch message followed by up to 20 deterministic,
path-aware issues. Local validation covers `type`, `enum`, `required`,
`properties`, `additionalProperties`, `items`, `minItems`, and `maxItems`;
Tool implementations validate additional domain semantics.

`get_steering_messages()` may return a second acknowledgement function. With
an acknowledgement, the list contains exactly one message. The Agent Loop
calls it once as `acknowledge(true, observation)` immediately after
`commit_message` succeeds, or as `acknowledge(false)` when commit returns or
throws a failure. The observation is an owned copy of the optional commit
observation. An acknowledgement failure ends the Run as a Session error.

Authentication is independently composable: >lua

  local manager = require("neoagent.auth").new({
    methods = { example = login_method },
    store = credential_store,
  })
  local authenticated = manager:wrap(model, "example")
<
Credentials are tagged `api_key` or `oauth` values. A login method may
provide `login`, `refresh`, `request_opts`, `public_metadata`, and
`cache_identity(credential)`. The cache identity is safe opaque text; the
manager hashes it with the method ID before returning it.
Stores implement `read`, `write`, `modify`, `list`, and `delete`.
`manager:list_credentials()` returns secret-free metadata.
`manager:cache_identity(id)` returns the hashed identity or nil, and
`manager:derive_cache_identity(id, credential)` validates an explicitly
supplied credential and returns the same method-scoped hashed form. Catalog
composition uses this method for configured and environment API keys.
`manager:subscribe(id, callback)` publishes copied login, identity-changing
refresh, and logout revisions.

Use `manager:wrap(model, id, { optional = true })` when an ambient credential
may run the Model without a stored login.

===============================================================================
6. TOOLS AND SESSIONS                                    *neoagent-composition*

A Tool is `{ name, description, input_schema, execute }`.
`execute(arguments, ctx)` returns
`{ content = { ... }, isError?, details? }`. Content blocks are UTF-8 text or
base64 images. Image blocks carry string `data` and a valid `image/*`
`mimeType`; Neoagent normalizes the MIME value to lowercase. An optional stable
`id` is non-empty UTF-8, contains no control characters, and is at most 512
bytes. Its optional `revision` is a finite number or non-empty UTF-8 string
with no control characters and at most 128 bytes. Image IDs are unique within
one result. Immutable final images may omit `id` and `revision`; transient image
updates supplied through `ctx.on_update` include both. The Agent Loop converts
malformed final results into tool errors and drops malformed transient updates.

`execute_tool(tool, arguments, ctx)` is the policy boundary for approval,
logging, sandboxing, and other decorators. Its context contains the Model, Run,
caller context, executor, update callback, and current tool call.
Model-produced arguments satisfy the locally supported `input_schema`
vocabulary before this boundary is entered.
An ordinary empty top-level Lua argument table is treated as an empty JSON
object. Nested empty arrays use a list value such as `util.list()` or decoded
`[]`; nested empty objects use `vim.empty_dict()` or decoded `{}`.

Optional Tool fields are:

  capabilities.read_files   Enable skill discovery for this toolset.
  on_messages(messages, ctx)
                            Derive state from the active conversation.
  render(opts)              Return semantic presentation data.

Configuration, |:checkhealth neoagent|, |neoagent-agent| toolset replacement,
and turn startup share one complete Tool validator. Names are safe, non-empty,
and unique; descriptions are UTF-8 strings; schemas use the supported
vocabulary; executors and optional hooks are functions. Model, prompt, request
options, executor, Tool values, and the provider-use lease are prepared before
a user message is accepted. Preparation failures leave the conversation
unchanged.

`details.changed_paths` tells the built-in Neo Agent which unmodified
buffers may be refreshed after a successful disk mutation.

Bundled presets: >lua

  require("neoagent.tools").coding()
  require("neoagent.tools").read_only()
  require("neoagent.tools").update_plan()
  require("neoagent.tools").all()
<
The coding preset provides file read, write, edit, shell, and Neoagent
documentation tools. File tools operate on disk. The optional plan tool derives
its current state from successful calls in the active Session path.

Bundled tools use `ctx.fs` and `ctx.process(argv, opts)` when supplied.
The filesystem capability implements `create_temp`, `read`, `mkdirp`,
`write_all`, and `atomic_replace`. Process options include `cwd`, `env`,
`clear_env`, `stdin`,
`capture`, `max_capture_bytes`, `timeout_ms`, `kill_grace_ms`, and
`on_output`. Results contain `code`, `signal`, `stdout`, `stderr`,
`output`, and `timed_out`.

The shell timeout defaults to 300 seconds. Set `shell_timeout = false` to
disable the default, or pass a positive `timeout` in the tool call. Captured
output is bounded; overflow is written through the filesystem capability.

`write_file` and `edit_file` replace their target through a temporary in the
same directory. Existing targets must be regular files, symbolic links are
rejected, and their permission mode is preserved. New files request mode
`0644`, subject to the process policy. Rename publication is process-visible
atomically; no power-loss `fsync` guarantee is provided.
Every host and sandbox implementation inspects the target again after the
temporary is complete. A missing target follows the creation policy. Any
other inspection failure removes the temporary and prevents rename.

`require("neoagent.session").new()` creates an in-memory Session. It accepts
`{ store = store }`, `{ messages = messages }`, or a validated
`{ entries = entries, leaf_id = leaf_id }` snapshot. Initial messages are
validated atomically and use the `user`, `assistant`, or `toolResult` role.
User content is UTF-8 text or text/image blocks. Assistant content is a list of
text, thinking, and Tool-call blocks. Tool results reference an earlier Tool
call and contain text/image blocks. Timestamps and usage values are finite;
semantic identifiers, signatures, and extension data are validated and copied.
The bundled store uses the current append-only JSONL tree format: >lua

  local store = require("neoagent.storage").new({
    directory = directory,
    cwd = cwd,
  })

  local session = require("neoagent.session").new({ store = store })
<
No file is created until the first message is accepted. Open an existing store
with `require("neoagent.storage").open(path)`.

An in-memory Session may also receive immutable `id`, `workspace`, `timestamp`,
`parent_session`, and `metadata` header values. `storage.new()` accepts opaque
`metadata` and optional `index_attributes` alongside `directory`, `cwd`, and
`parent_session`. Index attributes accelerate higher-level pickers and remain
disposable projections of authoritative Session headers.

Tree-aware Session methods are: >lua

  session:append(message[, state])
  session:id()
  session:identity()
  session:messages()
  session:context_messages()
  session:entries()
  session:entry(id)
  session:leaf_id()
  session:path([id])
  session:state()
  session:append_compaction(values)
  session:move_to(id)
  session:snapshot()
  session:metadata()
  session:store()
<
`state` may contain `model = { provider, model }` and `thinking_level`. The
bundled store records supplied state in the same `message` entry under one
file lock. Its stored `request` value contains `model` and `thinkingLevel`. The
journal contains `message`, `compaction`, and `leaf` entries.
`thinking_level` has three forms: omission preserves the active branch value,
a supported string selects a value, and `vim.NIL` clears it. The clear is
stored as `thinkingLevel: null`; `session:state().thinking_level` then returns
Lua `nil`. Reopen, branch, fork, and copy projections apply the same rule.
`append_compaction()` accepts `summary`, `firstKeptEntryId`, and
`tokensBefore`. Session and Store entry construction owns `type`, `id`,
`parentId`, and `timestamp`; payloads containing those fields are rejected.

Every committed JSONL record ends with a newline. An existing-file append uses
one verified regular-file handle to record its locked pre-size, write, confirm,
and restore that size after failure. Path identity loss or an unconfirmed
rollback or handle close makes the Store reject later mutations. A confirmed
append enters memory before a lock-release failure makes its Store reject later
mutations. First persistence binds to the identity returned by atomic
replacement. A failed pathname or close confirmation accepts that published
entry once, makes the Store reject later mutations, and omits its disposable
index entry. Opening a Store reads and removes an incomplete final record
through one verified handle under the Session lock, then validates the
remaining tree. This contract provides process-visible consistency; it does
not promise power-loss durability through `fsync`.

`move_to()` changes the active leaf; the next append creates a branch.
Create a linked child with: >lua

  local child = require("neoagent.storage").fork(store_or_path, {
    directory = directory,
    entry_id = user_entry_id,
    position = "before", -- or "at"
  })
<
`storage.derive(snapshot, opts)` requires target `directory` and `cwd`. It
atomically publishes a validated header and complete tree while preserving
entry IDs, timestamps, branches, compactions, and the active leaf.

The bundled Profile composition is
`require("neoagent.profile_sessions")`. It stores the stable Profile ID under
`metadata.neoagent.profileId`, preserves unrelated header metadata, and adds
one-hop provenance to copies. `new({ profile_id, workspace, persistence })`
creates a bound Session. `open(path)` returns the Session with its binding and
Workspace. `derive(source, opts)` accepts `kind = "fork"` or `kind = "copy"`
and a `target_profile_id`. `list(persistence, workspace)` projects bindings for
the resume picker. Generic Session and storage constructors remain
Profile-free.

`storage.list_sessions(directory, cwd[, opts])` returns recent picker records.
`opts.index_attributes(metadata)` may rebuild generic cached attributes from a
header.
Workspace session indexes are disposable and rebuilt from the JSONL files when
missing or invalid. Reads and appends use per-file locks.

Reusable locks are available from `neoagent.file_lock`: >lua

  local lock = require("neoagent.file_lock").new({
    path = persistence_path .. ".lock",
    timeout_ms = 15000,
    poll_ms = 50,
  })
  local result = assert(lock:with(function() return update() end))
<
Acquisition creates the parent directory when needed. `acquire()` returns an
owned lease with `release()`; `acquire_async()` is cancellable. The lock path
is a stable regular file with mode `0600`. Linux and macOS use `flock()` and
Windows uses `LockFileEx()` on an open handle. Process or handle exit releases
kernel ownership. Release verifies the held token and pathname identity before
unlocking and closing the handle; ordinary release keeps the stable path.

CONTEXT COMPACTION                                  *neoagent-compaction*

Automatic compaction runs near the Model's context limit and after a provider
context-overflow error. It stores a summary in the Session tree and uses that
summary before retained recent messages in later requests. The full tree
remains available for branch navigation.

The threshold is `context_window - reserve_tokens`; recent retention uses
`keep_recent_tokens`. Set `compaction = false` to disable all Agent
compaction or `compaction.auto = false` to keep manual and overflow
compaction.

`neoagent.compaction.run(opts)` returns a cancellable Run whose result contains
`summary`, `first_kept_entry_id`, `tokens_before`, and optional `usage`. The
module also exposes `settings`, `estimate_context`, `should_compact`, `prepare`,
and `serialize`.

Session adapters are: >lua

  require("neoagent.chat").send(session, prompt, opts)
  require("neoagent.chat").run(session, prompt, opts)
  require("neoagent.chat").continue(session, opts)
<
`continue()` uses projected context without adding a user message. The
optional `get_steering_messages` callback supplies user-message tables between
assistant/tool turns and supports the acknowledgement return documented under
|neoagent-core-api|. Session adapters allow one active mutation per Session.
This includes the interval in which the optional `on_accept` callback observes
a journaled user message. Acceptance callback failures are advisory and reach
the optional `report(message, level)` callback while the turn continues.
