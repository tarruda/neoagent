1. INTRODUCTION                                        *neoagent-introduction*

Neoagent provides streamed Models, cancellable Runs, and a plain Agent Loop.
The plugin adds optional tools, persistence, provider management, and a
floating UI.

Requires Neovim 0.10+, curl 7.76+, `rg`, and `fd`. ImageMagick's `magick` is
optional for image conversion. Check the installation with: >

  :checkhealth neoagent

===============================================================================
2. SETUP                                                      *neoagent-setup*

A minimal setup selects a model. Neoagent installs no global mappings: >lua

  require("neoagent").setup({
    default_model = {
      provider = "openai",
      model = "gpt-5.4",
    },
  })

  vim.keymap.set("n", "<leader>a", "<Plug>(NeoagentToggle)")
<
For a local OpenAI-compatible endpoint: >lua

  require("neoagent").setup({
    providers = {
      local_llama = {
        api = "openai-completions",
        base_url = "http://127.0.0.1:8080/v1",
        models = {
          coder = {
            input = { "text" },
            context_window = 131072,
            max_output_tokens = 8192,
          },
        },
      },
    },
    default_model = { provider = "local_llama", model = "coder" },
  })
<
Common defaults are: >lua

  {
    default_thinking_level = "medium",
    shell_timeout = 300,
    retry = { enabled = true, max_retries = 3, base_delay_ms = 2000 },
    compaction = {
      strategy = "summary", auto = true,
      reserve_tokens = 16384, keep_recent_tokens = 20000,
    },
    sandbox = { enabled = false },
    persistence = {
      enabled = true, workspace_settings = true,
      directory = vim.fn.stdpath("state") .. "/neoagent/workspaces",
    },
    ui = {
      style = "codex", position = "center", margin = 1, input_height = 7,
      scroll_on_submit = true, scroll_on_transcript_leave = true,
      scroll_on_reopen = true, wrap_cards = false, show_thinking = true,
      images = { backend = "kitty", display = "always" },
      provider_shell = { position = "center", width = 0.75, height = 0.75 },
      completion = true, border = "rounded",
    },
  }
<
Set `tools`, `execute_tool`, and `system_prompt` to customize coding behavior;
see |neoagent-composition|. Sandbox, project resources, recording, and UI
options are described in their sections below.

Provider tables recursively override the built-in registry. Assign `false` to
remove a provider, or set `default_registry = false` to use only configured
providers. For a source-free provider, a table under `models[id]` adds or
overrides that model. For a discovery-backed provider, it overrides the ID
while the current catalog contains it. Add a static entry under
`catalog.additions[id]` to keep that model selectable independently of
discovery. This extends the provider's catalog and preserves its discovery
source. `false` under `models[id]` removes the ID. A model may set `api` to
override its provider's adapter.

Use `catalog.additions` for unlisted models: >lua

  providers = {
    deepseek = {
      catalog = {
        additions = {
          ["deepseek-v4-flash"] = {
            input = { "text" },
            context_window = 1000000,
            max_output_tokens = 384000,
            thinking = require("neoagent.model_efforts").thinking_completions({
              "off", "low", "high", "max",
            }),
          },
        },
      },
    },
  }
<
Additions survive discovery refreshes; remove them from config and restart to
remove them. Their fields override discovery; `models[id]` takes precedence.
Adapter names are `openai-completions`, `openai-responses`,
`openai-codex-responses`, and `anthropic-messages`.

`catalog.transform_model(model, ctx)` receives a config copy and secret-free
context. Return modified or replacement config, or `false` to exclude the ID.
Exact-ID overrides apply last. `neoagent.model_rules.compile(rules)` builds a
transform from ordered patterns or predicates: >lua

  local efforts = require("neoagent.model_efforts")
  local transform = require("neoagent.model_rules").compile({
    {
      match = "^gpt%-5",
      set = { input = { "text", "image" } },
      apply = function(model)
        model.thinking = efforts.openai_responses({ "low", "medium", "high" })
        return model
      end,
    },
  })
  -- Assign transform to providers.openai.catalog.transform_model.
<
Rules run in order. `defaults` fills absent fields, `set` recursively overlays
fields, and `apply(model, ctx)` handles derived values or returns `false`.
`model_efforts` also provides Completions and Anthropic thinking constructors.

Providers, models, and individual Model calls may set `request_opts` to a
table or callback. The layers merge in that order across `url`, `headers`,
`body`, and semantic `messages`. Header names are case-insensitive, maps merge
recursively, and lists replace inherited lists.

A callback receives
`{ model, messages, system_prompt, tools, request_context, request }`. Request
identity is copied: Agents supply `workspace`, `agent_id`, and `session_id`;
drafts supply `workspace`. Direct constructors accept `request_context`;
`stream()` can add fields but cannot change bound values. The chat helpers
supply Session identity per call for unbound Models. Recording uses the same
identity.

Return `messages` to replace semantic content before modality adaptation and
file preparation. `body.messages` and `body.input` are encoder-owned.
Callbacks must avoid side effects: planning or credential changes can repeat
preparation.

A model's `thinking` table maps levels to request options. Levels are ordered
`off`, `minimal`, `low`, `medium`, `high`, `xhigh`, `max`, and `ultra`.
Missing levels are unavailable; `false` removes an inherited level. Selecting
a model starts at `default_thinking_level`, clamped to a supported value.

`input` lists accepted message modalities: `"text"`, `"image"`, or both.
Built-in adapters replace unsupported images in the request copy with a text
placeholder. Sessions keep the original image block.

The built-in `openai`, `openai-codex`, `deepseek`, and `anthropic` providers
upload eligible images lazily by default and reuse provider file IDs. Set
`file_uploads = false` to embed local bytes even when remote mappings exist:
>lua

  require("neoagent").setup({
    providers = {
      ["openai-codex"] = { file_uploads = false },
    },
  })
<

Uploads require supported native endpoints and PNG, JPEG, GIF, or WebP input.
OpenAI Platform uses API-key Responses; Codex uses ChatGPT's file service with
subscription Responses, including Lite. DeepSeek supports Completions,
Responses, and Messages; Anthropic uses Messages and Files. OpenAI Completions
and gateways embed images inline. Eligibility follows the Model's `input`
capabilities.

For Anthropic keys spanning workspaces, set
`request_opts.headers["anthropic-workspace-id"]`; uploads and mappings use
that workspace. Compatible models reuse uploads within a provider; providers
keep independent mappings. OpenAI Platform and DeepSeek request 24-hour
expiry. Codex checks availability on reuse; Anthropic files persist until
deletion.

Expired or missing files can be replaced before inference. Transient metadata
checks retry within the preparation deadline; uploads and local-read failures
return errors without inline fallback. File errors exclude credentials, signed
URLs, raw transport text, and response bodies.

Viewing a Session does not upload images. Preparation follows prompt
acceptance and can be cancelled while editing the next prompt. Remote
references reduce request bytes, not image token, count, or input-size limits.

The Anthropic provider enables ephemeral prompt caching by default. Set its
`prompt_caching = false` to disable automatically added cache controls.

The built-in system prompt follows the active tools and includes the working
directory. Set `system_prompt` to a string or callback to replace it. The
callback receives the Session, Model, Workspace, submitted prompt, tools, and
discovered resources. Configured AGENTS.md and skill context is appended to
the result.

BUILT-IN PROVIDERS                               *neoagent-built-in-providers*

The default provider IDs are:

  openai             OpenAI API; login `openai` or `OPENAI_API_KEY`.
  openai-codex       ChatGPT subscription; login `openai-codex`.
  anthropic          Anthropic API; login `anthropic` or
                     `ANTHROPIC_API_KEY`.
  deepseek           DeepSeek API; login `deepseek` or `DEEPSEEK_API_KEY`.
  alibaba-token-plan Alibaba Cloud Token Plan Personal; login
                     `alibaba-token-plan` or use
                     `BAILIAN_TOKEN_PLAN_API_KEY` for inference; optional
                     dashboard login provides quota reporting.
  zai                Z.AI API; login `zai` or `ZAI_API_KEY`.
  zai-coding-plan    Z.AI Plan; login `zai-coding-plan`, `zai`, or
                     `ZAI_API_KEY`. Both login names use the `zai` credential.
  opencode-go        OpenCode Go; login `opencode-go` or
                     `OPENCODE_API_KEY`.
  llama.cpp          Local llama.cpp router; login `llama`.

Open the Provider Shell with `:NeoagentProvider`, select a provider, and
choose an authentication action. Stored inference credentials take precedence
over a configured `api_key`, then an `api_key` callback such as an environment
lookup. Each logout action removes its corresponding stored credential.
Dismissing OAuth or device-code instructions leaves authorization running; use
`:NeoagentProvider!` to cancel it.

Credentials use `stdpath("state") .. "/neoagent/auth.json"` unless `auth.path`
is set. Credential listings contain IDs and types only.

Alibaba Cloud Token Plan Personal requires its dedicated `sk-sp-...` key from
Token Plan My Subscriptions and uses the Singapore plan endpoint. Supply the
key through login or `BAILIAN_TOKEN_PLAN_API_KEY`. The optional dashboard
login enables quota reporting and stores a separate credential.

Codex diagnostics default to `stdpath("state") .. "/neoagent/codex.log"`. They
contain bounded transport metadata and exclude credentials, HTTP bodies, and
conversation content. Configure or disable the sink under the provider: >lua

  providers = {
    ["openai-codex"] = {
      diagnostics = false,
      -- diagnostics = { path = "/private/path/codex.log" },
    },
  }
<

AGENTS AND APPLETS                                           *neoagent-agents*

`setup(opts)` creates the command-facing Neoagent Applet and registers the
Neo, Chat, and Codex Profiles. Neo and Codex are configured for coding; Chat
has an empty system prompt and no tools. Codex offers Models using the
`openai-codex-responses` API. A global default using another API is ignored
for Codex; its draft has no selected Model when none is compatible. Agents and
Sessions are created when work begins.

`:Neoagent` opens the Neo draft for the current Workspace. Drafts retain
model, thinking, sandbox, and input choices per Profile and Workspace until
the first accepted message creates an Agent. `:NeoagentCycle` lists drafts and
live Agents. Closing the UI leaves the Agent running.

A draft selects its model from the Workspace/Profile preference, configured
`default_model`, or first available provider/model. See
|neoagent-workspace-settings| for saved preferences.

The top-level Applet supports: >lua

  applet:toggle()
  applet:open()
  applet:close()
  applet:show_agents()
  applet:new(profile_id)
  applet:draft(profile_id[, workspace])
  applet:retained_draft(profile_id[, workspace])
  applet:resume([path])
  applet:fork([entry_id[, position]])
  applet:select_fork()
  applet:copy_session()
  applet:agents()
  applet:active_agent()
  applet:default_agent()
  applet:select(agent_or_id)
  applet:destroy_agent(agent_or_id)
  applet:foreground_applet()
  applet:toggle_provider_shell()
  applet:set_provider_shell(open)
  applet:provider_shell_open()
  applet:provider_shell()
  applet:destroy()
<

`require("neoagent").default()` returns the active or last foreground Agent
and may return nil before work begins. `require("neoagent").applet()` returns
the command-facing Applet. `applet:fork()` returns a cancellable Run whose
success contains `{ ok = true, agent, input? }`; validation can return
`nil, error` before starting. Session-copy selectors manage these Runs for
their caller. Destroying the Applet cancels pending derivations. Calling
`setup()` again replaces an idle composition; active Agent or authentication
work blocks replacement.

`new(opts[, runtime])` constructs an independent Agent immediately.
`runtime.session` and `runtime.workspace` bind caller-supplied values;
`runtime.runtimes` can supply shared provider runtimes: >lua

  local neoagent = require("neoagent")
  local session = require("neoagent.session").new()
  local review = neoagent.new({
    name = "Review",
    tools = require("neoagent.tools").read_only(),
    persistence = { enabled = false },
    system_prompt = "Review this project.",
  }, {
    session = session,
    workspace = vim.fn.getcwd(),
  })
<

Agent methods include: >lua

  agent:id()
  agent:profile_id()
  agent:label()
  agent:applet()
  agent:activity()
  agent:summary()
  agent:subscribe_activity(callback)
  agent:presenter()
  agent:dialogs()
  agent:prepare()
  agent:send(text)
  agent:steer(text)
  agent:dequeue_steering()
  agent:compact([instructions])
  agent:stop()
  agent:branch(entry_id)
  agent:select_branch([callback])
  agent:select_model([callback])
  agent:set_model(provider, model)
  agent:available_thinking_levels()
  agent:get_thinking_level()
  agent:set_thinking_level(level)
  agent:cycle_thinking_level()
  agent:set_ui_position(position)
  agent:subscribe(callback)
  agent:snapshot()
  agent:get_session()
  agent:get_model()
  agent:get_model_selection()
  agent:get_workspace()
  agent:get_process_sessions()
  agent:get_toolset()
  agent:set_toolset(toolset)
  agent:config()
  agent:is_running()
  agent:destroy()
<

Each Agent has fixed Profile, Session, and Workspace identity. `send()` starts
a turn while idle and queues steering while busy. `set_toolset()` replaces the
`{ tools, execute_tool }` pair between Runs and returns its previous value.

`destroy()` cancels work and releases owned resources. A destroyed Agent
rejects new work; caller-owned provider runtimes remain available. Retained
process sessions survive `stop()` and UI close. Configure their limits with
`runtime.process_sessions`; see |neoagent-process-sessions|.

`agent:subscribe(callback)` publishes `messages`, `context`, `event`,
`submission_accepted`, and `finish` updates with increasing revisions.
`snapshot()` supplies current state for a newly attached consumer.
`submission_accepted` identifies the prompt that became durable.

`agent:presenter()` serializes semantic selection, input, confirmation, and
notice requests. `agent:dialogs()` exposes the Agent's dialog source for
executor interactions. The bundled Agent Applet presents both; a headless
Agent uses the fallback host presentation.

`branch()` and `select_branch()` move inside the Agent's Session. New, resume,
fork, and copy operations belong to the top-level Applet, which keeps one live
claim for each Session ID.

WORKSPACE TRUST                                     *neoagent-workspace-trust*

The built-in Neo Profile asks for trust before loading project resources or
starting a tool-capable Run. Chat and direct Lua compositions use only
policies their caller supplies.

The target is the canonical Git worktree root, or the canonical working
directory outside Git. The prompt offers persistent trust, trust until Neovim
exits, and cancel (`t`, `s`, and `q`). Cancelling restores the submitted text
to the retained Profile draft.

Persistent decisions default to `stdpath("state") .. "/neoagent/trust.json"`.
Remove a path from that file to revoke trust. Configure another path or
disable the built-in policy with: >lua

  workspace_trust = { path = "/private/path/trust.json" }
  -- workspace_trust = false
<

Trust allows repository content to influence Neo. Executor and sandbox policy
control tool effects.

Custom compositions can construct `neoagent.workspace_trust.new(opts)` and
inject it through `neoagent.new(opts, { workspace_trust = policy })`.
`policy:request(workspace)` reports trusted, scheduled, or active state, and
`policy:attach(callbacks)` connects an interaction surface.

SANDBOXING                                                  *neoagent-sandbox*

Native sandboxing is experimental and disabled by default. Enable it for the
bundled coding Profiles with: >lua

  require("neoagent").setup({
    sandbox = { enabled = true },
  })
<

`:NeoagentToggleSandbox` changes the selected Agent or draft; running calls
keep their admitted authority. `:NeoagentSandboxInfo` reports support and
errors. Failed activation blocks restricted calls. Restore support or
explicitly disable sandboxing to permit host execution.

The default profile grants read-only host access, writes within the Workspace
and shared temporary directory, read-only access to `.git`, restricted
networking, and a small inherited environment. Override it with a table or
callback: >lua

  sandbox = {
    enabled = true,
    profile = {
      filesystem = {
        entries = {
          { path = vim.uv.cwd(), access = "write" },
          { path = vim.fs.joinpath(vim.uv.cwd(), ".git"), access = "read" },
          { path = "/absolute/secret", access = "deny" },
        },
      },
      network = "restricted",
    },
  }
<

Filesystem access is `read`, `write`, or `deny`; paths are canonical and
absolute. `network` is `restricted` or `enabled`. Lists replace their
defaults. A profile callback returns a complete profile from a default-profile
copy and admission context. `ctx.context` contains the workspace and execution
environment; `ctx.call` describes a Tool call, or `ctx.process` a retained
subprocess spec.

`environment.clear = true` starts with an empty environment; `inherit` selects
parent variables and `set` supplies explicit values. Variable names must be
nonempty and contain neither NUL nor `=`; names such as `ProgramFiles(x86)`
are supported. With `clear = false`, ambient variables are copied except
editor connection variables and known or credential-like names (including key,
token, secret, password, and credential segments). Explicit `inherit` or `set`
entries opt these variables back in. The worker always removes `NVIM`,
`NVIM_LISTEN_ADDRESS`, and its private bootstrap variable before running
Tools.

Neovim and Neoagent's installation files must remain readable under the
profile. A conflicting denial blocks execution; narrow it or move the
installation. `:NeoagentSandboxInfo` checks platform availability, not custom
profiles.

Linux uses namespaces and seccomp. macOS uses `/usr/bin/sandbox-exec`. Windows
uses restricted accounts, ACLs, Job Objects, and WFP, requires Neovim 0.12+,
and needs a local account database (domain controllers are unsupported). Run
one elevated setup from the plugin checkout: >

  nvim --headless -u NONE -i NONE -n -l scripts/sandbox_windows_runtime.lua -- --setup
<

Windows allows one registered host account and state directory per machine.
Set `NEOAGENT_WINDOWS_SANDBOX_STATE` before the first elevated setup to choose
it, and use that location in every Neovim configuration. Changing the account
or directory is rejected. A lost journal blocks setup and execution.

Concurrent invocations, including retained processes across Agents, may share
writable regions only with matching write policies. Other policies need
disjoint write regions and must preserve each other's protected paths.
Temporary storage is shared by policy; explicit temporary subdirectories
retain their paths. `lease-policy-conflict` means another invocation must
finish before admission. Admission and native cleanup each allow 60 seconds
for permission updates, separately from execution or health-probe timeouts.

Rerun interrupted elevated setup in the registered directory to finish
provisioning or recover an inaccessible disabled account. Incompatible
journals are rejected without conversion.

Host failure triggers recovery while the editor retains cleanup ownership.
Successful native recovery releases capacity even after an initial cleanup
error. If termination cannot be confirmed, `lease-job-unconfirmed` blocks
admission and preserves accounts, permissions, and reservations. Rerunning
setup cannot bypass it. A full Windows restart provides recovery evidence;
sleep and hibernation do not. Never delete the inventory or registry state to
bypass uncertain cleanup.

`read_agent_documentation` and `update_plan` run in the parent process even
when sandboxing is unavailable. Grant a custom Tool parent execution with
`sandbox.parent_tools`: >lua

  local inspect = {
    name = "inspect",
    description = "Inspect parent state",
    input_schema = { type = "object", properties = {} },
    execute = function()
      return { content = { { type = "text", text = "parent state" } } }
    end,
  }

  require("neoagent").setup({
    tools = { inspect },
    sandbox = { enabled = true, parent_tools = { inspect } },
  })
<
The grant matches the configured Tool's name and implementation function and
gives it full host authority. Other custom Tools are blocked in restricted
mode.

A denied call can request one host execution with: >json

  {
    "options": {
      "require_escalation": true,
      "escalation_justification": "why host execution is required"
    }
  }
<

Approval selects the original host Tool before that call begins. The bundled
shell implementation may remember a literal argument-token prefix for the
current Session, including when that Tool is renamed. Custom Tools cannot
inherit these approvals by sharing its name. Compound or dynamic shell syntax
always prompts.

Custom compositions can use
`require("neoagent.sandbox.composition").compose(toolset, settings, opts)`. It
returns a toolset, activation status, and dialog broker. Unavailable isolation
blocks restricted calls while parent Tools remain available. Use
`.switchable()` for runtime changes; its fourth return value controls the
sandbox state.

AGENTS.MD AND SKILLS                                  *neoagent-context-files*

Neo loads the global `stdpath("config") .. "/AGENTS.md"` and each project
`AGENTS.md` from the Git root to the Workspace. Outside Git, discovery starts
at the Workspace. Linked project resources are ignored. Files enter the prompt
from broadest to most specific. Explicitly configured global resources are not
subject to the project boundary.

Skills contain a `SKILL.md` with YAML `name` and `description`. Only metadata
and paths enter the prompt; the Model reads instructions as needed. Discovery
requires a file-reading Tool. Nearer project skills override same-name
entries.

Resource configuration defaults are: >lua

  agent_instructions = {
    global_files = { vim.fn.stdpath("config") .. "/AGENTS.md" },
    project_filenames = { "AGENTS.md" },
  },
  skills = {
    global_dirs = {
      vim.fn.expand("~/.agents/skills"),
      vim.fn.stdpath("config") .. "/neoagent/skills",
    },
    project_dirs = { ".agents/skills" },
  },
<
Replace lists to change discovery; empty lists disable those locations.
`agent_instructions = false` or `skills = false` disables that resource type.
Both `neoagent.agent_instructions` and `neoagent.skills` expose
`discover(opts)` and `format(resources)`.

PROVIDER RUNTIMES AND SERVICES                    *neoagent-provider-services*

The interactive composition shares provider runtimes. Direct Agents can reuse
them through `runtime.runtimes`. Each provides Authentication, a ModelCatalog,
and optional management Services.

A ModelCatalog owns the provider's selectable inventory. Its API is: >lua

  catalog:start()
  catalog:snapshot()
  catalog:discoveries()
  catalog:subscribe(function(snapshot) ... end)
  catalog:refresh({ force = true })
  catalog:publish_discoveries(models[, opts])
  catalog:destroy()
<

`snapshot()` returns a copy of the model map with revision, source, freshness,
refresh, and persistence status. Subscribers receive the current snapshot
immediately. Catalog updates leave already resolved Models unchanged.

`catalog.discover(ctx)` returns a cancellable Run. A successful result
contains `models` and may contain ETag or Last-Modified validator data; an
unchanged result preserves the current discoveries. A failed or empty
effective inventory preserves the published snapshot.

A discovery source declares stable cache identity: >lua

  catalog = {
    source_id = "example-models",
    source_revision = 1,
    account_scoped = true,
    ttl_ms = 14 * 24 * 60 * 60 * 1000,
    source_options = function(provider)
      return {
        management_url = provider.service_opts.management_url,
      }
    end,
    discover = discover_models,
  }
<

Increase `source_revision` when changed discovery semantics make an existing
cache unsafe. `source_options` returns JSON-safe provider options that affect
discovery. Account-scoped sources use a hashed Authentication identity and
perform live discovery when no safe identity is available.

Catalogs are cached under `stdpath("state") .. "/neoagent/provider/state"`,
independently of Session persistence. `catalog.ttl_ms` sets freshness; expired
catalogs refresh automatically and retain their snapshot on transient failure.

A Provider Service supplies management status and provider-scoped operations:
>lua

  {
    id = "example",
    name = "Example",
    state = function(ctx) ... end,
    operations = {
      refresh = {
        label = "Refresh",
        run = function(ctx) ... end,
      },
    },
  }
<

Optional members are `wrap_model(model)`, `subscribe(listener)`,
`on_event(event)`, and `destroy()`. A wrapped Model must satisfy the normal
Model contract. Operations receive provider configuration, raw arguments,
authentication resolution, and interaction helpers for selection, input,
confirmation, progress, and notification. They return cancellable Runs and may
return a document artifact for Neoagent to open.

Non-mutating operations may run with model, compaction, and catalog work.
Mutating operations require exclusive use of their Service. Login and logout
coordinate all Services sharing the Authentication method.

`neoagent.provider_state.new(snapshot)` creates a semantic dashboard channel.
Snapshots may contain `status`, `field`, `progress`, `limit`, `list`, and
`activity` blocks. A `field.level` may be `info`, `success`, `warn`, `error`,
or `muted`.

The Provider Shell invokes the Service's non-mutating `refresh` operation on
focus, with no background polling. Changing provider cancels a pending
automatic refresh; explicit operations continue when the Shell loses focus.

The Provider Shell API is: >lua

  local shell = applet:provider_shell()
  shell:providers()
  shell:select(provider_id)
  shell:cycle(step) -- step is -1 or 1
  shell:operations()
  shell:info()
  shell:run(operation[, args])
  shell:cancel()
  shell:login([provider_id])
  shell:logout([provider_id])
  shell:cancel_login()
  shell:open([origin])
  shell:close()
  shell:toggle([origin])
  shell:is_open()
  shell:is_active()
<

Restricted management endpoints may reject an otherwise valid model
credential. The provider remains usable and the Shell shows a warning. Z.AI
management origins derive from `base_url` and can be overridden with
`service_opts.management_url`.

llama.cpp model definitions can include a Hugging Face source, load
parameters, and explicit thinking request layers: >lua

  providers = {
    ["llama.cpp"] = {
      catalog = {
        additions = {
          qwen = {
            hf_repo = "ggml-org/Qwen3.5-0.8B-GGUF",

Catalog additions remain selectable independently of the router inventory.
Their IDs define loadable models and alias their Hugging Face router IDs.
`models[id]` may override a router-reported model without keeping it in the
catalog. `service_opts` may set `wait_timeout_ms`, `download_timeout_ms`, and
`poll_interval_ms`.

HTTP RECORDING                                            *neoagent-recording*

Provider HTTP recording is disabled by default. Enable it with: >lua

  require("neoagent").setup({
    recording = {
      enabled = true,
    },
  })
<

Recording captures requests, responses, timing, and outcomes for model
streams, catalog discovery, file uploads and metadata checks, Provider Shell
operations, and built-in authentication. Model exchanges include Workspace,
Agent, Session, provider, and model IDs.

`recording.directory` defaults to `stdpath("state") .. "/neoagent"`.
Recordings are stored under that root at: >text

  workspaces/<basename>-<sha256>/recordings/<date>-<session-id>/
  provider/recordings/<provider>/<date>/
<
Session-less Workspace exchanges use `unscoped` in place of the Session ID.
File uploads and metadata checks use the shared provider directories.

`recording.retention` controls completed files in each Session or shared
provider directory:

  `rolling`   Keep the newest successfully published exchange. This is the
              default.
  `all`       Keep every completed exchange.

Failed finalization preserves the previous recording and the partial file.

`recording.format` accepts:

  `auto`   Publish YAML when compatible Mike Farah `yq` v4 is on `PATH`;
           otherwise publish JSON Lines.
  `yaml`   Require compatible `yq` v4 and publish `.yaml`.
  `json`   Publish `.jsonl` without a `yq` dependency.

YAML recordings represent JSON bodies as native values. Binary and large
response bodies use marked base64 encoding. Replay preserves recorded bytes
and chunk boundaries; reading YAML requires `yq`.

Credential headers, credential-bearing URL values, known credential fields in
non-model requests, and authentication response bodies classified as sensitive
are replaced by `*`. Identifier-named request headers are masked too.

Model request bodies, media-upload bodies, and ordinary provider response
bodies are not sanitized. Recordings can therefore contain prompts, tool
schemas and results, images, generated text, and other private interaction
content. Treat them as sensitive when storing or sharing them.

Recorder directories and files use private permissions. Failures produce
content-free diagnostics and do not change provider results. A
`.partial.ndjson` file marks an exchange interrupted by process exit or
finalization failure. Failed finalization may also leave private `.body`
temporary files beside it.

WORKSPACE SETTINGS                               *neoagent-workspace-settings*

With persistence enabled, the first accepted message saves model and thinking
preferences per Workspace and Profile. A model without thinking clears that
preference. Resuming a Session uses its active branch's choices. Direct Agents
use their configured name as the preference key. UI position and the latest
100 accepted inputs are shared by the Workspace.

Settings, Sessions, and input history live under
`<persistence.directory>/<workspace-basename>-<workspace-sha256>/`. Invalid or
unreadable settings leave defaults active and report the file to correct.
`persistence.workspace_settings = false` keeps configured choices
authoritative while preserving Sessions and input history.

`neoagent.workspace_settings.new({ directory = path, root = cwd })` exposes
`metadata()`, `load()`, `merge(defaults)`, `write(settings)`, and
`update(patch)`. Update merges keyed tables, replaces other values, and
deletes `vim.NIL` keys.

5. CORE APIS                                               *neoagent-core-api*

Models can be constructed without `setup()`: >lua

  local model = require("neoagent.api.openai_completions").new({
    provider = "local",
    model = "coder",
    base_url = "http://127.0.0.1:8080/v1",
    input = { "text", "image" },
  })

  local run = model:stream({
    messages = { { role = "user", content = "Hello" } },
    on_event = function(event) end,
    on_done = function(result) end,
  })
<

Other constructors are `neoagent.api.anthropic_messages`,
`neoagent.api.openai_responses`, and `neoagent.api.openai_codex_responses`.
Optional settings include `api_key`, `context_window`, `max_output_tokens`,
`timeout_ms`, and `request_opts`; `stream()` also accepts `system_prompt`,
`tools`, and `request_opts`. A per-request `max_output_tokens` overrides
output settings in `request_opts` after shaping; Responses requires at least
16 tokens. `max_thinking_tokens` caps explicit thinking budgets (currently
Anthropic manual thinking), while `thinking_level` selects reasoning effort.
Manual thinking must fit below the output limit and is disabled when the
remaining budget is too small. Image-bearing calls supply `files`, a reader
for their local file references. Configured provider Models may also receive
`file_cache` from the same workspace. Session chat helpers bind both
dependencies automatically. The Codex constructor adds `responses_lite`,
`request_max_retries`, and `on_diagnostic`. A constructor also accepts the
copied `request_context` identity described above, and `stream()` may supply
additional identity fields using the same option.

`timeout_ms` is a positive integer deadline in milliseconds. A per-stream
`timeout_ms` overrides the constructor default; `false` disables that default
for one stream. Configured catalog entries use `request_timeout_ms` to supply
the constructor default.

Models expose `api`, `provider`, `id`, `stream`, and unique `input` modalities
(`text`, optionally `image`). Optional `context_window` and
`max_output_tokens` set budgets; wrappers preserve them.

`thinking_level` selects a declared mapping from `model.thinking`; explicit
`request_opts` take precedence. Omitting it keeps the configured wire options.

Built-in Models provide `estimate_request(opts[, "compact"])`, which returns
estimated input tokens after shaping. Pass the corresponding call's request
options and invoke it inside a Run, since Authentication may need to resolve
credentials. It performs no inference or file preparation. Model wrappers
preserve this method and acquire provider leases. Custom Models may omit it;
compaction then estimates messages, the system prompt, and Tool schemas.
Tokenization, images, and encrypted context remain approximate and may need
overflow recovery.

Errors can set `context_overflow = true` to request bounded context recovery.
Set `retry_exhausted = "request"` when the Model's retry budget is spent, so
outer recovery will not replay the failure. Compaction uses `"summary"` or
`"native_reduction"` for its own budgets. Errors with
`operation = "compaction"` do not trigger inference recovery. Estimation
failures before compaction is needed retain their normal classification and
retry behavior.

Codex Models provide `compact(opts)`, a cancellable Run returning one
encrypted context item and optional usage. Replaying the item requires its
original API, provider, and Model. Native requests do not inherit the Model's
stream output cap. Set `compaction_output_tokens` to cap native output; it
must be at least 20000 tokens. This minimum also applies to caps supplied
through `request_opts`.

Adapters preserve native assistant signatures for matching API, provider, and
model identities; omitted fields default to the destination. For other
identities, requests convert visible thinking to text and omit redacted
thinking, signatures, and phase metadata. Session messages remain unchanged.

Events include `text_delta`, `thinking_delta`, `tool_call_delta`, `usage`,
`provider_status`, `inference_stats`, and `warning` (with `message` text).
Results are `{ ok = true, message, text }` or
`{ ok = false, error, message? }`, possibly retaining partial output. A
successful `toolUse` response requires a `toolCall`; cancellation uses
`stopReason = "aborted"`.

Model-response validation errors have `kind = "protocol"` and a `code`:
`missing_tool_call` identifies a tool-use stop with no tool call;
`invalid_assistant_message` identifies other semantic validation failures.
Provider wrappers can inspect these codes without matching error text.

A Run supports: >lua

  run:cancel()
  run:is_done()
  run:is_cancelled()
  run:result()
  run:diagnostics()
  run:await()       -- inside neoagent.async.run()
<

Callbacks run on Neovim's main loop; completion occurs once. Callback and
cancellation-handler failures become bounded diagnostics without changing the
result. `async.run()` accepts a diagnostic reporter; awaiting a child forwards
its diagnostics unless it has its own. Forwarding survives cancelled Runs
until detached subprocess cleanup finishes observation.

`neoagent.async.await(start)` gives `start` completion callbacks and expects
an optional cancellation function. A producer that transfers a resource may
call `done.resolve(value, disposer)`; cancellation either cancels pending work
or disposes a settled value before delivery.

Call `neoagent.async.yield()` between bounded CPU work to keep editor events
and cancellation responsive.

The reusable Agent Loop is: >lua

  require("neoagent.agent_loop").run({
    model = model,
    messages = messages,
    tools = {},
    commit_message = function(message)
      local ok, err = message_owner:append(message)
      return ok, err
    end,
  })
<

The loop copies messages and uses the supplied dependencies. Optional fields
are `system_prompt`, `execute_tool`, `context`, `model_options`,
`get_steering_messages`, `prepare_request_messages`, `on_event`, `on_done`,
and `report`.

The async `prepare_request_messages(messages, options)` callback receives
copied messages and Model request options after commits, before each Model
call. Return replacement messages or `nil, err`; the Loop validates the list
and stops locally on failure. The list may contain a `nativeCompaction` item
for a compatible Model. To budget the request, estimate the final replacement
using the supplied options before returning it. Built-in adapters require a
fresh estimate if credentials or later changes alter request content;
credential-only header changes remain valid.

An optional third result, `acknowledge()`, runs immediately before the Model
call. Steering may trigger another preparation pass; only the final validated
pass is acknowledged. Use this to count request attempts, not provider
acceptance or completion. Rejected or cancelled preparation is not
acknowledged.

`commit_message(message)` returns `true` after the message becomes
authoritative or `nil, err` on failure. Its optional third result is a copied
observation message with presentation metadata. Assistant, tool-result, and
steering messages commit before dependent work or final observation. A
response containing only thinking is committed and followed up once. A second
empty response ends with a Model error and retained partial messages.

A failed Model may propose
`recovery = { message = user_message, warning = text }`. The Loop commits
partial output and that message, then prepares one follow-up. Standalone
`stream()` callers receive the proposal and own any follow-up. Usage remains
per response.

Tool schemas and model-produced arguments are validated before execution.
Malformed calls become error tool results.

`get_steering_messages()` may return one message and an acknowledgement
function. The Agent Loop calls `acknowledge(true, observation)` after commit
or `acknowledge(false)` when commit fails.

Authentication is independently composable: >lua

  local manager = require("neoagent.auth").new({
    methods = { example = login_method },
    store = credential_store,
  })
  local authenticated = manager:wrap(model, "example")
<

Credentials are tagged `api_key` or `oauth` values. A login method may provide
`login`, `refresh`, `request_opts(credential[, scope])`, `public_metadata`,
and `cache_identity(credential)`. `validate_credential(credential)` may
enforce a method-specific credential shape. Set `login_with_ambient = true`
when stored login remains available alongside an active environment or
configured credential. Stores implement `read`, `write`, `modify`, `list`, and
`delete`. Metadata and cache-identity APIs return values that do not contain
credentials.

Providers may bind independent Authentication methods to named scopes: >lua

  providers = {
    example = {
      auth = "example-inference",
      auth_scopes = { dashboard = "example-dashboard" },
    },
  }
<
Model wrapping uses `auth`. A Provider Service operation declares
`auth_scope = "dashboard"` and requests that credential with
`ctx.resolve_auth("dashboard")`. The Provider Shell gates the operation and
offers login and logout for each method independently. Authentication methods
may set `login_label` and `logout_label` for those actions.

Use `manager:wrap(model, id, { optional = true })` when the Model can run with
an ambient credential.

LOCAL SUBPROCESSES                                       *neoagent-subprocess*

`neoagent.subprocess_common` runs local processes under the caller's
authority. It provides `run(spec, options)` and `scope()` without Tools, RPC,
or a terminal buffer. Supported hosts are Linux (x86, x64, ARM, ARM64), macOS
(x64, ARM64), and Windows. Unsupported hosts fail before spawning with
`process_supervision`.

Call `run()` inside a managed Run: >lua

  require("neoagent.async").run(function()
    return require("neoagent.subprocess_common").run({
      argv = { "git", "status", "--short" },
      cwd = "/path/to/project",
      stdio = { kind = "pipes" },
      timeout_ms = 10000,
    }, { capture = { max_bytes = 65536 } })
  end)
<
`argv` is a non-empty list of NUL-free strings, passed without shell parsing;
`cwd` must be a directory. Use an explicit shell for shell syntax and an
explicit interpreter for portable script execution. Unknown fields are
rejected.

`environment = { inherit = true, set = {} }` is the default. Set
`inherit = false` for an exact environment; values must be strings. Both stdio
modes use the requested cwd and PATH. A bare POSIX PTY executable requires
PATH in the target environment; use an explicit path otherwise. Pipes retain
native PATH defaults. Windows searches cwd before PATH unless
`NoDefaultCurrentDirectoryInExePath` is present in Neovim's environment.
Lookup uses libuv's .com/.exe rules rather than PATHEXT and accepts quoted
PATH entries.

Windows strings use WTF-8 to preserve native UTF-16 paths. Environment names
are case-insensitive; duplicates are rejected. Drive entries such as `=C:` are
allowed in snapshots. An exact environment must include each of these keys
present in the parent (empty values are allowed): HOMEDRIVE, HOMEPATH,
LOGONSERVER, PATH, SYSTEMDRIVE, SYSTEMROOT, TEMP, USERDOMAIN, USERNAME,
USERPROFILE, WINDIR. Missing keys raise `process_validation`. PTYs add no TERM
or NVIM variables; set TERM explicitly when needed.

Pipe stdin defaults to closed; `{ kind = "pipes", stdin = "open" }` enables
writes. Run options may set `input = { chunks = { "data" }, close = true }`.
Bytes are sent without added newlines. For commands that intentionally consume
only a prefix, `input.allow_early_close = true` tolerates closed stdin; still
check the process exit and output.

`capture` is required: `false` disables capture, while `{ max_bytes = N }`
bounds aggregate capture and raises `output_limit` on overflow.
`on_output(event)` receives raw `{ stream, data }` events, where stream is
`stdout`, `stderr`, or `pty`. Observers must return promptly without yielding;
an error or yield fails the operation and terminates it. Spawn observers begin
after handle publication.

For retained execution, create `subprocess.scope()` before calling
`scope:spawn(spec, observer?)`. Close the scope when its owner ends and
observe cleanup with `scope:wait(timeout_ms)`, including when spawn raises
without returning a handle. Handle methods are:

  state()                   Copy phase, controls, outcome, and release state.
  write(bytes)              Accept at most 64 KiB per call.
  close_stdin()             Close pipe input after accepted writes; idempotent.
  flush()                   Await accepted writes and requested close.
  resize(columns, rows)     Request a PTY size.
  interrupt()               Send terminal input or a native interrupt.
  terminate(reason)         Request termination; idempotent.
  wait()                    Await the outcome; multiple waiters allowed.
  wait_cleanup()            Await cleanup observation.
  wait_release()            Await eventual native release.
  dispose(reason)           End ownership and request forced termination.

Waiting methods require a managed Run. Cancelling a waiter leaves the process
owned; cancelling `run()` disposes its target. Pending input is bounded to 1
MiB and 64 writes. On `input_limit`, flush before retrying. Write acceptance
and native write completion do not prove application consumption. Output
delivery is bounded even when editor callbacks are delayed.

`interrupt()` writes Ctrl-C to PTYs, subject to terminal input modes. POSIX
pipes receive SIGINT even with closed stdin. Windows pipes terminate their Job
because redirected processes have no portable console interrupt. No
termination grace or synthetic exit status is added. A failed signal raises
`process_signal` without ending ownership.

`timeout_ms` is a positive integer lifetime deadline, at most 2147483647 ms.
`kill_grace_ms` defaults to 1000 and accepts 0–60000. POSIX termination sends
TERM, then KILL after the grace; Windows terminates the Job. Disposal requests
forced termination immediately. Cleanup continues after caller cancellation. A
cleanup deadline failure raises `process_cleanup`, independently of process
timeout or exit status.

Outcomes contain `code`, `signal`, `timed_out`, `started_at_ns`,
`finished_at_ns`, `duration_ms`, and optional `termination_reason`. Non-zero
exits are ordinary outcomes; a numeric signal gives code `128 + signal`.
`run()` adds `stdout`, `stderr`, and callback-ordered `output`. Startup,
stream, observer, and cleanup failures raise structured errors without
inventing an exit status. Disposal rejects outcome waiters with
`process_disposed` unless an earlier failure won. `wait_cleanup()` rejects
only cleanup failures. After cleanup observation, `state().terminal` retains
any observed exit outcome even when `wait()` raises. Native identifiers are
not exposed.

`scope:run()` uses the same spec. `scope:close(reason)` disposes live handles
and rejects new work. `scope:is_settled()` means cleanup observation finished,
possibly with failure. `scope:wait(timeout_ms)` reports that failure or raises
`process_cleanup` if its own wait expires; cleanup remains owned.

`state().released` and `wait_release()` observe actual native release
separately. `scope:is_released()` and `scope:wait_release(timeout_ms)` include
failed starts. A later release does not erase a cleanup failure. Capacity must
stay reserved until release; descendants outside the containment boundary
below are excluded.

PTYs use `{ kind = "pty", columns = 80, rows = 24 }`. They merge stdout and
stderr; terminal modes govern echo, line endings, and control bytes.
`close_stdin()` is unsupported. Dimensions must be integers in 1–32767 on
Windows or 1–65535 on POSIX; invalid values raise `invalid_terminal_size`.
Resize acknowledges acceptance, not application handling; pending requests
coalesce to the latest size. A native resize failure raises
`process_terminal`.

Linux PTYs require glibc or musl with posix_spawn session and cwd support.
Windows requires ConPTY (Windows 10 version 1809+). Missing support raises
`pty_unavailable` without falling back to pipes.

macOS PTYs execute a short LuaJIT/FFI path after fork. Its safety depends on
libSystem and the LuaJIT build; native tests do not establish universal
post-fork safety. An active sampling profiler or unrestorable C debug hook
prevents startup. Execution acknowledgement has a five-second deadline.

POSIX supervision retains control of the original process group after leader
exit. Job control and detached descendants can escape it. Windows PTYs assign
a Job during creation; pipe Job assignment follows creation and has a startup
race. Full restricted descendant containment belongs to the sandbox lease.
Retained interactive Tools must not promise arbitrary POSIX descendant
control.

RETAINED PROCESSES                                 *neoagent-process-sessions*

`agent:get_process_sessions()` owns retained processes across activities and
UI closure. Agent destruction disposes them. This API adds no model-facing
Tools. Standalone callers can construct
`neoagent.process_sessions.new(options, on_cleanup?, controller_factory?)` and
must close the manager themselves. The default factory runs locally. Cleanup
observers receive failures on the editor loop despite caller cancellation;
target and later worker failures can be reported separately. Agents forward
them to diagnostics after destruction.

Neo and Codex use their current sandbox toggle for new admissions. Failed
activation blocks restricted admission; existing targets keep their authority.
Headless Agents use local placement unless
`runtime.process_placement(context, spec)` returns a controller factory. The
selector receives the execution context and a copied spec. Both placements
support Linux, macOS, and Windows.

Set Agent limits in `runtime.process_sessions`, or pass them to the standalone
constructor:

  Option         Default    Range          Purpose
  capacity       16         1–64           Reserved process slots.
  completed      32         1–256          Retained completed records.
  output_bytes   65536      1–262144       Bytes per output buffer.

Pending output and returned history each have this byte budget and a 128-event
limit. Excess old bytes are discarded while reads continue. Results report
`dropped_bytes` since the last collection. IDs and records are in memory only.

Reserve an admission before asynchronous startup: >lua

  local processes = agent:get_process_sessions()
  require("neoagent.async").run(function()
    local admission = processes:reserve({
      argv = { "sh", "-c", "cat" },
      cwd = vim.fn.getcwd(),
      stdio = { kind = "pipes", stdin = "open" },
      timeout_ms = 60000,
    })
    local result = admission.start(100)
    -- Publish result successfully before committing its handoff.
    local id = admission.commit()
    -- On publication failure, call admission.abort("publication failed").
    if id then
      result = processes:interact(id, 100, { kind = "write", data = "hello\n" })
    end
  end)
<
`reserve(spec)` is synchronous inside the publishing Run and returns the owner
before placement or startup. `admission.start(wait_ms)` starts once and
returns a copied observation. If the target completed, the result has no
`session_id` and `commit()` returns nil; otherwise commit publishes the
provisional ID.

Commit or abort every reservation, including unstarted ones. Keep the
admission with the publication owner when startup runs in a child Run.
Cancellation of the publishing Run aborts it; normal Run completion does not.
Future Tool integration must tie commit to durable result acceptance.

`interact(id, wait_ms[, control])` collects new output and optionally sends
one control. Wait budgets are 0–30000 ms, separate from the target lifetime
deadline. Polls wake on output or completion. Concurrent interactions raise
`process_session_busy`. Cancelling a poll preserves the target and unread
output; a later remote interaction waits for any outstanding acknowledgement.
Cancellation does not shorten worker supervision deadlines.

Controls are `write` with `data`, `close_stdin`, `resize` with `columns` and
`rows`, `interrupt`, and `terminate` with `reason`, each in a table with
`kind`. Writes accept at most 65536 bytes. Platform limits follow
|neoagent-subprocess|. Control errors preserve their `kind` and `code` across
sandbox placement; channel failures remain separate. Terminating a completed
target or repeating acknowledged stdin closure succeeds.

Results contain `events` (raw stream bytes), incremental UTF-8 `text`,
`dropped_bytes`, `stdin_writable`, `resize_supported`, and three lifecycle
flags:

  done           Target cleanup observation finished.
  cleanup_done   All controller cleanup outcomes, including worker shutdown, known.
  released       Native resource release confirmed.

Optional fields are `outcome`, `error`, `cleanup_error`, and `release_error`.
Incomplete UTF-8 is retained per stream; invalid bytes and gaps are escaped.
`history(id)` copies the bounded raw output already returned to callers.

`forget(id)` disposes a target and removes its record after release.
`close(reason)` rejects new work and disposes all controllers.
`wait_cleanup(timeout_ms)` and `wait_release(timeout_ms)` are async, with
positive bounded deadlines. Cleanup failure can precede eventual release and
remains observable afterward. Containment remains limited as described in
|neoagent-subprocess|.

`status()` returns `closed`, `reserved`, `completed`, `provisional`,
`quarantined`, `cleanup_done`, `released`, `reservations`, and the first
`cleanup_error`. `completed` counts finished committed targets, some still
reserving capacity. `reservations` copies records ordered by `session_id`,
with `committed`, `discarded`, `done`, `cleanup_done`, `release`, and optional
`cleanup_error` and `release_error`. Release is `pending`, `quarantined`, or
`released`; the error explains quarantine.

Failed starts and forgotten targets retain capacity until release is proven.
Only completed, released records are evictable. Losing remote release evidence
quarantines capacity; forgetting, closing, or worker exit cannot bypass it.
Windows can instead prove release through native sandbox cleanup; operation
failures remain visible. See |neoagent-sandbox| for recovery.

Custom sandbox compositions obtain a factory from
`sandbox_runtime:process_factory(context)`. An independently supplied platform
can use `neoagent.sandbox.placement.new(options)` with `profile`, `platform`,
and launch services, then
`neoagent.sandbox.process_session.factory(placement, context)`. Bind the
factory when constructing the manager. Each restricted target retains one
sandbox worker until cleanup and release.

6. TOOLS AND SESSIONS                                   *neoagent-composition*

A Tool is `{ name, description, input_schema, execute }`. Construct individual
bundled Tools with, for example, `require("neoagent.tools.read_file").new()`.
`execute(arguments, ctx)` is async and returns its final
`{ content = { ... }, isError?, details? }`. Content blocks contain UTF-8 text
or local image references:
`{ type = "image", file_id = sha256, mime_type = "image/png", bytes = byte_count, filename = "sample.png" }`.
`filename` is optional metadata. Transient image updates sent through
`ctx.on_update` require stable `id` and changing `revision` values; these
fields are removed from persisted image blocks.

Bundled `read_file` receives the Session's managed writer as
`ctx.context.files`. It stores the processed image bytes before returning a
reference; the original file can then change or disappear without changing the
attachment. `max_image_output_bytes` bounds the binary attachment, defaulting
to 3.375 MiB (4.5 MiB after base64 encoding) so retained images also fit
inline requests. With ImageMagick available, larger processed images are
recompressed as JPEG. The maximum is 8 MiB; individual model endpoints may
impose lower limits. Custom producers call the same writer's asynchronous
`put(bytes)` and use the returned `{ file_id, bytes }` in their image blocks.
Failed publication must fail the tool result rather than return a reference.

`execute_tool(tool, arguments, ctx)` is the policy boundary for approval,
logging, sandboxing, and other decorators. Model-produced arguments satisfy
the supported `input_schema` vocabulary before this function runs.

`details` is Tool-owned JSON data. Executors may add an `execution` JSON
object; both are retained in Session messages. Sandbox policy owns
`execution.sandbox`. `cleanup_failed` reports a cleanup error;
`cleanup_unobserved` means cancellation stopped the wait while cleanup
continued independently. `cleanup_kind` classifies that cleanup outcome
separately from the operation's `kind`. Neither changes a completed Tool's
success or failure. `cleanup_notice` is the one-based index of the explanation
in `content`, displayed alongside the Tool's ordinary preview and sent to the
Model. The content block owns the notice text.

Optional Tool fields are:

  capabilities.read_files   Enable skill discovery for this toolset.
  on_messages(messages, ctx)
                            Derive state from the active conversation.
  render(opts)              Return semantic presentation data.

Bundled presets are: >lua

  require("neoagent.tools").coding()
  require("neoagent.tools").read_only()
  require("neoagent.tools").update_plan()
  require("neoagent.tools").all()
<

The coding preset provides file read, write, edit, shell, and Neoagent
documentation tools. The optional plan tool derives its state from successful
calls on the active Session path.

Restricted execution recognizes only the shipped `read_file`, `write_file`,
`edit_file`, `shell`, `grep`, and `find` implementations. The executor
receives a copy with restricted `execute`; its other fields are unchanged.
Custom Tool grants are described in |neoagent-sandbox|.

These Tools limit prepared input strings to 16 MiB and paths to 32 KiB in both
local and restricted execution. File arguments use the editor's environment
and Workspace cwd in either mode. Restricted file reads, writes, and edits
have a 30-second execution deadline after worker startup, including
parent-side image import. A timed-out write or edit can have incomplete
effects; inspect the file before retrying.

The bundled shell Tool uses the parent Neovim's shell settings and the
Workspace cwd. It accepts a command and optional timeout, which defaults to
300 seconds; `shell_timeout = false` disables that default. Explicit timeouts
and numeric defaults must be positive and at most 2147483.647 seconds.
Restricted shell calls also enforce finite timeouts in the parent, with a
short allowance for command termination and response delivery if the worker
becomes unresponsive.

Command-backed Tools set `NVIM` to the executing editor's server address and
omit `NVIM_LISTEN_ADDRESS`. A restricted worker with no server supplies an
empty address. The local subprocess API itself inherits the OS environment.

`write_file` and `edit_file` replace regular files, preserve existing modes,
reject symbolic links, and request mode `0644` for new files.
`details.changed_paths` tells the interactive Neo Agent which unmodified
buffers may be refreshed after success. These are literal filesystem paths;
relative paths use the Workspace cwd without environment expansion. Bundled
file Tools report their prepared absolute targets.

`edit_file` accepts files up to 64 MiB and requires unique, non-overlapping
matches in the original content. Exact matches take precedence over a
punctuation- and whitespace-tolerant fallback. Edits preserve surrounding
text, the BOM, and line-ending convention.

`require("neoagent.session").new()` creates an in-memory Session. It accepts
an optional store, initial messages, or validated tree snapshot. Its `files`
option supplies an attachment writer; otherwise it uses in-memory storage.

The bundled append-only store is: >lua

  local store = require("neoagent.storage").new({
    directory = directory,
    cwd = cwd,
  })

  local session = require("neoagent.session").new({ store = store })
<

No Session file is created until the first message is accepted. Open an
existing store with
`require("neoagent.storage").open(path, workspace_storage)`. Obtain that
capability from `store:workspace_storage()` or resolve it explicitly with
`require("neoagent.workspace_storage").resolve(directory, cwd)`.

Workspace storage contains `workspace.json`, `sessions/<session-id>.jsonl`,
`files/<sha256>/content`, `provider-cache/<namespace>/<sha256>.json`, and a
rebuildable `session-index.json`. Back up or move the whole workspace
directory. There is no garbage collection: unused blobs and provider mappings
may remain.

Tree-aware Session methods are: >lua

  session:append(message[, state])
  session:id()
  session:identity()
  session:messages()
  session:context_messages()
  session:checkpoint_identity()
  session:entries()
  session:entry(id)
  session:leaf_id()
  session:path([id])
  session:state()
  session:preview_compaction(values)
  session:append_compaction(values)
  session:move_to(id)
  session:snapshot()
  session:metadata()
  session:store()
  session:files()
  session:file_cache()
<

`state` may include `model = { provider, model }` and `thinking_level`.
Omitted thinking state preserves the active branch value; a string selects a
level; `vim.NIL` clears it. `move_to()` selects another tree entry, and the
next append creates a branch.

`checkpoint_identity()` returns the active encrypted checkpoint's required
API, provider, and Model, or nil when there is none.

`append_compaction(values)` requires `tokens_before` and either:

  - Local: `summary` and optional `first_kept_entry_id` for the retained suffix.
    Omit the ID to summarize the whole active context.
  - Native: encrypted `native` and `retained_users`, an ordered list of
    `{ entry_id, text_chars? }` records referencing user messages on the active
    path. `text_chars` limits the request's text prefix across content blocks;
    images, journal messages, and transcript text remain intact.

`preview_compaction(values)` validates the same payload and returns
prospective request messages without changing the journal or leaf, or
`nil, error` if validation fails. Use it to budget the request before
publishing a checkpoint.

Create a linked child inside a Run with: >lua

  local run = require("neoagent.async").run(function()
    local child, err = require("neoagent.storage").fork(store, {
      directory = directory,
      entry_id = user_entry_id,
      position = "before", -- or "at"
    })
    if not child then error(err, 0) end
    return { ok = true, store = child }
  end)
<

`storage.derive(snapshot, opts)` creates an independent copy while preserving
the source tree. It is asynchronous and accepts `opts.source_files` when
importing attachments from another store. All retained branches are imported
before the destination document is published. Same-workspace copies share
blobs and provider mappings; cross-workspace copies import blobs only.
`storage.list_sessions(directory, cwd[, opts])` returns recent picker records.

`require("neoagent.profile_sessions")` associates Session headers with stable
Profile IDs. It provides `new`, `open`, `derive`, and `list` operations for
new, resumed, forked, and copied Profile Sessions. Generic Session and storage
constructors remain Profile-free. For `derive`, pass `target_native_api` when
the target Profile supports encrypted checkpoints. An active encrypted
checkpoint requires a matching target API, and the derived Agent must use the
original provider and Model.

Session documents are authoritative. Workspace indexes are rebuilt when
missing or invalid. Cross-process mutation uses `neoagent.file_lock`: >lua

  local lock = require("neoagent.file_lock").new({
    path = persistence_path .. ".lock",
    timeout_ms = 15000,
    poll_ms = 50,
  })
  local result = assert(lock:with(function() return update() end))
<

`acquire()` returns a lease with `release()`, and `acquire_async()` is
cancellable. Locks use OS advisory ownership and stable private lock files.

CONTEXT COMPACTION                                       *neoagent-compaction*

Automatic compaction runs before inference when estimated context reaches
`context_window - reserve_tokens`. Set `compaction = false` to disable it, or
`compaction.auto = false` to keep only manual and overflow recovery.
Successful final answers do not trigger compaction.

Neo and Chat retain a local summary and recent suffix, shortening the suffix
or consuming the whole active context when necessary. Codex retains recent
user messages before an encrypted checkpoint and requires the original API,
provider, and Model to resume. Local summaries cannot replace encrypted
context. Compaction changes request context; the complete Session tree remains
available.

Request budgets include shaping, the system prompt, Tool schemas, images, and
reserved output. `keep_recent_tokens` is an upper target, not guaranteed
retention. Summarizing Models must support the consumed images. Checkpoints
are validated and budgeted before publication; failures leave the prior
context and committed messages intact. A later continuation need not resubmit
the prompt.

Local summary requests lower thinking to `low` or the lowest enabled level,
preserving `off` and lower selections. Without a selection, configured
reasoning remains in effect. Output and thinking budgets must leave room for
summary text. Request copies may shorten large text and Tool results with
omission markers; reductions and overflow recovery are bounded.

`compaction.strategy` applies to Neo, Chat, and direct Agents:

  summary   Default. Serialize conversation for a dedicated summary prompt.
  prefix    Summarize the original prefix with its system prompt, Tool schemas,
            and message order, allowing servers to reuse cached prompt prefixes.

Prefix mode adds a temporary instruction outside the Session and rejects Tool
calls in summary output. If the request still cannot fit after reduction,
compact earlier or reduce the input. This setting does not affect Codex.

`agent:compact(instructions)` accepts focus text for local summaries. Native
compaction rejects non-empty instructions. The activity Run reports
preparation failures or missing compactable history; disabled compaction or an
unavailable Model can return `nil, error` immediately.

For the lower-level summary API, call
`neoagent.compaction.local_component.evaluate(opts)`, pass its decision as
`opts.budget` to `local_component.prepare(opts)`, then pass that result as
`opts.preparation` to `neoagent.compaction.run(opts)`. Evaluation and
preparation require a Run when Authentication is involved. Results contain
`summary`, `tokens_before`, optional `usage`, and optional
`first_kept_entry_id`. `neoagent.compaction` also exposes `settings`,
`estimate_context`, `should_compact`, and `serialize`.

Session adapters are: >lua

  require("neoagent.chat").send(session, prompt, opts)
  require("neoagent.chat").run(session, prompt, opts)
  require("neoagent.chat").continue(session, opts)
<
`continue()` uses projected context without adding a user message. The
optional `get_steering_messages` callback supplies user-message tables between
assistant/tool turns and supports the acknowledgement return documented under
|neoagent-core-api|. Session adapters allow one active mutation per Session.
`on_accept` observes a committed user message; callback failures reach
`report(message, level)` without stopping the turn.
