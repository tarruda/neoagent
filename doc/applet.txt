1. OVERVIEW                                                     *applet-overview*

The `applet` package has two primary values:

  Applet  A coordinated multi-window composition. It owns layout, Hosts,
          buffers, windows, focus, observation, and atomic publication.
  Pane    The content and runtime for one buffer. It owns content compilation,
          reconciliation, mappings, extmarks, scrolling, and optional images.

An Applet mounts existing Panes through a host-neutral layout. A floating Host
projects the layout as coordinated floats. A tab Host projects its main
topology as native splits in a dedicated tabpage. Both Hosts use floats for
Layers.

A Pane compiles a plain content Tree into ordinary Neovim buffer state. The
Tree describes lines, highlights, source annotations, mappings, targets,
window chrome, and image placements. The mounted Pane value is also the
runtime capability used for text, cursor, focus, scrolling, completion, and
native handle access. There is no second Pane-handle object.

`require("applet")` is the public module. It exports the concrete Applet, Pane,
layout, Host, presentation, interaction, image, and effect values used by
Neoagent. Modules under `lua/applet/` depend only on Neovim APIs and other
Applet modules.

The cursor is the selection model. Normal motions, search, marks, Visual
selection, registers, and yanking retain their native behavior for every key
that a content Tree or Applet layout does not claim.

2. PANE                                                             *applet-pane*

Create a Pane with fixed dependencies: >lua

  local Applet = require("applet")
  local ui = Applet.Pane.nodes

  local transcript = Applet.Pane.new({
    key = "transcript",
    extent = "document",       -- "document" or "viewport"
    buffer_mode = "managed",   -- "managed" or "editable"
    frame_interval_ms = 50,     -- optional automatic presentation cadence
    render = function(state, env)
      return ui.text({
        key = "message",
        text = state.message,
      })
    end,
    handlers = {
      choose = function(event)
        print(event.payload.id)
      end,
    },
    on_error = function(err)
      vim.notify(err.message, vim.log.levels.ERROR)
    end,
  })
<
`key` is the Pane's stable identity in an Applet layout. `extent = "document"`
allows natural output beyond the visible window and leaves scrolling to
Neovim. `extent = "viewport"` bounds physical and virtual output to the
mounted height. An editable Pane leaves physical text and undo under Neovim
while it owns virtual chrome, decorations, mappings, and actions.

`frame_interval_ms` bounds the automatic presentation cadence for frequently
updated state and content Tree submissions. Every submission immediately
becomes the newest pending value; the next frame commits that value. The first
submission after connecting is presented immediately. Native viewport,
surface, Theme, and image-resource invalidations request the next safe
InteractionDomain turn immediately.

Pane and Applet submissions are immutable borrowed values: >lua

  transcript:set_state({ message = "Hello" })
  transcript:set_state({ message = "Ready" }, { eager = true })
  transcript:update(tree)       -- submit a content Tree directly
  transcript:set_theme(theme)   -- recompile semantic styles
  transcript:flush()            -- bypass cadence for eager rendering
<
The caller retains ownership and does not mutate a submitted value. Each
semantic change supplies a new value, affected subtree, or revision. Pending
submissions coalesce to the newest generation. A failed render,
content compilation, or commit preserves the last committed Layout and
reports `{ pane, phase, generation, message }`.

`set_state(state, { eager = true })` bypasses the configured frame interval
while retaining InteractionDomain safety. It suits terminal lifecycle and
direct-interaction submissions that must settle on the next safe domain turn.

Pane retains a compiled document when consecutive Trees share the same root
table and equal layout constraints, Theme generation, and image generation.
Chrome, view intent, and editable state are validated and committed
independently. Owners can retain immutable root identity for status-only
updates without traversing document regions.

A document root composed entirely of regions with explicit revisions retains
its longest unchanged prefix when its root table changes. Pane compiles and
reconciles from the first affected region. Region revisions cover their child
content and image sources.

Compiled Layouts are compared as exact immutable Lua values. Reconciliation
receives one categorized change set for content, decorations, interaction,
images, regions, sources, virtual text, chrome, and view state.

An Applet creates and connects the buffer and window for every mounted Pane.
Closing an Applet retains its Pane buffers for reopening; destroying it releases
the complete mounted runtime.

The Pane runtime methods are:

  key()                    Return the stable Pane key.
  is_destroyed()           Report completed resource destruction.
  is_editable()            Report editable buffer semantics.
  is_connected()           Report a live Applet connection.
  is_settled()             Report that the latest submission is committed.
  is_mounted()             Report a valid buffer/window mount.
  is_visible()             Report Host visibility.
  is_focused()             Report semantic and native focus.
  geometry()               Return mounted logical and screen rectangles.
  focus()                  Focus the mounted Pane.
  mode()                   Return `normal` or `insert`.
  text()                   Return the current buffer text.
  replace_text(text[, cursor[, revision]])
                           Replace an editable Pane's text.
  cursor()                 Return `{ line, column }`.
  set_cursor(cursor)       Apply a semantic cursor.
  at_start()               Test the first editable position.
  at_end()                 Test the final editable position.
  move_cursor(direction[, count])
                           Move up, down, previous, next, start, or end.
  scroll(opts)             Scroll to a target and optional alignment.
  focused_target()         Return the target under the cursor.
  targets([opts])          Return copied targets, optionally filtered by group.
  move_target(opts[, count])
                           Move among semantic targets.
  reveal_target(key)       Reveal one exact target.
  focus_target_intent()    Focus and reapply the submitted target intent.
  completion_visible()    Report Neovim popup-menu visibility.
  complete()               Start native filename completion.
  completion_move(direction)
  completion_accept()
  native()                 Return `{ buffer, window }` for advanced use.
  destroy()                Release Pane-owned resources; idempotent.

Text is readable for managed and editable Panes. Text replacement and
completion require an editable Pane. Cursor values use a one-based `line` and
zero-based byte `column`. `focus_target_intent()` focuses the Pane and reapplies
its current `view.target_intent`, including the optional reveal target.

An `InteractionDomain` coordinates safe commits: >lua

  local domain = Applet.InteractionDomain.new({
    critical = function() return completion_is_settling() end,
  })
<
Visual, Select, operator-pending, register-prefix, and host-declared critical
interactions defer physical commits until `SafeState`.
The Domain activates its global key observer while at least one connected Pane
participates and releases it when the final participant disconnects.

3. APPLET                                                         *applet-layout*

An Applet owns one coordinated presentation lifecycle for several Panes. Its
layout describes a main Pane topology, split allocation, Layers, focus, and
ambient bindings. Create Panes first, then mount the same values: >lua

  local Applet = require("applet")
  local layout = Applet.layout

  local input = Applet.Pane.new({
    key = "input",
    buffer_mode = "editable",
    render = render_input,
  })

  local applet = Applet.new({
    name = "example",
    host = Applet.host.floating({
      container = "editor",
      side = "right",
      width = 0.5,
      height = 1,
      margin = 1,
    }),
    render = function(state, env)
      return {
        root = layout.frame({
          key = "example:frame",
          child = layout.split({
            key = "example:body",
            axis = "vertical",
            children = {
              {
                key = "document",
                grow = 1,
                child = layout.mount(transcript, {
                  required = true,
                  buffer = { filetype = "example" },
                }),
              },
              {
                key = "input",
                basis = { content = 3 },
                grow = 0,
                child = layout.mount(input, {
                  required = true,
                  focus = { mode = "insert", cursor = "end" },
                }),
              },
            },
          }),
          layers = state.dialog and { state.dialog } or {},
        }),
        focus = { initial = "input" },
      }
    end,
    handlers = {
      ["example.save"] = function(event)
        print(event.pane:key())
      end,
    },
    on_error = function(err)
      vim.notify(err.message, vim.log.levels.ERROR)
    end,
  })

  applet:set_state({})
  applet:open()
<
`Applet.new()` requires a non-empty `name` and a Host value or Host resolver.
A resolver is `function(state) return host end` and requires state-driven
`render`. Optional constructor fields are:

  render        Convert copied state and a handle-free environment into one
                complete Applet layout.
  handlers      Map non-`applet.*` action names to callbacks.
  domain        Use an injected InteractionDomain owned by the caller.
  critical      Add an unsafe-commit predicate to an Applet-owned domain.
  notify        Replace the package-owned notification effect.
  open_uri      Replace the package-owned URI-opening effect.
  on_focus      Receive `(current_pane_key, previous_pane_key)`.
  on_resize
  on_pane_buffer_change
  on_pane_close
                Receive a copied event and an idempotent `default` callback
                after an observed external change.
  on_error      Receive `{ applet, phase, generation, pane, message }`.

The Host constructors validate and copy plain policy values: >lua

  Applet.host.floating({
    container = "editor", -- "editor", "largest_window", or "auto"
    side = "center",      -- left, right, top, bottom, or center
    width = 0.9,           -- fraction or positive integral cells
    height = 0.9,
    margin = 1,
    base_zindex = 40,
  })

  Applet.host.tab({
    position = "after", -- before, after, first, or last
    label = "Example",
  })
<
`applet:set_host(host_or_resolver)` selects the next Host policy and reprocesses
the current submission. A Host-kind change takes effect on the next open
epoch. `applet:host()` returns its copied semantic descriptor.
`applet:is_visible()` distinguishes an open Applet in an inactive tab from one
currently visible.

An Applet layout is a complete snapshot: >lua

  {
    root = layout.frame({
      key = "frame",
      child = layout_node,
      layers = { layer_node },
    }),
    bindings = { binding, ... },
    focus = {
      initial = "input",
      intent = { key = "details", revision = 4 },
    },
  }
<
Every frame, split, scope, layer, and split child has a stable non-empty key.
A mount derives its identity from `pane:key()`. `frame.child` accepts mount,
split, or scope nodes. `frame.layers` is an ordered list of layer nodes.
Focus intents apply once for one contiguous `{ key, revision }` occurrence.
Removing an intent ends that occurrence, so the same token may be submitted
again later. Applet retains only the current occurrence token.

A split allocates one axis: >lua

  layout.split({
    key = "body",
    axis = "vertical", -- vertical stacks; horizontal places side by side
    revision = 2,
    children = {
      {
        key = "main",
        basis = 0.8,
        grow = 1,
        shrink = 1,
        min = 1,
        max = 100,
        child = mount_or_scope_or_split,
      },
    },
  })
<
`basis`, `min`, and `max` accept positive integral cells or a fraction in
`(0, 1]`. A basis also accepts `{ content = true|cells, min = value,
max = value }` and includes Pane chrome in the allocation. `grow` and `shrink`
are non-negative weights. A changed `revision` discards adopted native tab
split sizes.

A scope contributes ambient mappings to every Pane in its subtree: >lua

  layout.scope({
    key = "provider-scope",
    bindings = { binding, ... },
    child = mount_or_scope_or_split,
  })
<
Mount one existing Pane with optional lifecycle and surface policy: >lua

  layout.mount(input, {
    lifecycle = "retained", -- retained or transient
    owns_pane = false,
    required = true,
    mount_revision = 1,
    buffer = {
      name = "input",
      uri = nil,
      filetype = "example-input",
      sensitive = false,
      options = { buftype = "nofile", swapfile = false },
    },
    window = {
      border = "rounded",
      options = { wrap = true },
      host_options = {
        floating = {},
        tab = {},
      },
    },
    focus = {
      mode = "insert",       -- normal, insert, or preserve
      cursor = "preserve",  -- preserve, start, or end
    },
    bindings = { binding, ... },
  })
<
Retained mounts keep their buffer across close and reopen. Transient mounts
delete their owned buffer at unmount. `owns_pane` transfers Pane destruction
to the Applet when that mount identity expires. A required mount makes its
first content commit part of open success. Changing `mount_revision` or
calling `remount(key)` clears suppression after an external detach. Sensitive
buffers require a transient mount and disable swap and undo-file persistence.
Transient buffer generations include mount revision, sensitivity, and Pane
identity. Replacing a sensitive generation allocates a fresh buffer, moves
foreign windows away from the prior buffer, overwrites it, and deletes it while
the sensitive descriptor remains attached.

A Pane can be mounted only once in one submitted layout and by only one live
Applet. The Pane key is opaque layout identity; display labels belong in Pane
content or chrome. Applet mapping dispatch retains its originating Insert or
Replace intent while the callback runs and applies the final focused Pane
policy when the callback completes. A `normal` policy cancels that intent,
including temporary Normal transitions that return to editing. An `insert`
policy enters Insert mode, and `preserve` restores the Pane's retained mode.
Focusing an existing mounted Pane keeps its live native cursor and viewport.
Applet restores retained cursor and viewport snapshots while mounting windows
across Host and Frame lifecycle transitions.

A Layer anchors an overlay subtree: >lua

  layout.layer({
    key = "dialog",
    container = "applet", -- editor, applet, or an earlier Pane key
    anchor = "center",
    width = 0.8,
    height = { content = true, min = 1, max = 20 },
    zindex = 80,
    modal = true,
    enter = true,
    restore_focus = true,
    child = mount_or_scope_or_split,
  })
<
Anchors are `center`, `top`, `bottom`, `left`, `right`, `top_left`,
`top_right`, `bottom_left`, and `bottom_right`. Width and height use the split
dimension forms and default to `0.8`. Modal Layers constrain focus to their
Pane subtree and higher modal Layers. Removing a Layer with `restore_focus`
restores its captured Pane focus.

Applet bindings use the Pane-content binding shape: >lua

  {
    mode = "n",
    lhs = "q",
    action = Applet.Pane.nodes.action("applet.close"),
    desc = "Close applet",
    nowait = false,
    silent = true,
  }
<
The built-in Applet actions are `applet.close`, `applet.focus`,
`applet.focus.move`, and `applet.focus.restore`. Pane content target actions
are also available. Content modal scopes, Applet modal scopes, content scopes,
mount bindings, layout scopes, and root bindings form one ordered mapping set
installed by each mounted Pane.

Lifecycle and observation methods are:

  set_state(state)       Borrow state and submit it through `render`.
  update(layout)         Borrow and submit a complete layout directly.
  set_host(value)        Select a Host value or resolver.
  open([opts])           Open or focus; `opts.origin_window` selects origin.
  close([opts])          Close; `restore_origin = false` suppresses restoration.
  toggle([opts])         Open or close.
  is_open()              Report the logical lifecycle.
  is_destroyed()         Report completed resource destruction.
  is_visible()           Report current Host visibility.
  host()                 Return the active or next semantic Host.
  observed()             Return the latest copied Host Snapshot.
  focus(key)             Focus one allowed mounted Pane.
  focused_pane()         Return its semantic key.
  pane(key)              Return the exact mounted Pane value when known.
  remount(key)           Clear external-detach suppression.
  notify(message[, level])
  open_uri(uri)          Run injected package-owned effects.
  flush()                Settle pending renders and observations eagerly.
  invalidate([opts])     Refresh Host facts or reset adopted split sizes.
  destroy()              Release every resource; idempotent.

Pending generations coalesce. Render, layout compilation, measurement,
staging, and publication failures preserve the prior committed Frame or roll
opening back to `closed`. Applet publishes copied Host Snapshots before
external callbacks. Callback mutations settle after the current observation
batch.

An open Applet activates live window, tab, buffer, mode, scroll, resize, and
option observers. Closing releases those broad observers. Each retained buffer
uses a buffer-local unload, delete, and wipeout observer until its next open or
final release.

`Applet.layout.compile()` exposes the pure layout compiler: >lua

  local frame = Applet.layout.compile({
    tree = applet_layout,
    host = Applet.host.floating({}),
    editor = { row = 0, col = 0, width = 160, height = 48 },
    container = nil,
    measurements = {},
    overrides = {},
    handlers = { ["example.save"] = true },
    has_action = function(name) return false end,
  })
<
`render(state, env)` receives semantic editor, Host, origin, focus, lifecycle,
generation, and measurement facts. Neither the environment nor compiled Frame
contains native handles.

`Applet.presentation.new()` creates an editable input presentation, a
two-Pane selection picker, or a managed notice from a semantic request. A
picker owns case-insensitive fuzzy matching and semantic selection. A notice
uses normal-mode `q`, `<Esc>`, and `<C-c>` cancellation. `Applet.Presenter`
implements `select`, `input`, `notice`, `confirm`, `notify`, and `open_uri` as
the default host fallback.

`Applet.host_effects` supplies `refresh_file(path)`, `open_document(document)`,
and `on_exit(callback)`. `Applet.Pane.text` supplies display-cell `width`,
`slice`, `truncate`, and line splitting.

4. CONTENT TREES                                                   *applet-trees*

Constructors in `Applet.Pane.nodes` return plain tables. Every node has a
stable, non-empty key. A complete Pane content Tree has this form: >lua

  {
    root = node,
    chrome = {
      title = { { text = " Example ", style = "strong" } },
      title_pos = "center", -- "left", "center", or "right"
      footer = nil,
      footer_pos = "center",
      options = { cursorline = true },
    },
    view = {
      scroll = "preserve", -- or "follow_end"
      initial_target = nil,
      target_intent = nil,
    },
    edit = {
      on_change = ui.action("draft.changed"),
    },
  }
<
The content primitives are:

  region      A stable vertical reconciliation unit with optional revision.
  text        Rich runs with explicit or native wrapping, clipping, tabs, and
              styles.
  column      Vertical children separated by a fixed gap.
  row         Horizontal children with growth weights. An explicit `width`
              beyond the available width creates native horizontal scrolling.
  container   A fixed two-dimensional box with clipped absolute layers and
              stable z-order.
  responsive  The first variant matching current width and height.
  panel       Padding and whole-line background styling.
  source      A range annotated with a path or language for syntax.
  image       A fixed cell rectangle with searchable text fallback.
  target      Cursor-selectable semantic content and an optional action.
  scope       Mappings active for a subtree or the complete buffer.
  virtual     Virtual lines anchored above or below physical content.

`view.target_intent` selects an exact target after content reconciliation.
Its `key` identifies one contiguous occurrence, `select` names the cursor
target, and optional `reveal` names a second target whose final line remains
visible with the selection when both targets fit in the viewport. Removing the
intent permits its key to be used again. Pane retains only the current
occurrence key.

`text.background` applies one semantic whole-line highlight to every compiled
line without padding its physical text. Use `panel.background` when the node
also needs allocated padding. Pane carries this highlight through the
`breakindent` and `showbreak` prefix of natively wrapped lines.

Document roots may be one region, a column containing only regions, or any
ordinary node, which becomes one implicit region. A root scope may wrap those
forms. Regions are vertical units and do not appear inside rows or nested
layout nodes.

Text nodes accept `wrap = "word"`, `"character"`, `"none"`, or `"native"`.
The first three modes compile physical buffer lines at the available content
width. Native wrapping preserves each logical line for Neovim soft wrapping.

A rich-text run accepts one `style`, one `group`, or a `groups` list. The list
preserves layered highlights over the same text. Each item is a highlight
group name or `{ group = name, priority = integer }`; `{ style = name }`
resolves a semantic Theme style. Pane emits a separate extmark for every
layer.

`Applet.Theme.new()` creates an independent derived-highlight namespace.
`theme:derive(key, spec)` returns one stable group per semantic key, up to
`max_derived_highlights` (256 by default). Independent Theme values never
overwrite one another's derived groups. Reaching the bound returns the base
group, or `nil` when no base is supplied.

A container allocates a fixed inner rectangle. `width` and `height` describe
that rectangle; a border and down-right shadow extend its outer dimensions.
The ordinary `child` begins inside `padding`. Entries in `layers` are
containers with an absolute position relative to the parent's inner top-left
cell. Layers clip to that inner rectangle. Higher `zindex` values paint above
lower values, and later declarations paint above earlier declarations at an
equal z-index. Borders paint above their container's contents. Negative layer
coordinates move content through the top or left clipping edges. >lua

  ui.container({
    key = "stage",
    width = 80,
    height = 24,
    child = document,
    layers = {
      ui.container({
        key = "details",
        position = {
          mode = "absolute",
          row = 3,
          col = 12,
          zindex = 70,
        },
        width = 48,
        height = 14,
        padding = 1,
        background = "NormalFloat",
        border = {
          kind = "rounded",
          style = "border",
          title = " Details ",
          title_pos = "center",
        },
        shadow = {
          row = 1,
          col = 2,
          character = " ",
          style = "shadow",
        },
        child = details,
      }),
    },
  })
<
Every positioned layer requires explicit `width` and `height`. Background,
border, title, and shadow styling accept semantic `style` values or concrete
`group` values. A custom border supplies eight one-cell characters in
Neovim's floating-border order. Transparent cells expose lower layers. Text,
highlights, targets, scopes, source annotations, and image viewports project
through the same visible-cell composition.

Viewport overflow is explicit on the root content node:

  error     Reject output above the presentation height.
  clip      Retain a prefix or suffix and a physical overflow marker.
  collapse  Compile a supplied summary node.

Use `Applet.Pane.widgets.menu`, `Applet.Pane.widgets.dialog`, and
`Applet.Pane.widgets.card` for common compositions. Widgets return primitive
content Trees and install no hooks. Dialog navigation and action bindings
belong to its modal scope, so they work from every cursor position inside the
Pane.

A three-option menu with an initial selection is: >lua

  local menu, entry = Applet.Pane.widgets.menu({
    key = "options",
    initial = "two",
    items = {
      { key = "one", label = "One",
        action = ui.action("choose", { id = 1 }) },
      { key = "two", label = "Two",
        action = ui.action("choose", { id = 2 }) },
      { key = "three", label = "Three",
        action = ui.action("choose", { id = 3 }) },
    },
    keys = {
      previous = "<Up>",
      next = "<Down>",
      activate = "<CR>",
    },
  })
  pane:update({
    root = ui.column({
      key = "example",
      gap = 1,
      children = {
        ui.text({ key = "message", text = "Choose an option:" }),
        menu,
      },
    }),
    view = {
      target_intent = Applet.Pane.widgets.menu_intent(entry, "options-open"),
    },
  })
<
Menus return their primitive scope and an entry descriptor covering the
requested `initial` item, or the first enabled item, and the final visible
item. `menu_intent(entry, key)` converts that descriptor into a target intent
which selects the entry and keeps the complete menu visible when it fits. The
initial item must be enabled. Focused items use the `selected` Theme style.
Menus claim no default keys. With the explicit keys above, arrow
movement and Enter are semantic while `h`, `j`, `k`, `l`, and every other
unclaimed key remain native. Either movement key selects the first enabled
item when the cursor is outside the menu group. Horizontal padding on an item
row belongs to its nearest menu item, keeping cursor-based selection stable
across native column changes. Menu titles, labels, and details use word
wrapping by default. Set `text_wrap` to `word`, `character`, `none`, or
`native` to apply that mode throughout one menu. Dialog action menus are
vertical and default to Up, Down, and Enter. `initial_action` chooses their
entry and they return the action-menu entry descriptor as a second value.

===============================================================================
5. INTERACTION                                               *applet-interaction*

Actions are plain references: >lua

  ui.action("provider.run", { operation_id = "refresh" })
<
Handlers use names outside the reserved `applet.*` namespace. Pane content
provides these built-in actions:

  applet.target.move      Move among enabled targets in one optional group.
  applet.target.activate  Dispatch the selected target's action.
  applet.target.reveal    Move the cursor to one exact target.

Target movement anchors to an enabled candidate containing the cursor. At a
free cursor position, `next` selects the first following candidate and
`previous` selects the last preceding candidate. `entry = "first"` selects the
first enabled candidate from a free position in either direction. Reaching a
document boundary returns `false`; a movement with `wrap = true` cycles through
that boundary.

An Applet adds:

  applet.close            Close the complete Applet.
  applet.focus            Focus `payload.pane`.
  applet.focus.move       Move focus left, right, up, or down.
  applet.focus.restore    Restore focus captured by the active Layer.

A scope is the content primitive that claims mappings. Modal scope bindings
take precedence, followed by the innermost matching scope and its parents.
Duplicate bindings and ambiguous overlapping sibling scopes fail compilation.
Applet layout scopes and mount bindings participate in the same precedence
order.

Handler events contain the action, copied payload, count, mode, cursor facts,
and the exact `event.pane` value. Applet-dispatched events also include
`event.applet` and the committed Applet generation.

A target can describe cursor-dependent chrome with `focus_style` and `focus`.
Move and reveal actions place the cursor on its first non-blank physical line,
falling back to its first line when the target contains only whitespace.
`focus_style` highlights its physical rectangles while the Normal-mode cursor
intersects them. `focus.active` and `focus.inactive` are lists of virtual-text
decorations selected by the same cursor relationship.

Each focus decoration has a target-relative non-negative integer `row` or the
value `"end"`, optional display-cell `col`, non-empty `chunks`, and either
`position` (`overlay`, `eol`, `right_align`, or `inline`) or `win_col`. An
optional non-negative `priority` defaults to 200. The row immediately after
the target is addressable so a composition can draw a bottom edge on an
existing boundary line. `"end"` resolves that boundary after dynamic content
such as prepared images establishes its physical height.

Visual and Select modes suppress target chrome so native selection remains
clear. Reconciliation restores both free cursor positions and surviving
target-relative positions.

6. IMAGES                                                         *applet-images*

Create one image system with an explicit backend and share it among related
Panes: >lua

  local images = Applet.ImageSystem.new({
    backend = my_backend, -- or "kitty"
    max_source_bytes = 20 * 1024 * 1024,
    max_cache_bytes = 80 * 1024 * 1024,
    max_pixels = 40 * 1000 * 1000,
  })
<
ImageSystem validates PNG sources, bounds source size, pixel count, and cached
bytes, and publishes one complete presentation per Pane. The bundled `kitty`
backend uses the Kitty graphics protocol. A backend table implements:

  available                           Report current availability as a boolean.
  cell_dimensions()                   Return terminal cell pixel dimensions.
  replace(owner, placements)          Replace one complete owner presentation.
  clear(owner)                        Relinquish one presentation owner.
  release(resource)                   Release an unreferenced prepared PNG.
  redraw(owner)                       Reapply a current presentation.
  destroy()                           Release the complete backend.

`replace` receives every desired placement for `owner` in one list. Each
placement contains its slot `key`, validated PNG `resource`, fixed cell
dimensions, fit, screen position, and optional source viewport. An optional
`set_error_handler(callback)` reports a transport failure. ImageSystem captures
the backend generation around every backend call and publishes candidate state
only when that generation remains available and current. A synchronous error
callback or thrown method destroys the backend once and clears resources and
presentations before the caller can publish its candidate.

`Applet.ImageSystem.diagnostics({ backend = "kitty" })` reports whether the
current terminal provides the ordered Kitty transport needed for persistent
placements. A custom backend owns its protocol-specific diagnostics.

Pane reads terminal cell pixels from terminal window geometry. Explicit
`cell_width` and `cell_height` options override detection. Kitty uses `1:2` as
the aspect-ratio fallback when pixel geometry is absent.

Image nodes accept bounded PNG bytes or trusted local PNG paths. Byte sources
carry an owner-defined `id`; `id` and `revision` form their constant-cost
identity, keeping image payloads outside Layout comparison: >lua

  ui.image({
    key = "attachment:42",
    source = {
      kind = "png_bytes",
      id = "attachment:42",
      data = screenshot_png,
      revision = 3,
    },
    alt = "Screenshot attached by the user",
    width = "fill",
    height = "auto",
    max_height = 12,
    fit = "contain", -- "contain", "cover", or "fill"
    align = "left",
  })
<
Integer widths and heights reserve exact cell dimensions. `width = "fill"`
uses the available width. `width = "native"` approaches the source pixel
width without exceeding available cells. `height = "auto"` preserves source
aspect ratio using detected cell pixels; `max_height` bounds the result.

The owner keeps `id` unique for distinct byte resources that can coexist in a
shared ImageSystem and supplies a finite numeric or string `revision`, changing
it whenever source contents change. Numeric and string revisions are distinct
identity values.

An image node `key` identifies one visual slot. ImageSystem owns the slot set
that the backend has presented for each Pane. When a slot publishes a new
source revision, Pane requests the desired source and compiles the presented
source until that preparation completes. First load uses the compact fallback.
Removing the node submits a presentation without that slot. An unavailable
backend clears every presentation and compiles fallbacks.

Pane resolves the complete visible presentation before invoking ImageSystem.
It clips placements to the editor screen and removes cells covered by higher
z-index floating rectangles. Its slot map contains source identities, so
ImageSystem alone resolves every referenced resource before invoking the
backend. The backend receives a candidate only after Pane has completed its
buffer transaction. Source preparation retains the current presentation until
the desired revision is ready, and cancellation suppresses stale source
completions.

Source reads and PNG validation are asynchronous and bounded. Desired and
current presentations retain prepared resources. Releasing the final desired
or presented reference cancels active source work, releases its backend
resource, and discards its failure record. The byte limit bounds the complete
set of referenced prepared resources.

Kitty uploads prepared PNG bytes in bounded direct chunks and reuses one upload
across independent Pane presentations. It creates every candidate placement
before deleting the prior owner's placements. Queued revisions for one Pane
coalesce to its newest complete presentation. Image data without a visible
placement is deleted from the terminal and uploaded again when it becomes
visible. Neovim redraw observation reapplies current persistent placements in
screen order. A terminal output failure makes the backend unavailable.

The backend orders protocol output after Neovim text through a serialized UI
API or the built-in TUI acknowledgement barrier. Active tmux receives its
pass-through envelope. Environments without an ordered output boundary keep
the selected backend unavailable.

An unavailable backend compiles the fallback at its natural bounded height
and reserves no image rectangle. Offscreen, folded, horizontally clipped,
popup-obscured, and overlapping rectangles remain hidden until the next
coalesced refresh. Disconnect clears its owned presentation. Destroy clears
runtime protocol state and the prepared source cache. Applet
performs no network fetch or image conversion. Use `images:destroy()` when its
owner is destroyed.

The interactive harness compares native floating windows with a Pane
container scene: >lua

  :luafile scripts/applet-image-harness.lua
  :lua applet_image_harness("kitty", "native")
  :lua applet_image_harness("kitty", "pane")
<

7. DIAGNOSTICS                                                 *applet-diagnostics*

`make benchmark-applet` enforces the representative container budgets used for
the Applet UI. At 80x22, Tree construction is bounded to 0.05 ms and
8 retained KiB per frame, content compilation to 0.75 ms and 64 KiB,
retained position updates to 0.05 ms and 8 KiB, and full updates to 0.75 ms and
32 KiB. A retained position update has a zero composed-cell budget. The target
runs 1,000 iterations and reports each measurement as JSON.

The pure Pane content compiler is available as: >lua

  local compiled = Applet.Pane.compile({
    tree = tree,
    width = 80,
    height = 24,
    extent = "document",
    theme = theme,
    images = image_snapshot,
  })
<
Content Trees contain plain finite data. Compilation rejects callbacks,
cycles, metatables, malformed UTF-8 text, duplicate semantic identities,
unknown built-in actions, ambiguous mappings, and impossible layouts before a
buffer is mutated.
